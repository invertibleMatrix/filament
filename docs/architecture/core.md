# Module map: core

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `core/`

| File | What it is |
| ---- | ---------- |
| `core/agent-limits.js` | Pure: an agent's account and its plan's windows in one shape, whoever reports them — `claudeIdentity`, `claudeWindow`, `claudeUsageWindows` (Claude's adapter and its `/usage` report), `codexIdentity`, `codexWindows`, `codexCredits` (Codex's app-server), `cursorIdentity` (the Cursor SDK), `agyQuotaWindows`, `agyIdentity` (Antigravity's quota from Google; `bounds`), `statusReading`; `accountRecord`, `sameIdentity` and `mergeWindows` fold readings into what services/agent-accounts.js keeps. |
| `core/answering-model.js` | Pure: whether the model that answered a turn is the one its chat names. `answeredAs(chosen, answered, { sure })` reads both names without their marks (an effort suffix, a `[1m]` window, a date, a route's prefix): "same", "different", or "unknown" — no name on a side (`default`, `auto`), or two names that may be one model, two where the agent itself said so (`sure`); a bare `opus`/`sonnet`/`haiku` is any model of its family. `mainCounted(modelUsage)`: the counted model that read the most. |
| `core/app-folder.js` | Pure: an app as a folder that travels (the Space Apps plan, Import app…) — `appJsonOf({ title, description, icon, content, folder })` writes the app.json its download carries (`APP_JSON_KEYS` of its content, its folder written as `FOLDER_MARK`), `textsWith` and `pathsWith` rewrite a JSON value's texts, and `unpinnedText` points a download's pinned library addresses back at the web. |
| `core/app-hooks.js` | Pure: an app's hooks (the Space Apps plan) — the filament.db collections a POST from this computer lands in, each at `/hook/<app>/<token>` (services/app-hooks.js keeps the tokens, http/hooks.js answers). `hooksOf(v)` checks an app's `hooks` (`HOOK_NAME`, `HOOKS_MAX`); `hookRow({ at, type, text, headers })` turns a POST into the record its collection keeps: JSON, a form or text, with its x- headers but those that may carry a secret (`hookHeaders`). |
| `core/app-secrets.js` | Pure: an app's secrets (the Space Apps plan) — `secretsOf(v)` reads the names its app.json declares, each an environment variable (`SECRET_NAME`, `SECRETS_MAX`) with a line on what it is for; `secretValue(v)` checks a typed value; `hider(values)` and `hiddenIn` hide the values in what the app's commands say (`hiddenWords`). The values are sealed by services/app-secrets.js and never reach a page or an agent. |
| `core/app-sql.js` | Pure: one SQLite database per app (the Space Apps plan) — its limits (`SQL_MAX_CHARS`, `SQL_ROWS_MAX`, `SQL_TIMEOUT_MS`, `SQL_DB_MAX_MB`, `SQL_DIR`), `sqlRefusal(sql, params)`, `sqlMay` (the authorizer's rule for what a statement may reach), `valueOut` and `sizeOut` for its rows, and `sqlFailure`. The query runs in services/app-sql-child.js, a process of its own, so a query without end is stopped by ending that process. |
| `core/app-tools.js` | Pure: the tools an app offers its Space's agents (the owner's of 11-05) — `appToolsOf` checks an app's `tools` (a no-shell argv with `{args.<name>}`, its arguments' bounds, reads/writes/sends), `appToolKept`, `grantToolOf` (what a Keep records), `appToolSchema` (its arguments as JSON Schema) and `fillAppTool` (argv filled, each value checked). Listed and run through the space tool's `app` action. |
| `core/artifact-content.js` | Pure: what a Dashboard and a Design are made of, kept as one JSON file and drawn by Filament's own pages — `dashboardOf(input)` (tiles of `TILE_KINDS`, the tables they read, `FORMATS`, `NUMBER_OF`), `appOf` (an app's content), `feedsOf` and `FEEDS` (Filament's own numbers a Dashboard may name, `isFeed`, `feedKey`), `designOf` (screens at `SCREEN_SIZES` and their shared style) and `screenWords`; each checked in words that name what is wrong. |
| `core/artifacts.js` | Pure: an artifact at `http://<name>.art.localhost:<port>/` — its name and address (`ART_DOMAIN`, `artifactNameOfHost`, `artifactAddress`, `nameFor`), a file's path (`artifactPath`), the page as served (`servedPage`, `typeShell`, `lookSheet`), policies (`pageFramePolicy`, `artifactPolicy`); where a page reads them (`artifactsAt`: here, under its pass; on the network, one https address, `/<name>/~<pass>/`: `artifactsOnNetwork`, `artifactOfPath`, `NETWORK_SANDBOX`, `rootedUnder`, `passHidden`). |
| `core/at-once.js` | Pure: `fewAtOnce(items, read, atOnce)` — each item read a few at a time (`AT_ONCE`), the answers in the items' order: enough side by side that a long list does not wait on each read in turn, few enough not to start a process per item at once. The git readers (adapters/git/), the run log and the Space and git routes read through it. |
| `core/autofit.js` | The context-fit vocabulary — `fitVerdict` (the one verdict word every surface uses), `AUTOFIT_RESERVE_CAP` (the reply reserve a request's fit is judged with) and `detectOverflow` (a provider's "did not fit" refusal and the limit it named). Nothing here reshapes a request: the pipeline stamps the fit, and the harness's agent loop is the one reader of `detectOverflow`. |
| `core/backups.js` | Pure: a model's backups (HarnessV4_Settings_Plan HS-5), the failover order of the route that catches its name — `backupsOf(cfg, name)` (the route, its first provider, its backups, how they are chosen, and whether Backups › on a provider's page may set them), `backupsProblem` (a new list checked: API providers only, no repeats), `withBackups` (the configuration with it), `routeWords`, `STRATEGY_WORDS`, `AGENT_WHY`. |
| `core/beside.js` | Pure: a team beside a chat — its lead in a chat of its own, kind `team`, tied by a `beside` link, never by `parent_id`. `BESIDE_LIMITS`, `BESIDE_STATES`, `besideAction` (fire as send), the lead's opening (`openingContent`, `recordBlock`), the message its result reaches the main agent in (`resultMessage`, `isTeamResult`), the ask BugHunters checks a result by (`verifyAsk`), hunt findings (`findingsOf`, `mergeFindings`, `sameBug`), and its card's state (`besideState`). app/teams-beside.js runs it. |
| `core/body-summary.js` | `summarizeBody(body, format, bytes)` — a compact, content-free description of a request body (roles, counts, sampling, cache markers, sizes) that the record's `translation.received` and `translation.sent` carry, so what came in and what went out can be seen without storing a byte of conversation. |
| `core/browser.js` | Pure: the agent's browser tool — `ACTIONS` and those that act on a page (`ACTING`, `acts`, `actingSteps`), `BATCHABLE`, its limits (`TABS_MAX`, `BATCH_MAX`, `SNAPSHOT_MAX`, `TEXT_MAX`), the protocol's commands and events a page takes (`CDP_METHODS`, `CDP_EVENTS`), page sizes (`SIZES`, `pageSize`), a page's site (`siteOf`), the addresses it may open (`wholeUrl`, `urlProblem`), `keyEvents`, and `snapshotOf`: the accessibility tree as lines with handles (`e12`) stable across snapshots. |
| `core/cache-facts.js` | Pure: a prompt's cache numbers, and whether it has any — the one rule every reader takes. `saysCache` (a usage's reader was given a cache field), `seenPrompt`/`cacheSaid` (a call marked `cacheSeen: true`, a sum's count of said prompt tokens, an older usage by its figures), `cacheTouched`, `hitOf` and `carriedOf` (a share of the said tokens, null where none: never 0%), `seenWith`, `promptOf`. The page keeps the same rule in ui/lib/cache-facts.js. |
| `core/call-place.js` | Pure: `callPlace(name, input, { root, locations, fresh })` — the file or folder a call works in, absolute, or null: a path kind's path in whatever vocabulary the call speaks (`canonicalOf`), else a coding agent's `locations`, else the folder a command's leading `cd`s reach from its base. Which git place that is, app/now-in.js asks git. `editsSaid(paths)`: what a file-writing call's start says it writes (`edits`). `driveSpelled(s)`: a drive as Git Bash or WSL spells it (`/h/x`). |
| `core/cards.js` | What a card may be: the kinds Filament attaches to its own answers (`CARD_KINDS`, `CARD_V`) and `cardProblem(card)`, the structural validator the server runs before attaching one — a card that fails is logged and the answer goes out as text alone. The page never validates: it draws the kinds it knows and falls back to the answer's text for any other. |
| `core/catalogues.js` | Pure data: what Filament knows about its destinations before asking them — `KNOWN_AGENTS` and `AGENT_CATALOGUE` (the coding agents it drives: start, modes, sign-in, install, `installCommand`, `viaRegistry`), `RETIRED_AGENTS` with what their install wrote (`RETIRED_SEEDS`), `CURSOR_SDK` behind its switch (`cursorSdkOn`, `cursorSdkHeld`, `agentCatalogue`, `CURSOR_SDK_OFF`), what a fresh install seeds (`agentUpstream`, `agentRoute`), `agentHomeVar`, `agentLaunchEnv`, `agentKey`. |
| `core/changes-view.js` | Pure: the Changes tab's read by place — `filesOf(status, counts)` (a place's uncommitted files from `git status --porcelain=v2` and `diff-index --numstat`, each its letter and the lines added and removed, at most `FILES_MAX`), and who wrote each (`attribute`, `writersOf`, `namedFiles`, `commitTimes`): the agents whose own edit calls named it since the file's last commit. An agent that only read is no writer. |
| `core/codex-items.js` | Pure: a Codex item (the app-server's shape) as the call Filament draws for it — `commandCall`, `fileCall` and `changeInput` (a file change: its card and its edit), `itemCall` (an MCP tool, a web search, an image), `itemResult`, `itemFailed`. Read by the bridge as Codex runs a turn (adapters/agents/codex/items.js) and by the import of Codex's chats on disk (services/memory/import/codex.js), so both draw the same cards. |
| `core/context-words.js` | Pure: one set of words for how earlier turns reach the model — compaction's `METHODS` (`methodOf`, `methodName`), an agent session's `WAYS` (`wayName`), what a sub-agent sees (`SUBAGENT_VIEW_WORDS`), what a fork carries (`FORK_TRANSCRIPT_WORDS`, `CARRY_WORDS`), `roomWords`, and a finished turn's `FORMS`. The stored values and setting keys stay as they are; the page keeps the same tables in ui/lib/context-words.js. |
| `core/conversation.js` | Which chat a request belongs to — `conversationKey` (the client's own id when it sends one, read by `clientConversationId` from `CONVERSATION_HEADERS`, else a fingerprint of the first message; the upstream and working folder are in the key), `CHAIN_HEADER` and `chainRefOf`, and `shellSessionOf` (the session a request's background shells belong to, one rule for the agent loop and its sub-agents). |
| `core/dashboard-sources.js` | Pure: what a Dashboard reads and watches by itself (HarnessV4_Space_Plan S2) — its sources (`sourcesOf`: a command's argv run in the project's folder with no shell, a connection's read-only tool, an address fetched, a folder, a Python script; rows by `rowsFrom`, `columnsOf`, `rowKey`), its watches (`watchKept`, `watchNews`), its buttons (`actionKept`, `fillAction`), and the grants a Keep records (`grantOf`, `sameGrant`). services/dashboard-runner.js runs them. |
| `core/drift.js` | Pure: the signs that an agent drifts from its work, said at a call (the owner's of 11-10, state signals alone) — one command failing a third time in a row in one folder, with nothing Filament saw changed between (`newDriftState`, `failedAgain`, `driftChanged`, `FAILS_AGAIN`, `failingLine`), and a file changed outside every open task's writes (`outsideLine`), each in the loop's brackets or a coding agent's; and a turn's second changed file, where the unplanned line is judged (`changedSecond`). |
| `core/failure.js` | One shape for every failure (HarnessV3-FailurePoints §5.2): the `Failure` typedef — what failed, where, what it said, its tries and timing, what had streamed, what is kept and what happens next. `saidOf(e)` (a network code in plain words, `NETWORK_WORDS`), `failureParts`, `failureLine` (the one line a person and a model read), `worded`, `keptRounds`. A run's end, the task graph's notices, the failure card and the Requests page read the same fields. |
| `core/feed-xml.js` | Pure: `feedRows(xml, from)` — an RSS or Atom feed's items as rows (id, feed, title, link, date, text), the newest first, or what is wrong in words, for an app's `fetch` source read as RSS; `plainText` turns CDATA, entities and the HTML inside into text. Both hide an app's secrets before a text is cut. No network and no XML library (`FEED_ITEMS_MAX`, `FEED_TEXT_MAX`). |
| `core/flow.js` | Pure: a flow (HarnessV4_Flow_Plan) — the person's agents and teams in steps, designed by the main agent after `/flow` or drawn by hand. A step's boxes run side by side once the step before is done; each box names the earlier boxes it needs and is handed their results. `FLOW_LIMITS`, `BOX_KINDS`, `flowOf` and `checkFlow`, `stepAt`, `boxAsk`, `handOff`, `verdictOf`, and the notices a chat carries (`startNotice`, `endMessage`, `driveNotice`). |
| `core/fold.js` | The fold, deterministic: a finished turn as its report — the user's text, one line per tool call (`stubLine`, `argSummary`, `resultSummary`), the model's text in order — sent by a fold compaction, a fresh agent session's start, a fork's folded inheritance and a sub-agent's folded view. `foldGroup`, `composition`, `pinHashOf`. A folded turn depends only on its bytes and `VIEW_VERSION`, so the provider's prefix cache holds; the archive keeps every byte. |
| `core/folded-teams.js` | Pure: the words for a team key or a Lead's tag Filament does not ship that a session, a flow, a team or a file may name — each says which team does its work, Builders or BugHunters. `foldedTeam`, `foldedTeamWords`, `foldedLeadWords`, and `resultChecked` (whether a team's result comes checked: BugHunters' and the Verifier's, which nothing checks again). |
| `core/footprint.js` | Pure: Filament's footprint in a repository — its copies (`copyKind`), its refs under `refs/filament/` by kind (`REF_PREFIX`, `refKind`, `SUBAGENT_REFS`, `SNAPSHOT_REFS`, `MOVE_REFS`), the branches its routines' runs made — and for each whether the person's Clean up takes it, why it stays, or whether it goes only where ticked (`planFootprint`, `footprintAnswer`, `pressedPlanOf`, `pressedTakes`). Nothing goes unless a record shows this data folder made it, or the folder that made it is gone. |
| `core/goal-drive.js` | Pure: a goal driven round by round (the owner's of 11-05, 11-10) — `driveFrom`, `driveOf`, `goalRoundLine` and `goalRoundOf` (Filament's round line and back), `goalMarkOf` (a reply's `[goal: done]`, `[goal: blocked: why]`, `[goal: waiting]`), `afterTurn` (the next round, a halt by mark, Stop, the `DRIVE_ROUNDS` cap or, at any end, `DRIVE_MS`, or neither while something wakes the agent), `haltLine` (why it halted, for the agent's next turn), `driveWords`, `driveShort`. It counts no money. |
| `core/hash.js` | `sha256` and `shortHash` — the content hashes everything Filament keys by content uses (slice summaries, folded turns, pins, memory blocks): SHA-256 over the string form, so the same bytes always meet the same key. `same`: a secret given compared with the one kept by their bytes, a character of two bytes a no (a terminal's ticket, an artifact's pass, a device's code). |
| `core/headers.js` | `lowerHeaders(req.headers)` — an inbound header map as Filament reads it: lower-cased names, multi-valued headers joined, one shape for every lookup. `FILAMENT_MARK` (`x-filament`) is the header on every answer of Filament's server but the model endpoints', by which an app's fetch knows another Filament. |
| `core/hunt-range.js` | Pure: a hunt's range — what BugHunters hunts in: a diff (what is uncommitted, or everything since a ref), a commit range `a..b`, or files; none named, what is uncommitted and what the chat's turns changed. `parseRange(v)` reads it from plain words, `huntsIn(team)` says whether a team's lead hunts (`HUNT_LEAD`), and `rangeBlock` writes the block a lead's opening carries: each file with the lines its diff changes (`linesOf`, `GIT_READ`), never the diff. |
| `core/kept-answers.js` | `keptAnswers({ most, perKey, budget?, weigh? })` → `{ get(key, basis, query, read, keep), size, weight }` — answers kept by what they rest on: a basis that did not move answers as it did, one read under way serves every ask, a failed read is not kept; `most` keys of `perKey` answers, the oldest asked going first, and past `budget` (each answer weighed) the oldest that weigh. A run's changes read through it (http/admin/runs.js), a turn's (http/admin/memory.js). |
| `core/kept-reads.js` | `keptReads({ freshMs, most, onMoved })` → `{ get(key, read, { asked, fresh }), forget, size }` — reads answered at once from the last one: a kept answer is given at once and, past `freshMs`, read again behind it, one read under way at a time; `fresh` reads anew and waits; an answer that differs from the kept one is told through `onMoved`. A git mark's read, seconds long in a large repository, goes through it (http/admin/git.js). |
| `core/lazy.js` | `lazy(obj, key, load)` — a property read on first use, then a plain one: enumerable from the start, so a spread or a serialization reads it, and an assignment takes its place without loading. The archive's turn bodies and the session service's compaction rows open their messages this way, so a composition costs what the copy holds, whatever the archive has grown to. |
| `core/lines.js` | Pure: `createLineReader(onLine, { max, onOver, eol })` → `{ push, rest, end }` — lines read off a stream as its chunks come (an agent's JSON-RPC messages, ripgrep's matches, the names git lists), each chunk searched for its newlines once and a line of many chunks joined once. A line past `LINE_MAX` (64 MiB, a WebSocket message's most) is dropped, never held whole: its two ends are kept so `overFields` reads its id and method, and `onOver` is told. |
| `core/list-since.js` | `listVersions({ keys, states })` → `{ take(key, rows, since) }` — a list read again and again sent as the rows that moved: each answer is a version kept as each row's hash, and a read naming a version it holds gets the order of the rows' ids and only the rows that moved, came or went. The Agents tab, Now and the Teams board read a large chat's agents this way (http/admin/sessions.js). |
| `core/mcp-door.js` | The door to the MCP tools that load on demand: a server's tools ride every request in full only where it says `load: "core"`; the rest are named in the system prompt and reached through one tool, `mcp` (`DOOR_TOOL`: find, load, call), so what it loads joins after the cached prefix. `doorIndex`, `resolveTool`, `unwrapDoor` (a call through the door as the tool's own call, its id kept), `doorCall`, `doorAnswer`, `doorLines`. |
| `core/media.js` | Images a tool shows the model, and the media a request carries — `imageTypeOf` (PNG, JPEG, GIF or WebP by their first bytes, never the name), `IMAGE_MAX_BYTES`, `imageBlock`, `MediaResult` (a result's words and image blocks), `picturesIn` (the pictures in a tool's result, which services/run-images.js keeps), and `mediaIn` and `mediaPast` (base64 media within one request's room: the newest whole, an older one past the room left out in words, `leftOutWords`). |
| `core/messages.js` | Pure message readers for every layer that looks inside a wire message, in all three shapes (Anthropic blocks, OpenAI content and tool_calls, Responses items) — `textOfMessage`, `blockText`, `messageKind`, `blockKind`, `messagePieces`; the calls an exchange made (`callsMade`, `callLog`, `callsRead`); the ask line (`askLine`, `isAskLine`, `withoutAskLine`); a visual's title and lines (`visualTitle`, `visualLines`, `desktopVisualOf`); `inBrief`, `resultsInBrief`. |
| `core/model-caps.js` | What a model can do at a provider, the one answer the picker, the wire and the dashboard share — `capsAt(cfg, upstream, sent, rules)` and `modelCapsFor(cfg, name)`: its reasoning levels and default, fast mode with its cost and request fields, extended thinking, the context windows a session may choose, its output ceiling, whether it takes tools; each answer names the tier that gave it, the operator's first. `CAP_FIELDS`, `placeOfName`, `withoutOperatorCaps`, `withFlex`. |
| `core/model-choice.js` | Pure: a sub-agent's model as a person names it (HarnessV4_Tasks E23) — `chooseModel(name, provider, book)` reads "Kimi K3", "GPT Sol" with "Codex", or a routed name against the picker's families (an exact name wins; two equal matches are refused), at the effort `effortOf` reads; where it cannot run, it says why. `chatEffortOf`: a chat made at an effort — beside its name, or as its member at that level (a Space's runs, 11-04). `modelList`, `providerWords`. |
| `core/model-families.js` | Pure: the catalogue as models, not ids — `buildFamilies(cfg, rows)` folds ids spelled one per variant (`grok-4.7-high-fast`, `kimi-k3-flex`, `opus[1m]`) into one family whose effort, speed, thinking and window are chosen by member id (`parseVariant`, `LEVEL_ORDER`); a plain API model's effort, fast mode and window are settings instead. `effortOffer`, `windowOptionsFor`, `sessionWindowFor(cfg, model, chosen)`, `isOtherRow`. |
| `core/model-traits.js` | Pure data and one lookup — `MODEL_TRAITS`, `traitsOf(model)`, `builtinEffortsOf(model)`, `traitName`: what Filament knows about a model family's reasoning and windows before asking it, versioned with the app beside the built-in price table — the effort levels it takes, the one it uses when none is sent, and the windows beyond its standard one. The operator's `effort.modelCaps` wins over it; nothing here widens them. |
| `core/move-note.js` | Pure: `moveNote(meta)` → `{ ids, text }` or null — what the agent hears of its chat's move to another place, on the newest message of the first turn after it: from where to where, that earlier paths name the old folder, the files that came with it, and that what git ignores stayed behind. `toldPatch` marks the moves told once that turn ran to its end; a failed or cut-off turn leaves them for the next. |
| `core/notes.js` | The note registry: a note is the fact behind a line in a record's `changes` — something Filament did differently from the request, or could not do. Each kind (`NOTE_KINDS`) has two renderers: the record sentence, pinned by the golden corpus (`renderRecord`), and the hint the chat shows (`renderHints`); `pushNote` and `appendNotes` keep a turn's sentences and objects aligned. test/core-notes.test.js fails a kind that lacks a renderer. |
| `core/notices.js` | Pure: Filament's own notices — `[Filament: …]` — in words another machine sent are never one of Filament's: `unnoticed` makes such a notice's bracket a parenthesis, so it opens none, read past the characters no reader sees (controls, zero-width, bidi marks); `unnoticedStream` does so piece by piece, a bracket split from its name held for the next. Used by remote-agents.js, remote-commands.js (a command's output there), subagents.js (cards, asks) and spaces.js. |
| `core/oauth.js` | Pure: signing in to a remote MCP server (HarnessV4_Settings_Plan HS-7) — `bearerChallenge` (a 401's `WWW-Authenticate` Bearer challenge), `resourceMetadataUrls` and `issuerMetadataUrls` (in the MCP authorization spec's order), `pkcePair` (S256), `addressOf` and `signInKey` (where a sign-in is kept), `endpointProblem` (https, or http on this computer), `authorizeUrl`, `tokensFrom` (a token answer read), and accounts (`MAIN_ACCOUNT`, `accountOf`, `accountsAt`). |
| `core/op-kinds.js` | Pure data: the kinds of operation the op log records and the System tab shows — `OP_KINDS`, `OP_KIND_KEYS`, `NOISY_OP_KINDS`, `DEFAULT_OP_KINDS`, `WIRED_OP_KINDS` — so the config schema, which offers them as chips, does not import the log itself. services/oplog.js re-exports them. |
| `core/package-managers.js` | `LOCKFILES` (the lockfile that names each package manager, in the order the Environment prefers them) and `ECOSYSTEM` (the ecosystem each serves), in one place: the harness's frozen Environment says which manager a project's scripts run with (app/agent/environment.js), and memory's environment check which one a claim about the project contradicts (services/memory/request-env.js). |
| `core/path-glob.js` | `globToRegExp(pattern)` — a file-path glob as a regular expression: `*` within a segment, `**` across segments, `?` one character, `{a,b}` alternatives (each a glob too), case-insensitive, backslashes read as slashes. Shared by the MCP server's Glob (http/mcp.js), the `glob` hand (adapters/tools/hands.js) and the task graph's writes. |
| `core/plugin-hooks.js` | Pure: a plugin's hooks as Claude Code runs them (HarnessV4_SpacesPlugins_Plan B3) — a hook written for Claude's events runs at Filament's moment for it, translated both ways: `CLAUDE_EVENTS`, `claudeNames` and `claudeMatches` (the names a matcher matches a call by, a plugin's own server's tool as `mcp__plugin_<plugin>_<server>__<tool>`), `claudeStdin` (Claude's JSON on stdin), `claudeCall`, `filamentArgs`, and `claudeVerdict` (the hook's answer read back). |
| `core/plugin-parts.js` | Pure: a plugin's parts (HarnessV4_SpacesPlugins_Plan B2) — `partPaths(manifest, kind)` (where each part stands: Claude's default folders or the paths its manifest names, Codex's fields), `mcpServersOf` (its MCP servers as Filament keeps one), `hooksOf` and `HOOK_MOMENTS` (its hooks at Filament's four moments), `userConfigOf` and `checkValues` (the values it asks for), `fillSpec`, `pluginEnv`, `notHereWords` (the parts Filament does not run), `PART_LIMITS`. |
| `core/plugins.js` | Pure: plugins from Claude Code, Codex and marketplaces in one shape (HarnessV4_SpacesPlugins_Plan B1) — `marketplaceOf` (Claude's `.claude-plugin/marketplace.json`, Codex's `.agents/plugins/marketplace.json`), `manifestOf` (a plugin's manifest), `directoryOf` (Anthropic's directory as Claude Code caches it), `sourceOf` and `sourceWords` (where a plugin comes from: a folder, git, GitHub, npm, or unknown in words), `searchPlugins`, `pluginName`, `PLUGIN_LIMITS`. |
| `core/pool.js` | Pure: a chat's own list for its agents (E15 step 8), `subagents.pool` — rows in order, each at its effort, a nameless one the main agent's model (`DEFAULT_POOL`) — and its rows per card and team (`byCardProblem`, `byTeamProblem`, `CHAT_ROWS_MOST`). A launch naming no model takes the first row with room under its model's limit (`seatsOf`, `seatFree`, `takeSeat`, `waitSeat`); `poolOf`, `poolKept`, `poolProblem`, `poolTotal`, `poolRoom`, `lendsWords`, `poolNote`, `poolLine`. |
| `core/ports.js` | The port contracts as JSDoc typedefs, no runtime code: what the application and the pure algorithms ask of the outside world, so a fake can stand in for it in a test — `Clock`, `Summarizer`, `SliceCache`, `ProgressSink`, `ConfigStore`, `EventBus`, `BusEntry`, and `Destination` (where a request goes, one per upstream from `deps.destination(upstream)`) with `AgentBridge` and `RequestAnswerer`.
