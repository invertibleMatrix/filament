# Module map: app/sessions

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `app/sessions/`

| File | What it is |
| ---- | ---------- |
| `app/sessions/agent-copy.js` | Filament's copy of a coding agent's session follows the agent's own compactions (HarnessV4_Tasks C28): where the agent hands its summary over as it compacts, `followOwnCompaction(…)` writes a compaction row with no model call — the summary as the copy's head, the turn it fell in counted from the compaction on — so the copy a fresh session starts from stays the size of what the agent holds. Where no summary comes (Codex, Cursor), `copyBehind` says when Filament writes one (compactor.js). |
| `app/sessions/agent-line.js` | When and how a coding agent's session makes room (HarnessV3-ACP AC5-3): the agent compacts its own context, so the line is the session's `thresholdPercent` of the agent's window, read against what it last said it holds. `agentHeld`, `agentLine`, `namedWindow`, `heldWords`, and `agentWay` — the session's `context.compaction.agent`, else a suggestion: the agent's own compaction, Self (the agent writes Filament's summary) while the cache is warm, else Ours. Also `ownShare`, `seedRoom`. |
| `app/sessions/cache-clock.js` | A session's prompt cache as a message is about to be sent (HarnessV4_Tasks C26): `cacheClock(…)` → warm, cold, or none where no reply touched a cache. A model Filament calls keeps it as its last turn's markers asked (`writtenTtlMs`, `ttlMsOf`, `routeCacheTtl`: five minutes or one hour); a coding agent's is `AGENT_CACHE_MS`, one hour, since Filament sees nothing of its cache. A message into a cold cache asks first (`context.compaction.resumeQuestion`), in `idleWords` and `resumeWords`. |
| `app/sessions/changes-view.js` | A change as a patch for a reader beside the session (HarnessV4_Tasks E13-1, E15 step 4), such as a side agent asked to review the main agent's work: `changesView(…)` over `CHANGE_SOURCES` — `running` (the running turn's, so far), `turn` (the last finished turn's own files, from its rounds), `uncommitted` (the folder as git sees it) — or a range `since:<ref>`. `changeSource` reads the name. Read only: nothing is staged, written or fetched. |
| `app/sessions/compaction.js` | Compaction's one home (HarnessV3 Step 4 D1): the summarizer's words (`COMPACTION_SYSTEM`, `SUMMARY_SHAPE`, `compactionPrompt`, `summaryOfReply`), which model writes a summary (`compactionModelOf`), where the usable window ends (`usableWindow`, `linePercentOf`), what a turn looks like to a summarizer (`turnTranscript`, `transcriptOf`), `summarize`, and the summary as a history's head (`compactionHead`, `summaryHead`, `copyTurns`, `copyWindow`). Every compaction path comes here. |
| `app/sessions/compactor.js` | The compactor (HarnessV3-Compaction §5): `createCompactor(…)` → `{ plan, run, own, copy, copyRead, writerFor, writeSummary }`, one door for how a session's window makes room: the turn start at the compaction line, Compact now, the preview. Three kinds: the session's own model writes one summary, forking its warm cache when it can; a side model writes it; or every finished turn but the newest folds to its report, with no model call. Nothing is deleted. Also `chooseWriter`, `compactionSettingsOf`. |
| `app/sessions/compose.js` | The composer (HarnessV2 §9): `compose({ turns, compactions, settings, form, newUser, … })` → `{ body, report, places }` — archived turns, the session's settings and the new message as the pipeline's request body, with what each turn became. Pure; never calls a model: past the compaction line it says so and the compactor makes room. The newest compaction heads the history; each finished turn goes whole unless a compaction folded it. Same inputs, same bytes, so the cached prefix holds. |
| `app/sessions/composition.js` | "Explain this request" (HarnessV2 §10.5): `compositionReport(rec, { turn, chainKind })` — how one request's outbound body was put together, read off its record in one shape whichever door it came through: the request, where it sits in its chain, the settings hash, the turns by shape and history → sent, memory's blocks by kind and weight, the compaction in force, the notes in order, and its gaps. Numbers, ids and Filament's own sentences only. Served by `GET /api/requests/:id/composition`. |
| `app/sessions/copies.js` | The copy of a project's worktree template into a worktree a chat was just made in or moved to (HarnessV4_Four_Plan E19): `createWorktreeCopies({ memory, log, publish, now, copy })` → `{ start, running, stop, stopAll }` — run beside everything else, its progress read by the chat's turn that waits on it, its start and end kept on the chat's meta (`copies`) and told on the feed. Filament stopping cuts it (`COPY_CUT`) and what was copied stays; `copiedBoundary` is the transcript's row. |
| `app/sessions/cut-turns.js` | The turns a restart cut off, kept (HarnessV4_Tasks A2): `keepCutTurns({ runs, archive, log, onKept, stop })`, run once at start as memory opens. Each turn whose run (`TURN_RUNS`: `agent-turn`, `coding-agent`) the last process left open gets the work its run log holds (`eventsOf`, core/run-work.js) and a `meta.cut` mark, and its run is closed, so the model's history, a summary, memory and a fresh agent session's seed see what it did. `onKept` hears each one for resume-cut.js. `LEFT_OPEN`. |
| `app/sessions/draft-start.js` | The first request of a session not born yet, weighed by part (HarnessV3-NewTask NT-D5/D6/D8): the New Task board's figures. `draftEngine(…)` says what would answer the first message (the loop, a team, a model, an agent, or none); `startAnatomy(…)` builds the request with the functions the turn uses (`loopSystem`, `loopToolArgs`, `usableWindow`) and weighs each part, saying what only the first turn can know (memory's briefing, recall, MCP tools) as a ceiling. Calls no model, writes nothing. |
| `app/sessions/idle-wake.js` | The idle wake (the owner's of 11-08): a chat's agent that ended its turn while its background command runs is told after `sessions.idleWakeMinutes` (5; 0 off) that it runs on (kind `idle`). `createIdleWaker(…)` → `{ ended, began, stopped, next, list, kept, restore }`: any turn's start drops it; one blocked is set again (twice for an unsent wake, then told); in a row they back off to an hour; `kept`/`restore` carry it across a restart, which ended its commands (`idleGoneText`, kind `exit`). |
| `app/sessions/mcp-found.js` | Settings › MCP servers › Import from other apps (HarnessV4_Settings_Plan HS-6): where Claude Desktop, Cursor and Codex keep their MCP servers (`foundSources`), each file's servers read as Filament's (`foundIn`: JSON `mcpServers`, Codex's TOML `[mcp_servers.*]`) with notes for what cannot carry over, `nameFrom` (the name Filament offers) and `sameKey` (the same server under another name). Read only when the person asks; Claude Code's own file is not read. |
| `app/sessions/mcp-servers.js` | Settings › MCP servers, the server half (HarnessV4_Settings_Plan HS-1): `createMcpServers(…)` lists a place's servers (all chats, a project or one chat) as it resolves them, each with its layer, whether it is on and its last test, credentials masked; writes one entry of one layer through that layer's one writer, so two windows never lose each other's servers; tests a server (connect, list its tools, close; `testWords` says a failure); and imports other apps' servers (mcp-found.js). |
| `app/sessions/mcp-sign-in.js` | Signing in to a remote MCP server (HarnessV4_Settings_Plan HS-7): `createMcpSignIns(…)` — started from a server's row, the browser sent to the server's page and back to Filament's `BACK_PATH`, the code exchanged and the tokens kept sealed by address and account. `start`, `back`, `cancel`, `stateOf`, `signOut`, `auth` (Filament's agent: a header per request, renewed on a 401) and `withTokens` (a coding agent's servers, renewed under `AGENT_TOKEN_ROOM_MS`). A sign-in in progress has no clock. |
| `app/sessions/move.js` | A chat moved to another place of its repository with its own uncommitted files (HarnessV4_Git_Plan §12): into a new worktree made for it, or a place the repository has. `createChatMove(…)` → `read` (the sheet's plan: what goes, what stays and why, `STAYS`), `move` (each file its agents changed, carried by git's restore from snapshots, all or nothing, under the chat's turn lock, `MOVE_WINDOW`) and `back` (while no turn ran since). Kept in the chat's meta; `movedBoundary`, `movedSince`. |
| `app/sessions/outputs.js` | Outputs (HarnessV4_Four_Plan E20): `outputsOf(rounds)` → `{ files, gone, errors }` — the files a chat's agents wrote that git does not show (outside any repository, or ignored by its git), read from the rounds its turns recorded, each looked at as it stands now: a file now inside a repository git sees leaves the list, one not where it was written is in `gone`. Read only. `GET /api/memory/sessions/:id/outputs` answers it. |
| `app/sessions/owed-wakes.js` | What a chat is owed survives a restart (the nudge map of 11-10): `createOwedKeeper` keeps its untold items, come-back and idle check-in in its meta (`owedWakes`; commands redacted). `restoreOwed` gives them back at start by id, each part by itself: one that fails stays kept. `wakeOwedAtStart` wakes the owed chats `OWED_STAGGER_MS` apart, skipping those its caller names; `staleWords` is the day's cutoff. server.js holds what the start gave back to a chat it does not go on with (`heldAtStart`). |
| `app/sessions/reattach.js` | What comes back after a summary (HarnessV3-AtHome AH-D9 b): the newest files the summarized work read, wrote or edited, as on disk when the summary is written, the live plan and the open task graph, in one block written once with the compaction so the cache holds. A file too big, outside the folder, behind a rule or past the room is only named. `reattachBlock`, `backAfterSummary`, `touchedFiles`, `planIn`, `livePlan`, `afterSummaryCandidates`, `blockFiles`, `blockPlan`, `REATTACH_FILES`. |
| `app/sessions/recall.js` | The recall tool's answers (HarnessV2 §6.4), pure over the archive: `filament_recall({ turn: n })` brings an archived turn back as text (`recallTurn`, `RECALL_TURN_CHARS`) and `{ result: "r:<hash8>" }` one archived tool result (`recallResult`), so every fold, stub line and pointer the shapes leave in the window resolves and nothing removed from it is lost to the model. `recall(archive, chainId, input)`, `parsePointer`, `RECALL_TOOL`, `RECALL_RESULT_CHARS`. |
| `app/sessions/replay-compare.js` | Replay-compare (HarnessV2 §10.6): `createReplayCompare(…)` → `start(id, { settings, defaults, turns, strategy })` forks the session before its last N turns (`REPLAY_MAX_TURNS` 10; a fresh one if all), under the feature's settings or your defaults, and replays the original messages on it through the front door one by one, in a run of kind `replay-compare`: a `replay-turn` event per turn with both sides (`sideOf`), the whole table on `run-end` (`totalsOf`). The original is left as it was. |
| `app/sessions/resume-cut.js` | A turn a restart cut off goes on by itself (HarnessV3-TaskGraph-v2 TG2-D83): `resumePlan(…)` picks each chat's newest cut turn with `sessions.resumeAfterRestart` on (never a team's own chat, `TEAM_WAITS`, or an archived one; not one cut again, `CUT_AGAIN`), and `resumeCutTurns(…)` sends it a turn by the route a message takes once the server listens (`RESUME_LINE`, `isResumeMessage`). A clean stop notes the chats whose turn runs (`noteRunningAtStop`, `takeRunningAtStop`, `stoppedTurns`). |
| `app/sessions/rewind.js` | Rewind in place, as Claude Code's /rewind: a chat goes back to before one of the person's messages — its files, its conversation or both (`REWIND_WAYS`) — and nothing is lost: the turns stay in the archive folded into one line, and Undo puts both back until the next message. `roundsFrom`, `planFiles` (each file its agents changed back to before their first change; what others changed is left), `putBack` (each place snapshotted first; a failed write puts back what moved), `rewindNote`. |
| `app/sessions/service.js` | Native sessions (HarnessV2 §3): the archive chain is the session, the server composes every request from it, and the harness is a view. `createSessions(…)` is what the admin rows call: `create`, `draftStart`, `turn` (compose, hand the body to the pipeline, stamp the turn; one live turn per session, a second sender gets 409), `transcript`, settings, `compact`, `rewindTo`, `fork`, `move`, `autofit`. Also `turnClock` (a turn's pre-send clock), `refusal`, `settingsChangeOfLine`. |
| `app/sessions/shapes.js` | Context shapes (HarnessV2 §6): how one completed turn reaches the model — `raw` (the trajectory byte for byte) or `fold` (core/fold.js) (`renderTurn`) — and the result policies on raw turns (`statusResults`, `pointerResults`, `dedupeResults`, and `clearResults` for the loop's overflow retry over `COMPACTABLE_TOOLS`). A pointer is `r:<hash8>` (`resultRef`), which `filament_recall` resolves. `shapeAt`, `shapePlan`, `compactedShapeOf`: shapes go one way, so a folded turn is never sent raw again. |
| `app/sessions/stretch.js` | A chat's work stretch: `createStretches({ archive, waits, moved, now })` → `{ began, ended, settle, going }`. Begun by a turn begun while nothing of the chat's was open, it goes on through every turn that ended while something whose end wakes its agent ran (a background command, a sub-agent, its agent's own task, a team beside it) or a wake was on its way. Now (ui/harness/lib/now.js) counts the chat's time from its start, under Working between turns; the start is kept as `workSince` in the meta. |
| `app/sessions/switch-question.js` | The question a switch asks before its first message (HarnessV4_Tasks A7): the chat's last turn ran on another upstream — another account of the same coding agent, or another model — so this message starts the agent's fresh session from Filament's copy (the newest summary and the turns since, in the form the person picks, `context.carry`), or goes on in the agent's session where it is still up, handed the turns it missed. `switchWords(q)` says it in words; it is asked every time. |
| `app/sessions/wake.js` | A chat goes on by itself (HarnessV4_Four_Plan E21): when a background command ends with no turn of its agent to hear it, or another agent's report, a check's or an apply's verdict, a command task's end or the side card's answer comes while no turn runs. `createWaker(…)` sends the chat a turn of its own, waiting briefly for one that is ending; `ended` tries one that failed before any work again after `WAKE_AGAIN_MS` (1, 5, 15 min). `wakeLineFor` says what came; `isWakeMessage` knows it again. |
