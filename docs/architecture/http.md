# Module map: http

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `http/`

| File | What it is |
| ---- | ---------- |
| `http/artifacts.js` | An artifact's address: the front door hands each request for a name under `art.localhost` here first, so an agent's page finds nothing of Filament's. `createArtifactsHandler(...)` serves its files alone: its page with Filament's script, old versions, the look, its data (`/_filament/db/`), typed ones, feeds; this machine alone. On the network (`artifactsListener`, `artifactsDoor`): https at port + 1, paired devices but other machines' agents, each page sandboxed under a pass (`createPasses`). |
| `http/events.js` | The dashboard's live stream, `/api/events`: `attachEventsStream` holds an SSE connection per tab carrying records, ops and the bus's topics (never a run's events), or those `?only=` names (another machine's desk), a 25 s ping and shutdown through the client set. A slow tab neither stalls the request path nor misses writes: `writeHeld` queues them in order until the socket drains (`drainedOrGone`); only a tab past `BACKLOG_BYTES` is cut off. `writeSse`. Also used by `admin/run-socket.js`. |
| `http/front-door.js` | The one request listener, `createFrontDoor(...)`: an artifact's address first, then the drain guard, the memory-engine rewrite and the routes: the model endpoints, MCP, an app's hooks, the pages behind the Host guard (a stranger is static.js's; a cookie again), the 404. `lanDoor`: the network's listener, where none of those answer but `/v1` to an agents' device with its `models` grant (`LENT_PATH`); `mainDoor` hands it the main one's. While memory opens, `OPENING_WAIT_MS`, then 503. |
| `http/guards.js` | Every request's doors: `readBody`, `checkInboundAuth`, `hostAllowed`; who calls — `isLocalCaller`, `whoIs` (this computer, `ownerOf`, the admin token, a device over a `sealedWay`, on loopback too but a browser here, `hereDevice`; `lapsedDevice`), `drives`, `agentsDevice`, `modelsDevice`, `sendsDeviceKey`, `pressRefusal`, `doorRefused`, the app's main process (`ownerKeySent`, `pressedWithKey`); `endsWithDevice`, `deviceCookie`, `cookieDevice`, `cookieAgain`, `ownOrigin`, `callerAddress`. |
| `http/mcp-connector.js` | A chat's signed-in connector at Filament's door (the owner's of 11-07): `createConnectorDoor({ key, auth })` → `give` (a server at `/mcp/c/<chat>/<name>/<sig>`, signed by an HMAC of this run's key, no header handed out), `forget` (what a chat's last turn gave), `handle` (forwards MCP's headers, the server's own and the sign-in's token; renews once on a 401; a 307/308 to its own origin followed, `SAME_SERVER_REDIRECTS` at most, no other; 404/403/405/401/503/502 in words). `CONNECTOR_PATH`. |
| `http/hooks.js` | An app's hooks' door: `createHookDoor({ dashboards, server, log })` takes `POST /hook/<app>/<token>` and keeps its body as a record of the hook's collection (`services/dashboard-runner.js` `hookAt`, `hookPost`). It answers this computer alone (loopback, a Host that names this machine) and never a web page: a request with an Origin is refused, so a site cannot write into an app. Nothing else is answered here; `front-door.js` hands it every `/hook/` path. |
| `http/mcp.js` | Filament's MCP toolset over Streamable HTTP, `McpToolServer`: Claude Code's own tool names (Read, Write, Edit, Bash, Glob, Grep), so an agent with its built-in tools off uses the chat client's tools, cards and permission mode, over the turn's client bridge where the client has the tool, else here; Glob and Grep fenced for another machine's agents (`theirFence`). Also the session's own Filament tools (`app/agent-tools.js`). `MCP_TOOLS`, `serverInstructions`, `pageResult`. Serves `/mcp/<token>`. |
| `http/memory-mcp.js` | Memory as a service: `/mcp/memory`, the MCP server an agent Filament does not run (Claude Code, Cursor, VS Code, any MCP client) adds once for every project. Streamable HTTP: JSON-RPC over POST, single or batch, answered as JSON or as SSE when the client must be asked its folder first. `memoryMcpRefusal` says who may call (`originAllowed`, `memoryKeys`); `MemoryMcp` keeps sessions by `Mcp-Session-Id` (`mcpSessionKey`) and the folder each stands in. The tools are `app/memory-mcp.js`'s. |
| `http/responses.js` | The OpenAI Responses front door, `createResponsesFrontDoor({ config, pipeline })`: a Responses request becomes a Chat Completions request for the normal pipeline (routing, rules, translation, agents), and the reply is turned back into a Responses object or event stream on the way out. The `previous_response_id` store lives here: the conversations a Responses client may continue, kept in memory for an hour. Built in `server.js`. |
| `http/router.js` | One route table for the whole HTTP surface: `createRouter(rows)` matches `[method, pattern, handler]` rows in order, first match wins. A pattern is literal segments; `:name` takes one segment, `:name*` one or more (a greedy tail). Params arrive undecoded; a handler decodes the ones it reads. A match says its row's pattern. Used by the front door and every admin area. |
| `http/static.js` | The dashboard and its docs served from disk through an mtime-keyed cache, a file read again only when it changed: `serveStatic` and `serveDoc` (docs by bare Markdown name only, no `..`). A page names its own files under a stamp of the UI's files (`/ui/b/<stamp>/…`, `uiStamp`), kept `immutable`; the page itself is checked each time and carries the frame policy of `core/artifacts.js`. A `stranger` gets the pairing page and files of `ANYONES`' types alone, judged by the file the disk opened. |
| `http/watch-hooks.js` | A watcher's address, its door: `createWatchHookDoor({ watch, server, log })` takes `POST /watch/<token>` for the webhook watcher the token opens (app/watchers/webhook.js `at`, `wait`, `post`). No key: it answers this computer and the tailnet's door, never the network's listener, Tailscale Funnel (404) or a web page. The token is looked for before the body is read; 60 posts a minute (429), 256 KB (413), a signature where the watcher asks one (401); a post taken is a 202 and `{ ok: true }`. |
| `http/ws.js` | A minimal server-side WebSocket (RFC 6455) for the harness's sockets, hand-rolled: they talk only to Filament's own clients, with no extensions or compression: `wsAcceptKey`, `wsHandshake`, `wsTextFrame`, `wsBinaryFrame`, `wsCloseFrame`, `wsPingFrame`, `wsPongFrame`, and `WsDecoder` (client frames unmasked, binary as bytes, joined once a frame, continuations reassembled, one past its cap refused unheld). Pure; used by `admin/terminal.js`, `admin/browser.js` and `admin/run-socket.js`. |

## `http/admin/`

| File | What it is |
| ---- | ---------- |
| `http/admin/agents.js` | The admin API's saved agents, `agentCardRoutes`: the cards a tag, an agent's tool or `/subagent as=` can name (the shipped ones, read-only, and yours, `services/agent-cards.js`), saved, copied, edited and deleted as `config` operations. Also whom a session's main agent may ask by itself (`PUT /subagents/ask`, `agentLoop.subagents.ask`), and per card who uses it (`usedBy`), why its models cannot run an agent (`problems`), and its `fallbacks`. |
| `http/admin/artifacts.js` | The admin API's artifacts area, `artifactRoutes`: what the harness reads of the pages agents made (title, description, icon, type, address, pin, last opened, versions with who made each: `artifactView`, `madeIn`, `helpersMade`, `readsOf`) and what the Artifacts page does to one: rename, pin, delete, make an old version the newest, download (`downloadOf`), keep a chat's visual as one, edit a Doc's or deck's Markdown. A page's files open on the artifact's own address, never here. |
| `http/admin/beside.js` | The admin API's teams beside a chat, `besideRoutes` (`/sessions/:id/beside`): the teams a chat's Team tab lists, sent from its fire card, their switches flipped while they work, a result sent to the main agent, BugHunters' ask for Verify…, what a send would run on and read, its lead's board, and Stop. `app/teams-beside.js` does each; a refusal is answered in its words. |
| `http/admin/browser.js` | The admin API's browser area: `browserRoutes`, the Browser pane's reads and acts on a chat's browser (`/sessions/:id/browser`: what it shows, take-over, navigation, tabs, size, a site's yes taken back, data cleared, a picture), and `browserUpgrade`, the apps' socket (`HOST_PATH`): no front door, so its own guards — the Host check, the artifacts' fence, no Origin, Filament's inbound key or a full device's sign-in; its binary messages a viewer's streams (`admin/tunnel.js`). |
| `http/admin/coding-agents.js` | The admin API's Coding agents area, `codingAgentRoutes`: Settings → Coding agents' entries with the registry's age (read again when older than a day), the registry read again, its agents' icons served under a policy that runs nothing, and an agent installed (or its install stopped), connected, turned off, its models asked for, and removed from this computer, over `app/coding-agents.js`. A change answers with the entries as they then stand; a refusal with its status and words. |
| `http/admin/config.js` | The admin API's config area, `configRoutes`: the schema and templates; reading and saving the configuration (`PUT /config?base=` refused where a save came since the draft's read; a key changed drops `keyFrom`); `GET /config/changes`; the harness pages' fields (`PATCH /config/fields`, `app/config-fields.js`); the inbound keys, a press, for this computer alone; the route tester; failover; the 9router import; the assistant's apply. A save that asks less or sets a key is a press (`pressNeeded`). |
| `http/admin/exec.js` | The exec area, `execRoutes`: `POST /exec {cwd, command, timeoutMs?, mode?}` runs a command in the shell here, its folder fenced as a chat's, judged by the mode sent (their grants cap it), else this machine's, and its rules — refused, run, or asked (`POST /exec/:id/answer`) —, as SSE (or JSON, `?stream=0`); `GET /exec/:id`, `POST /exec/:id/stop`. Output kept head and tail, a redacted line held past 32 KB; a hang-up (running: unread `EXEC_GRACE_MS`), revoke, grant off or copy let go stops it. |
| `http/admin/transfers.js` | The admin API's transfers area, `transferRoutes` (cp-send): `GET /transfers/haves`, `POST /transfers` (opened, or again: `have`), `/transfers/:id/part` (base64, from `have`; 409 elsewhere), `/transfers/:id/commit` (checked, into the mirror), `/transfers/place` (a copy checked out for a launch, or `for` your chat), `/transfers/back` and `GET /transfers/back/:id` (its change captured, in parts; 409 `runs` mid-turn). Another machine's agents' alone (remote.js AGENT_ROUTES, COPY_ROUTES). |
| `http/admin/files.js` | The admin API's files area, `fileRoutes`: read-only views of a project folder for the harness (the tree, a file for the code viewer, a name search, the folder browser, whether paths exist) and two rows that open a window here: the OS folder dialog and Show in folder, refused (403, `remote`) to another machine's caller. `cwd` must be a folder the agent loop may work in (`folder.js`), and every path stays inside it through the hands' fence (`adapters/tools/workspace.js`). Nothing here writes. |
| `http/admin/flows.js` | The admin API's flows, `flowRoutes`: a chat's flows (`/sessions/:id/flows`), drawn by hand or from a saved flow, edited, started beside the chat or in place, decided at a gate or the person's review, a box stopped, skipped, retried or handed on, stopped, gone on with after a restart, and the saved flows (`/flows/saved`). A draft by the main agent is its flow tool's, never a route. `app/flow-runner.js` does each; a refusal is answered in its words. |
| `http/admin/folder.js` | The folder fence the project-reading admin rows share: `allowedFolder(cfg, cwd)` allows a `cwd` by the agent loop's own judgement (`app/agent/turn.js` `folderVerdict`): it exists, it lies under a listed `agentLoop.roots` entry, and with no roots listed the listener is private to this machine. A refusal comes in words with the status the surface shows (400, 404, 403; 503 for a folder whose share does not answer, `folderHung`); `allowedFolderSoon` looks at it and the roots first, off the thread. |
| `http/admin/git.js` | The admin API's git area, `gitRoutes`: git for a project folder (status, the recent log, branches, where a chat works, what merging each of its places would bring, the repository's places, the worktree template, Filament's own footprint via `app/git-footprint.js`) for the harness header, sidebar, New chat, Files and Changes panes. Four rows write, each on the developer's click: removing a worktree that loses nothing, putting it back, saving the template, and Clean up. |
| `http/admin/guard.js` | The one wrapper every admin area's rows sit in, `guard(fn, mapError?)`: a local failure (archive, engine, config, a bad id) answers as JSON with its message instead of the front door's generic 500, with 502 kept for an upstream that failed. Areas that know their errors pass a mapping (memory off → 503, no such session → 404); bad percent-encoding in the path is a 400, and the body reader's refusal is rethrown because it has already answered. |
| `http/admin/index.js` | The dashboard's API (`/api/*`), `createAdminHandler(a)`: one route table from its areas behind the guards all routes share — loopback-or-token, the CSRF pair, the app's key where the row's class is a press (press.js `pressClass`: always, by its body, or a row nobody classed), a pairing or a grant (`doorRefused`), then a view device's rows and another machine's agents' (remote.js): their headers, fields, folders and own chats, any other 404 (`notTheirs`) —, the body read once for gate and row. |
| `http/admin/coach.js` | The admin API's first-run tips, `coachRoutes`: `GET /coach` reads ui/harness/coach/coach.json at each ask (`readCoach`: its steps, how dark the page goes behind a tip — `dim`, a step's own over it —, a broken one said in words) with the steps seen (`ui.coach.seen`); with the file's `replayOnRestart`, its first ask after a start forgets them and the tour seen. `POST /coach/seen {ids}` keeps steps seen; `POST /coach/reset` (Show tips again) forgets them. `FILAMENT_COACH_FILE` names another file. |
| `http/admin/telemetry.js` | The admin API's door to anonymous telemetry, `telemetryRoutes`: `GET /telemetry` (whether it sends, why not — not armed, off by the environment or the setting, an unofficial build with nothing chosen, the notice not shown — and the body last sent, for Show what's sent), `POST /telemetry/notice-seen` (the notice was shown; `off: true` turns it off too). |
| `http/admin/star.js` | The ask for a star on GitHub (the owner's of 11-22), `starRoutes`: `GET /star` (whether it asks now — Filament used in `STAR_AFTER_HOURS` different hours with a model call, from Usage's days (`hoursUsed`), not asked yet, no usage-stats notice waiting (`starAsks`) — the hours and `STAR_URL`), `POST /star/seen` (`ui.star.asked`: it never asks again). |
| `http/admin/owner.js` | This computer's owner key's one row, `ownerRoutes`: `POST /owner/session` mints a browser session (services/owner.js `session`) for a call with the key alone — the desktop app's main process, which keeps it as an HttpOnly cookie of its windows' session; any other is told `SESSION_REFUSED`. |
| `http/admin/keys-copy.js` | Providers' keys copied to another machine, `keysCopyRoutes`: `POST /key-copies` answers the keys named (`copyOf`: as set here, open, never cached) to the desktop app's main process alone: a local call with the press key and owner key (guards.js `pressedWithKey`, `ownerKeySent`); any other is told `COPY_REFUSED`. A coding agent, another machine's models, no API's kind (`KEY_TYPES`), a key or header no secret.key here opens: refused. `desktop/lib/machine-agents.js` `copyKeys` hands them on. |
| `http/admin/remote-work.js` | The admin API's Run on rows, `remoteWorkRoutes` (app/remote-work.js): `GET /remote-work`; `GET /remote-work/places?folder=`; `POST /remote-work` (`{ machine, folder, allow? }`, judged as a chat's start; 409 `ask`); `…/:id/chat`; `…/:id/check` (`{ seen? }`, nothing written); `…/:id/back` (`{ choices?, overlap?, at? }`; 409 `conflicts`, `moved` or `runs`, 410 its copy gone); `DELETE /remote-work/:id`. The person's alone: sends and bring backs are presses. |
| `http/admin/update.js` | The admin API's update rows, `updateRoutes` (cli/update.js `createSelfUpdate`): `GET /update` — whether this Filament updates itself on request (`can`, `why`, `version`), whether an update runs, how the last went; `POST /update` `{ version? }` → 202, `filament update --wait --json` run by systemd in a unit of its own. The person's alone; the update a press. |
| `http/admin/lsp.js` | The admin API's language servers, `lspRoutes`: `GET /lsp/servers` (`?project=<id>`), for Settings › Language servers — a place's servers (`languageServers`: yours, the plugins' by app/plugins.js `into`, Filament's own), each with where it comes from, its program, its files, whether it is on and installed here; a plugin's program alone is said. `GET /lsp/symbols` (`?cwd&q&chain`): the project's names an `@#` lists, by the chat's servers (`projectSymbols`). |
| `http/admin/mcp-servers.js` | The admin API's MCP servers, `mcpServerRoutes`: the list a place resolves (`?scope=` all, a project, a chat), a server written, switched or taken out of a place, a place put back to what it inherits, a server tested, remote ones asked whether they want a sign-in, other apps' brought in. A remote server's sign-in is started (from another machine `elsewhere` unless `paste`), its pasted return taken (`pasted`), asked after, cancelled and signed out here. Credentials show as the placeholder. |
| `http/admin/memory.js` | `memoryRoutes`, the whole `/api/memory/*` surface: engine, recall, remember, forget, items, sessions and projects (`?remotes=1`: each `remoteKey`; Add project fenced by `agentLoop.roots`, Everything), turns, activity and benchmark, its traffic and daily usage, canonical facts, their claims, backup and restore, learning, hygiene, sources and imports, and where `/mcp/memory` is. Every route sits in the one guard; MCP credentials masked; a permission confirmed or corrected is a press. |
| `http/admin/model-routes.js` | The admin API's models-across-providers area, `modelRouteRoutes`: `GET /model-routes` (the view a provider's page's Backups › reads, every model you can pick with the provider it goes to first and its backups) and `PUT /model-routes` (a model's backups), over `app/model-routes.js`. Every answer carries the configuration's version, which the page sends back as `base`, so a write from a read older than a change to that model's route is refused with what changed. |
| `http/admin/plugins.js` | The admin API's plugins area, `pluginRoutes`: where plugins come from (`app/plugin-sources.js`: what Claude Code and Codex keep, Anthropic's directory, marketplaces a person adds, refreshed or removed), read only when the page asks; the plugins installed (`app/plugins.js`): install at a commit, preview, check for updates, update, uninstall, where each is on, and values per place, a secret never sent back; and the connectors' picker (`app/connector-catalogue.js`). Nothing here runs a plugin. |
| `http/admin/press.js` | The press, row by row: `PRESS_TABLE` classes every row of the admin API once — a press always; by its body (`when`); by what the row finds kept, weighed in its own handler (`by`); the door's; or none, with why (`NO_PRESS`: reads, the person's chat, undoes or narrows, an agent may, a setting that asks no less, words kept, the caller's own reach, its own proof). What starts a program as the person is one. `pressClass(row)`: a row with no class is a press, and test/ratchets.test.js fails on it. |
| `http/admin/providers.js` | The admin API's providers area, `providerRoutes`: the writes that name one provider (`GET /upstreams`, add one, change one with `PATCH /upstreams/:id`, see what goes with one at `/removal`, remove one), each over `app/providers.js` and made against the configuration as it stands. Every answer carries the configuration's version, sent back as `base`, so a change from a read older than a newer change to that provider is refused with what changed. No answer holds a key. |
| `http/admin/remote.js` | The admin API's remote area, `remoteRoutes`: pairing (`/remote/pair`, `pairLinks`), its claim (`CLAIM_PATH`); devices, grants, `/remote/agent-device`, Clear copies, `/remote/lan`, `PAGES`, `DESK`. View devices' `VIEW_ROUTES`, `viewReads`, `viewFolderRefusal`; remote agents' `AGENT_ROUTES`, `COPY_ROUTES`, `AGENT_BODIES` (`agentBodyRefusal`, `agentModelRefusal`), `AGENT_TAKES`, `agentHeaderRefusal`, `agentFolderRefusal` (`notRooted`), `copiesRefusal`, `agentFileRefusal` (`aliasedPath`, no `.git`). |
| `http/admin/run-socket.js` | A page's run follows on one WebSocket (`/api/runs/socket`, `RUN_SOCKET_PATH`), using none of a browser's six connections: `runSocketUpgrade(a)` takes `follow` and `stop`, keyed, sending what `GET /runs/:id/events?stream=1` sends, and `cast` and `input`: a chat's browser live, the person's input back (none for a view-only device: `VIEW_CAST_WORDS`, `VIEW_INPUT_WORDS`). No front door: it holds the terminal stream's guards and checks the Origin; another machine's agents are refused it. |
| `http/admin/runs.js` | The admin API's runs area, `runRoutes`: the run log read back (the list, one run's meta, and its events as a JSON page or a live SSE stream that replays from `since` and then follows), a run's steer (a note, a veto, a stop or Force stop), its answers, background calls, agent commands and images, and its changes, the rounds its `snapshot` events record read back through `adapters/git/changes.js` (`RUN_CHANGES_KEPT`). `admin/run-socket.js` carries the same streams over one socket. |
| `http/admin/sessions.js` | The admin API's sessions area, `sessionRoutes`: the inspector's and native sessions' rows — create (in a new worktree where asked; an agents' device's, or yours in a copy placed for it, marked its), truth, requests, transcript, settings, turns, compose, stop, compaction, rewind, autofit, fork, move, recall, sub-agents, second looks, graph runs; a chat's asks answered by one route (`Ask`); a revoked agents' device's chats stopped, a copy let go's deleted. | `http/admin/skills.js` | The admin API's skills area, `skillRoutes`: Library › Skills: your skills with where each is on for the place picked, the plugins' skills, what the coding agents keep on this computer, Add (folders read where they stand, a git address cloned, a skill made here), a skill's page and files, a made one's files written, Update, Remove, a made one's books added, removed and searched (`app/skill-library.js`), and a crafter chat opened (`app/crafter-chats.js`). | `http/admin/spaces.js` | The admin API's Space area, `spaceRoutes`: a Space as the page shows it (its board, What happened in `LOG_SHOWN` lines, its last `SYNCS_SHOWN` syncs, what its agents run on) and the person's writes: tasks, files, logbook lines, a sync.
