# Module map: app

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `app/`

| File | What it is |
| ---- | ---------- |
| `app/acp-collect.js` | What an agent turn collects while it runs: the reply text, thought runs flushed as one unit (natively or woven into the text), rendered tool lines and the notes the bridge raises. `createTurnCollector(...)` gives the bridge one `onEvent`; the reply, the archive and the record read the collected text afterwards. A harness turn keeps the agent's words a block per round and leaves tool cards to the run. Used by `acp-turn.js`; renders through `acp-render.js`. |
| `app/acp-render.js` | An ACP agent's activity as the markdown a text-only chat client renders: one line per tool call (`formatToolLine`), a fenced `diff` per edit (`lineDiff`, `unifiedPatch`, `capPatch`, `renderDiff`), command output (`renderOutput`), a plan as a checklist (`renderPlan`), stop reasons (`describeStopReason`, `mapStopReason`). `announceable` says whether a call's title is worth showing yet; `ActivityRenderer` and `ThoughtInliner` are the per-turn renderers. Pure, no network. |
| `app/acp-turn.js` | A turn against an agent upstream, a local coding agent over ACP or Cursor's SDK in-process: relays the newest user message to an agent session and streams the reply on the client's wire (thoughts, tool lines, a client tool call where the agent needs its hands). Answers a harness chat's commands (`commands/acp.js`), says failures in words (`failureWords`), serves sub-agent and team-worker runs in host mode. `createAcpTurn(deps)` → `{ turn }`; `MODEL_MARKS`, a model name's `@` mode, `#` session. |
| `app/acp-wire.js` | The agent's reply on the client's wire, hand-built: `createAgentReply(...)` writes the Anthropic or Chat Completions stream (the message head on first output, blocks opened and closed as the output kind changes, pings while the agent thinks in silence, the closing usage and stop reason) or the whole reply as JSON. `endWithError` puts an exited agent's stderr under the error; the agent loop writes its rounds with `breakBlock` and `sendBlocks`. Used by `acp-turn.js` and `agent/turn.js`. |
| `app/agent-context.js` | What a turn gives a coding agent's session beside the person's words: `agentContext(...)` lifts memory's blocks out of the request (the briefing and goal for the session, recall with the prompt) and adds the task graph's words (`CODER_GRAPH_TEXT`), a sub-agent's part, a plain chat's agent-tool words, where a moved chat works (`MOVED_BLOCK`, `whereBlock`), a project's services (`usesBlock`), skills (`skillsBlock`) and envelopes (`envelopesBlock`), handed over by `adapters/agents/context.js`. |
| `app/agent-followon.js` | A coding agent's turn that goes on within its request: `followedBody(body, soFar, words)` builds Filament's next prompt in the same session (a graph task's sub-agent that ended without its report is asked for it), and `joinTurns(a, b)` joins two prompts' results into the one turn the record keeps, adding up notes, usage by model, lines changed and run costs. Used by `acp-turn.js`. |
| `app/agent-guests.js` | A coding agent's own agents (Claude's Agent tool, Codex's child threads, Cursor's tasks) as rows of the Sub Agents list, read out of the runs of the turns that started them: `guestsOfRun(run, events)` folds one run's `subagent-start` to `subagent-end` events, and `createGuests({ runs, turnRuns })` → `{ list(chainId) }` keeps the newest `GUESTS_KEPT` from the last `GUEST_TURNS` turns. A guest is read-only: no follow-up, stop or apply, and no count toward the session's limit. |
| `app/agent-inbox.js` | What Filament's sub-agents send a coding agent whose harness turn launched them (a lead's workers, sub-agents, saved agents): `createAgentInbox(...)` takes their reports from the registry's door as the agent's messages, sealed as envelopes while it works, and its `wait` answers within the agent's call patience (`MCP_PATIENCE_MS`, `heldFor`). `createAgentTurns()` → `{ open, get }` finds the turn an MCP call is for by its session (`server.js`). The inbox serves `agent-launch.js`, `agent-lead.js`. |
| `app/agent-launch.js` | Filament's `agent` and `wait` tools in a coding agent's own chat, the loop's launch in the agent's terms: `launchWords` (the standing `LAUNCH_BLOCK`), `LAUNCH_GONE` and `createLaunchTurn(...)`, an `AgentTurn` that launches through the loop's door in the registry under the agent's own call. A launch that outlasts the call runs on and reports as a message (`agent-inbox.js`); helpers run on the model a launch names, else the chat's and their cards', else the agent's own model on its own account. |
| `app/agent-lead.js` | A coding agent leading a team, the loop lead's ways in the agent's terms: `leadWords(team)` for its standing context, `leadGone`, `heardBlock(notes)` (the developer's messages between prompts) and `createLeadTurn(...)` → `LeadTurn`, whose team tools (agent, worker, wait) and tasks go through `agent/team-tools.js` and the graph. Workers' reports reach it as messages (`agent-inbox.js`); a supervising lead is shown new looks at its workers (`agent/looks.js`). Used by `acp-turn.js`. |
| `app/agent-logins.js` | More than one account per coding agent, each an upstream: the Default on the agent's own login, an added one with its own folder (`acp.home`) or, on Cursor's SDK, its own key. `createAgentLogins(...)` adds, renames, removes and turns off accounts (`setOff`), signs them in and out as each bridge names (a terminal, a browser page, the agent's own, or a key pasted), and reads who is signed in without a turn (`state`, `check`). Filament types no credential and says no key in a log or an answer. |
| `app/agent-permits.js` | A chat's coding agent answered by its permission switch: `createAgentPermits(...)` → `{ mode, judge, allowed, look, unlook }` judges as the loop: rules, the mode's gate, learned permissions, a chat's always-allow (`alwaysRun`, `keeps`), `ALWAYS_ASKED`. `allowed` judges a yes. A worktree's worker is kept in it (`namesOutside`, `climbsOut`), another machine's agents' reads too, short of Auto (`readPast`), and their calls at Filament's data folder or one over it always (`filamentFolderNamed`). |
| `app/agent-run.js` | A coding agent's turn as a run: `createAgentRun(...)` reads the agent events every adapter speaks (`text`, `thought`, `tool`, `plan`, `subagent`, `raw`) into the loop's run events (`services/runs.js`), so every view built for the loop draws an agent's turn too: a round per model call, tool cards, plans, sub-agents, snapshots through the turn tree, the place the agent works in (`now-in.js`). It tells the reply where a round begins, so the reply breaks its block there. Used by `acp-turn.js`. |
| `app/agent-self.js` | A coding agent making room in its own session when Filament asks: writing Filament's summary of it (Self) or compacting it its own way. `createAgentSelf({ config, destination })` → `how`, `write`, `compacts`, `compact`, `holds`, `closed`, `forget` asks the bridge of the session's upstream what its agent can do and has it do it; the bridge knows the chat as `chain:<id>`, and a write ends by its signal, never by a clock. Built in `server.js` for the session service. |
| `app/agent-tools.js` | Filament's own tools for a coding agent's session, one list whatever the bridge (Filament's MCP server for ACP agents and Codex, custom tools for Cursor's SDK): `createAgentTools(...)` → `{ memoryOn, list, has, call }`. Memory's tools, the graph's `tasks`, a task's `report`, a worker's `ask_lead`, a lead's team tools, `agent` and `wait`, and as the chat has them the visual, artifact, `space`, `team`, `flow`, `browser`, `background_command` and `skill` tools. Served by `http/mcp.js`. |
| `app/agent-worker.js` | A coding agent serving a sub-agent's or team worker's run: `workerWords(host)` (its part for the standing context, `ROLE_BLOCK`), `workerNote(m)` (a message to it in the lead's or developer's words, Filament's own under `SHIM_HEAD`), `workerAsker(registry, host)` (permission questions put on the lead's timeline, refused with `NOBODY_TO_ASK` where nobody can answer), `deniedWords` and `workerStatus` (how its turn ended, in the registry's words). Used by `acp-turn.js`, `agent-lead.js`. |
| `app/assistant.js` | The dashboard assistant: a chat agent that configures Filament by calling tools against a per-chat draft config, reached through Filament itself on any non-ACP route; nothing is saved until the person presses Apply. `Assistant` holds the chat and runs its tools, `TOOLS` are their schemas, `buildSystemPrompt({ cfg, models, dataDir })` writes its prompt and `PAGES` lists the console pages it can point to. Built in `server.js`; served by the config area's `/assistant/*` routes. |
| `app/chat-namer.js` | Chats named by the side model (`experimental.nameChats`), `createChatNamer`: as a message reaches its model or agent past Filament's refusals (memory's `onMessageSent`), a chat Filament named (`autoNamed`) is named once from about 1K tokens of its first message; a failed try again at the turn's end with the answer (`firstExchange`, `nameInput`, purpose `title`; `cleanName`). Never one kept from memory; `NAME_TRIES` bounds the asks; a name of the person's stands. Said on `turns` as `named`. |
| `app/chat-watchers.js` | A chat's watchers, said to its pages: `createChatWatchers({ spaces, nameOf, publish, publishReviews })`. For its transcript: `of(chain)`, the watchers that watch or wake the chat (core `chatWatchers`); `reviews(chain)`, its reviewed turns by number; `guide(chain, turn)`, a guidance turn's parts as its Space keeps them; `woke(kept)`, what woke it, as its turn keeps it. `moved()`, at each Space change, says a chat's list (`watchers`) or reviews (`reviews`) again on the feed, only where they moved. |
| `app/coding-agents.js` | Settings → Coding agents: every coding agent Filament can drive (Claude Code, Codex, Cursor's CLI and SDK, Antigravity, Qoder; the registry's; one made by hand; a retired one saying why, and whether once off it leaves the settings) and where each stands. `createCodingAgents(...)` → `{ list, connect, off, remove, askModels, install, cancelInstall, refreshRegistry, refreshIfStale, iconOf, stopAll }`; installs run in a terminal the person sees, never under a running turn. |
| `app/config-change.js` | A change a feature makes to the configuration beside the console's editor: `changeConfig(config, next, { forget })` normalizes, checks and saves it, a refusal naming what is wrong; `failure(status, message)` is an error a route answers with its status. `changedSince`, `changeLines`, `changesAnswer` and `staleAnswer` say what changed since a page's read, so a write from an older read is refused with it. Used by the feature modules and `http/admin/config.js`. |
| `app/config-fields.js` | Filament's own settings as the harness's pages write them field by field (`PATCH /api/config/fields`): `changeFields(config, { set, unset, base }, listening, { refuse })` takes only `FIELD_SECTIONS` and never a credential (`fieldLeaf`), checks each value by its schema type (`fieldValue`), puts the default back for `unset`, refuses a write from an older read only when a field it names changed since, and one `refuse` names (403, `press`), and says `restartNeeded` when the host or port moves. |
| `app/connector-catalogue.js` | The connectors' picker: the plugins the marketplaces of `plugin-sources.js` list that bring an MCP server, one row per service, found by name. What a plugin brings is read in its marketplace's folder or looked at in its repository (its JSON files alone) and kept in `plugins/looks.json` by source and commit. `createConnectorCatalogue(...)` → `list`, `add` (installed and turned on at a place, hooks off), `setup`, `fetchAnthropic`, `busy`; `hostOf`, `programOf`. |
| `app/count-tokens.js` | `/v1/messages/count_tokens` answered locally and only locally: no provider is ever contacted for a count, since Anthropic's count endpoint ships the whole conversation out and OpenAI-compatible providers have none. `handleCountTokens(deps, req, res)` answers with Filament's own estimate (the one compose, the context stamp and the loop's compaction edge use) over the body as it would go out. Routed by `http/front-door.js`. |
| `app/crafter-chats.js` | Crafter chats: `/craft <words>` in a harness chat, or a made skill's Craft it, opens a new chat in the same folder and model whose first message (the person's words after `crafterBrief`) waits in its box for the person's Send. Its agent has the `craft` tool (`agent/craft-tool.js`) beside its usual tools, its meta says what it crafts (`craft.skill`, `craft.from`), and a skill has one crafter chat (`.library/crafter.json`). `createCrafterChats(...)` → `{ tool, start }`; `crafterTitle`. |
| `app/deps.js` | `AppDeps`, the typed object the composition root (`server.js`) hands the application layer: the live `config()`, the log, the usage and op stores, memory, the health board, concurrency, the guards, `destination(upstream)`, `finish`, `plan` and `dryRun`, the events bus and the other services and closures more than one use case needs. Every app module takes it as its first argument, so each says what it depends on and builds alone in a test. JSDoc only: no runtime code. |
| `app/embeddings.js` | `/v1/embeddings`: `handleEmbeddings(deps, req, res)` routes by model as chat does, forwards to an OpenAI-compatible upstream's `/v1/embeddings` and records the request. Routed by `http/front-door.js`. |
| `app/engine.js` | The session's engine as pure answers: what answers a harness turn whose session chose an engine (`engine.mode`): the named model, a team led by the agent loop on it, or the coding agent the name reaches. `engineFor`, `turnEngine`, `agentRoute` (the stages' synthetic route), `harnessRunsLoop`, `codingAgentOf`, `agentSessionOf`, `agentTurnModel`, `agentModeOf`, `engineProblem`, `engineProblemFor`, `upstreamsOffProblem`, `walledProblem` and `filamentRuns` (the chat commands' gate). |
| `app/everything.js` | Everything: where a chat set to work outside any project runs. `createEverything({ dataDir, memory, config })` → `ensure()` makes `<data folder>/Everything` the first time a chat needs it and registers it as a project named Everything (`EVERYTHING`), so its chats stand together under Projects; refused in words where no chat may work there. Built in `server.js`, behind `POST /api/memory/projects/everything`. |
| `app/features.js` | The Feature board: `featureBoard({ cfg, records, archive, session })` gives one row per feature (translation, memory, compaction, per-session config, the agent loop, forks) with its global switch, its state in the open session, a number from the person's own traffic (the request records and the archive) and where the evidence lives. Pure over what it is handed; `GET /api/features` in `http/admin/system.js` gathers the inputs. |
| `app/filament-rows.js` | Filament's own rows for an app's `filament` source: the Space's board, the project's chats, what each spent and the project's places, each a JSON list an app's columns read (`core/dashboard-sources.js` `FILAMENT_READS`). Read-only and with no AI, built from the stores the composition root hands `createFilamentRows(...)` → `(project, what)`. A chat kept apart reads as "an untitled chat" in every row (`core/space.js` `readerNames`). Built in `server.js`. |
| `app/finish.js` | Closing a request's record, once: `createFinish(...)` → `finish(rec, patch, table)` frees the in-flight abort slot, gives the store the final tokens and cost, raises the fallback alert, tells the health board the outcome (an abort is never the upstream's fault) and books the spend on the session's ledger (`ledgerEntry`). `createLeftSpend` books what a harness chat's coding agent spent in cycles no turn showed. The pipeline and commands reach it as `deps.finish`. |
| `app/flow-runner.js` | A flow's runner: the person's agents and teams in steps beside a chat. The main agent drafts one with its flow tool after `/flow`; the person drafts or edits one by hand or from a saved flow, and Start is theirs alone. A step's boxes start once the step before is done; an agent box is a sub-agent of the person's, a team box a team sent beside the chat; gates and reviews hold the flow for the person. `createFlowRunner(...)`, `stepsInput`, `GO_ON_LINE`. Served by `http/admin/flows.js`. |
| `app/fork.js` | The save-state fork with its working tree: `forkSession({ memory }, chainId, { atTurn, worktree })` forks the conversation in the archive, then, where asked, checks the fork turn's snapshot out detached beside the repository or into a named folder and records it on the fork's meta. The conversation always forks; a worktree that cannot be made is said in words on the result, never a 500. Built in `server.js` for the sessions service's `fork`. |
| `app/git-footprint.js` | Filament's footprint in a repository, read and cleaned up: its copies, its refs under `refs/filament/` and the branches its routines' runs made, each with whether Clean up takes it or why it stays (`core/footprint.js`), from git, the disk, the sub-agent registry, the archive, memory's backups and the Spaces. `createFootprint(...)` → `{ read, clean }`; a read serves every ask for `READ_KEPT_MS`, and Clean up runs only on the person's press, one repository at a time. Used by `http/admin/git.js`. |
| `app/housekeeping.js` | Housekeeping requests: calls a client makes to its model that are no conversation, such as a 3-7 word session title. Sent to a coding agent, such an instruction reads as a task, so `detectHousekeeping` recognizes them and `makeTitle` and `makeSummary` let Filament answer them itself or hand them to a cheap API model. Used by `acp-turn.js` and the situate stage. |
| `app/hunt-range.js` | A hunt's range read from git: `resolveRange(...)` turns `core/hunt-range.js`'s range into the files in the chat's folder, each with the lines its diff changes and the command that reads it, or says why not in words. With none named it is what is uncommitted plus what the chat's turns changed (`ownChangesOf`, `CHAT_ROUNDS`). Read-only (`--no-optional-locks`, plumbing reads) and asynchronous, a few files at a time, untracked files counted to a cap. Used by the sessions service. |
| `app/internal-call.js` | A model call through Filament's own front door, the pattern every server-side loop copies: a `/v1/messages` request over loopback with lineage headers and the house key, so routing, failover, rules, memory and billing apply. `createInternalCall(...)` streams deltas to `onDelta` and returns the assembled message, no clock of its own; a failure names its provider and `retryAfterSeconds`. `withinFrontDoor` drops older media past `server.maxBodyBytes`. Used by the agent loop and the pipeline. |
| `app/letters.js` | Letters between chats, and inside one between its agent and its sub-agents: `send(from, input, {agent, waits})` writes or answers one; `heard` reads the person's messages. A chat writes one tagged in it, one that wrote to it, or its thread or starter; its agent a running sub-agent, whole at its next step; a sub-agent "lead", sealed (`waits`). At most `LETTERS_ALONE` while the person is silent, a thread's in its starter too; a reply goes once. Kept on chat meta; the registry's `letter` seals it. |
| `app/memory-mcp.js` | The tools of `/mcp/memory`, memory for an agent Filament does not run: `MEMORY_MCP_TOOLS` (short names, reads marked read-only), `memoryMcpCall(memory, name, args, where)`, where each call stands as `agent` in its folder's project and on the session's `mcp` chain, what it is shown is logged and a later retraction said first, and `memoryMcpOpening` (`initialize`'s instructions, with a brief when the folder is known). Shared verbs run `executeMemoryTool`. Served by `http/memory-mcp.js`. |
| `app/memory-tools.js` | Memory as tools the model calls: Filament attaches the `filament_memory_*` tools (search, sessions, load, remember, correct, close, confirm, forget, grep) and `filament_recall`, runs their calls against the brain and asks the same upstream again, withheld from the client, on the Anthropic, Chat Completions and Responses wires. Exports the schemas, `attachMemoryTools`, `executeMemoryTool`, `runMemoryTools`, `mergeJsonRounds` and the usage math (`clientUsageOf`, `totalUsageOf`). |
| `app/model-book.js` | The models a sub-agent's launch reads: the catalogue as the harness picker has it (`withAgentWords`: each coding agent's model in its own words), folded into families once per change, never per launch. `createModelBook(...)` → `stale()` on a save or a list answering, `now()` reads at once, `fresh()` waits for a stale book to be read again when a name as a person says it must match; a read never asks a provider. Built in `server.js`, which wires the registry's model choice. |
| `app/model-routes.js` | The models view Settings › Providers' Backups › reads: every model you can pick across providers and coding agents, with the provider it goes to first, its backups in order, whether it is in the picker, its window and price. `modelRoutesView(cfg, base, all)` is the page's view; `setBackups(config, name, rows, base)` keeps a model's backups (`core/backups.js`), refused when the route that catches the name changed since the page read it. Served by `http/admin/model-routes.js`. |
| `app/models.js` | The model list a client sees, `listModels(deps, res, format)`, in the Anthropic or OpenAI shape, and the catalogue's plumbing: `createModelCache(...)` keeps discovered lists in models-cache.json (asked on Refresh or a save that changed a provider), the windows coding agents named, the names each listed itself (`ownNames`), provider-stated output ceilings (`noteOutputCeiling`) and `windowForModel`; `cheapestModel` picks memory's cheap model. Routed by `http/front-door.js`. |
| `app/now-in.js` | Where the main agent works: `createNowIn({ root, publish, fresh })` → `{ saw(round, call) }` reads each call's place (`core/call-place.js`) to the top folder of its repository or worktree and publishes a `place` event on the run when it moves; the chat's folder is said only once the agent has worked elsewhere. Live only: nothing is kept past the run. Used by `agent-run.js` and the agent loop. |
| `app/own-spaces.js` | Spaces of your own (Work, Personal): a Space that belongs to no project, made as a project whose folder Filament makes (`Documents\Filament Spaces\<name>` or one picked), so it has its own memory, settings layer, Space and chats. `createOwnSpaces(...)` → `list`, `make`, `change`, `remove`, `widens`; what its chats may read beyond its folder is its layer's `loop.addedFolders` (`REACHES`, `THESE_MAX`, `reachLimits`). Deleting one deletes its chats, memory, board and routines; its folder stays. |
| `app/own-turns.js` | A coding agent's own turns, asked for: when the ACP bridge says a cycle the agent began by itself on a harness chat's session wants a turn (`onOwnCycle`), `wireOwnTurns(bridge, ...)` asks the sessions service for it through Filament's own door as a house call (`POST /api/sessions/:id/own-turns`) and tells the bridge how it went: shown, asked again once a busy session or a pending question frees, or refused. Wired in `server.js`. |
| `app/plan.js` | The request planner: `plan(...)` says which upstream one candidate is and the shaped request it gets (routing, rules, translation, the Responses wire-API detour), pure over the config handed in, so a dry run can plan against a draft. `dryRunWith` serves the admin API's dry run; `upstreamModelOf` and `cacheTtlLayer` serve the stages. The pipeline reaches it as `deps.plan`, the dry-run route as `deps.dryRun`. |
| `app/plugin-places.js` | Where a plugin is on: your defaults, a project's (a Space's) or a chat's `plugins.on`, each written through its layer's one writer. On at a place, a plugin is on in every chat there unless a narrower layer turns it off (`enabled: false`); its hooks have a switch of their own; uninstalled, it is taken off everywhere. `createPluginPlaces(...)` → `turn`, `at`, `onAt`, `placeOn`, `projectOf`, `everywhere`, `forget`; `placeLayers` is shared with `skill-places.js`. Served by `http/admin/plugins.js`. |
| `app/plugin-sources.js` | Where plugins come from: Claude Code's marketplaces and installed plugins, Anthropic's directory from Claude Code's copy, Codex's marketplaces and plugins, and marketplaces a person adds (a GitHub repository, an address, a folder). What Claude Code and Codex keep is read where it stands when the Plugins page asks, never written; an added marketplace is cloned into `plugins/marketplaces/<id>`. `createPluginSources(...)` → `found`, `entries`, `add`, `refresh`, `remove`. Installs nothing. |
| `app/plugins.js` | Plugins installed in Filament: one a source lists is copied at a fixed version or commit into `plugins/installed/<name@marketplace>/<version>`, with its own data folder, never run from Claude's or Codex's copy. What it holds is read as it is copied: MCP servers, hooks, skills, commands, agents, and the values it asks for, secrets sealed per place. `createPlugins(...)` → `list`, `get`, `install`, `check`, `update`, `uninstall`, `into`; `readPlugin`, `pluginAgentCard`. Installing runs nothing. |
| `app/providers.js` | Settings › Providers: `createProviders({ config, usage, now, machines })` → `list` (every upstream in the page's words: catalogue entry and plan, key set or not and where it came from (`keyFrom`), never the key, prefix, routes, model lists, last test, today's spend), `add` (another machine's models too: `type: "filament"`, `machine`), `change(id, patch, base)` (refused if changed since the page's read), `removal` and `remove(id, { also })`. Served by `http/admin/providers.js`. |
| `app/readiness.js` | Whether Filament can answer yet, one rule read by the console's Get started, Home's hero and `--open`: `upstreamCanAnswer(u)` (enabled and holding what its type needs; another machine's models while not found offline), `modelsThatAnswer(cfg, models)`, `frontDoorUrl(base, answering)` (where `--open` lands) and `startFacts(...)` (what `GET /api/start` answers). Used by `models.js`, `server.js` and `http/admin/system.js`. |
| `app/remote-work.js` | Run on, the desk's side: `createRemoteWork({ dataDir, remote, may, inRepo })` → `send` (`placeForPerson`; asked first, again for new files in no commit and Git LFS: 409 `ask`, `allow.ask` its id), `chat`, `check` (what waits, `previewApply`: `waiting`, `seen`), `back` (`takeBack`, `applyTaskWork` from the last apply in the repo's turn; `conflicts` until `choices` for that `at`, a refused write in words; 409 `runs`), `forget`, `list`, `places`. `remote-work.json`; refs `WORK_REF_PREFIX`. |
| `app/routines.js` | Routines' runner: what an agent of a project does by itself at its times, or as a watcher's events are heard. One timer serves every routine on; a run is a new chat of its project (read-only unless it writes, then in its own worktree), a turn of Filament's in the chat a watcher wakes, or a row in Needs you. Events wait while it runs, coalesced, never dropped. `createRoutines(...)` → `start`, `stop`, `arm`, `tick`, `heard`, `released`, `freed`, `hostOf`, `runNow` (and a wake's Retry), `live`. |
| `app/second-look.js` | A second look's run: the Reviewer (`REVIEWER`, read-only) reads a move before the person answers it, launched through the registry as one Filament starts itself, with no seat and no transcript row, its answer the person's alone. `createSecondLook(...)` → `start` (on the person's model choice, else the card's), `run`, `stop`, and `check` and `ended` for whether a dashboard button did what it is for; `lookIn(looks, chain)` gives a chat's looks to a turn's gate. Built in `server.js`. |
| `app/skill-from-memory.js` | The lines a made skill holds from memory: Add to a skill… writes a memory's words into a section of its SKILL.md, and `noteFromMemory` records them in `.library/from-memory.json` (`FROM_MEMORY_FILE`, `fromMemoryOf`).
