# Module map: ui

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `ui/`

| File | What it is |
| ---- | ---------- |
| `ui/app.js` | The console, the settings UI at `/ui/`: vanilla JS, no build step, every form generated from the server's schema. Boot, the hash router, `render()`, the live events stream (`onEvents` over `ui/lib/listeners.js`, let go when the page is put away), `bindUi` filling `runtime.js`'s `ui`, the engine line above every page, the agents' accounts (`followAccounts`), `putConfig` (naming the draft's `read` version, keeping `state.unreadable`), `readTrafficAgain` on a new `hello`; Ctrl+S, `commitFocused`. |
| `ui/copy.js` | The clipboard and secret-display widgets the console's pages share: `copyBtn`, `copyline`, `secretLine`, and `CHROME`, the shell's labels. |
| `ui/harness.css` | The harness's main sheet: the two Zai token sheets verbatim from the design reference, the type scale, keyframes, scrollbars, the focus model, the `.zc-*` primitive rules, and the region and component CSS for the sidebar, header (its clusters giving way by room), transcript, composer and rail; the task sheets, the held picture's chip (`.md-img-held`), the ask card and line, a thread's tile (`.thp`), the envelope cards (`.env-card`), and off-screen turns skipped (`content-visibility: auto`). |
| `ui/harness.html` | The harness page: first a script setting the theme's class before the first paint (theme.js's rule; the chat alone's `?theme=` first); links `harness/zc.css`, `harness.css`, `harness/instruments.css`, the settings sheets, the panes', views', team's, side's, flow's, overview's, Library's and Space's sheets, and last `harness/aqua.css`; loads KaTeX and xterm from `harness/vendor/` as classic scripts; mounts `#app` and the toast, runs `harness/app.js`; not the console's `style.css`. |
| `ui/index.html` | The console page: `style.css` and the shared settings sheet, the sidebar with its hub tabs (Home, Traffic, Usage, Memory, Destinations, Lab, Settings), Open the harness and the Assistant; runs `/ui/app.js` as a module. |
| `ui/nav.js` | Page titles, hub tabs and hash aliases in one table, so the sidebar, the palette and the hash router cannot drift: `PAGES`, `HUBS`, `HOME_PANES`, `HOME_SUB`, the hubs' tabs (`MEM_TABS`, `DEST_TABS`, `LAB_TABS`, `SETTINGS_TABS`, `HELP_TABS`, `CONFIG_TABS`), `TAB_ALIAS`, `TRAFFIC_VIEWS`/`TRAFFIC_TABS`, `navId`, `parseHash`/`formatHash` (a hub's bookmark round-trips) and `palettePages`. |
| `ui/pair.html` | The pairing page (the owner's remote Filament of 11-06), where another machine's browser claims a code made on the machine Filament runs on: the machine's name, the code and this device's name, Pair, and Open Filament once paired. Its sheets are the harness's (`harness/zc.css`, `harness.css`, `harness/aqua.css`); its script is `pair.js`. Served to anyone, as an unpaired browser that opens the harness or the console is sent here (`http/front-door.js`). |
| `ui/pair.js` | The pairing page, `mountPair({ doc, fetchImpl, loc, hist, ua, win })`: a link's code and fingerprint read from its fragment (`codeOf`, `printOf`), a link opened on the page too, and taken off the address; over https, `printWords` asks the person to compare the browser's certificate details; over plain http from another machine (`inTheClear`) it sends no code; a paired browser goes on, a lapsed one is told; the claim POSTed to `/api/remote/claim`, refused in words (`claimWords`). `deviceName`. |
| `ui/runtime.js` | The console's shared runtime: the mutable `state`, `REQ_FILTER_DEFAULTS` and `setReqFilter` (the Traffic filters), and `ui`, which `app.js` fills through `bindUi` once its helpers exist. Pages and components read `ui` at call time, never at module load, so nothing imports in a circle. The harness does not import it. |
| `ui/style.css` | The console's sheet: tokens, themes, the shell and its components. The harness does not load it. |
| `ui/tray-card.css` | The tray card's layout (HarnessV3-Native NA-D9): the widget kit's parts (`harness/instruments.css`) laid out for the desktop app's small frameless window — its head fixed and dragged, the chosen part scrolling under it, its foot fixed — on the popover's own solid colours in both themes. |
| `ui/tray-card.html` | The tray card's page, loaded in the desktop app's small window by the tray: the harness's tokens (`harness/zc.css`, `harness.css`), the widget kit (`harness/instruments.css`) and `tray-card.css`; mounts `#card` and runs `tray-card.js`. |
| `ui/tray-card.js` | The tray card (HarnessV3-Native NA-D9): Now (the harness's own Now from `harness/now-list.js`, every project, with the model calls in flight, `flightRows`), Today (the alerts but memory's, `cardAlerts`, the day's figures, each coding agent's plan, `planWords`), Requests (the last twelve) and Upstreams. `readCard` asks every 3 s while it shows, never hidden; `cardView`, `headFacts`, `cardNow`, `routeOf` (a row opens its chat through `window.filamentDesktop`). A browser gets it without Restart. |

| File | What it is |

Row buttons (`onRow`, `pressOff`) only tell the harness. |
| `ui/artifacts/deck.js` | A deck's slides from its Markdown, pure (E18 step 6), so the page, a test and the edit beside the page read them alike: `splitSlides(markdown)` — slides between lines of `---` (never inside a fence), a `#` or `##` heading starting one where there are none, each with where it starts and whether it is a title slide — and `slideAt(slides, at)`, the slide a caret is in. |
| `ui/artifacts/design.js` | A Design's page (E18 step 7): the agent's screens side by side on a canvas at their sizes (`SCREEN_SIZES`, `screenBox`), each named above (`screenLabel`), fit to the view as it opens (`fitView`); zoom from 10% to 400% at the pointer (`zoomAt`), a move by a drag, the wheel or the arrows; a screen clicked fills the view to try as a prototype, Esc goes back. Each screen is a frame of no origin (`SCREEN_SANDBOX`) built by `screenPage`; what fails in it is told to the harness, naming the screen. |
| `ui/artifacts/doc.js` | A Doc's page (E18 step 6): the agent's Markdown as a document in the harness's type, with an outline of its headings beside it where the page is wide and behind a button where it is narrow, the part in view marked as it scrolls; its diagrams drawn in its theme and Copy on each code fence. Inside the harness it follows the draft edited beside it, where it stands. |
| `ui/artifacts/markdown-page.js` | What the Doc's and the deck's pages share (E18 step 6): `markdownOf()`, `markdownHtml` (`ui/lib/md.js`'s `mdDoc`, escaped first, its pictures drawn at once), `drawDiagrams` (a mermaid fence drawn in the page's theme, the library loaded only when one is there, `MERMAID_GLOBAL`; one that does not parse keeps its code with the error under it), `copyButtons` and `headingLinks`. |
| `ui/artifacts/slides.js` | A deck's page (E18 step 6): its slides 16:9, drawn at one size and scaled to the page, type too large made smaller until it fits; the arrows, Space, PageUp/PageDown and Home/End move, O shows every slide, F fills the screen (asked of the harness inside its frame), P prints a slide a page. The slide shown is kept in the address (`#3`) and the tab; a card's preview shows the first slide; a draft opens at the slide its caret is in. |
| `ui/artifacts/type-page.js` | What Filament's own pages for its types share (E18 steps 6 and 7) — Doc, deck, Dashboard and Design, run on the artifact's own address after Filament's look: `pageContent()` (what Filament wrote in as data, `#filament-content`, never as HTML), `framed`, `still()` (a card's preview), `tell`/`hear` (drafts and the full screen, with the harness), `darkNow`, `onTheme`, `fullScreen`, `mark` with `FILL_MARK`/`LEAVE_MARK`, and `part(tag, cls, text)`. |
