# Module map: ui/harness chat (conversation, composer, views)

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `ui/harness/composer/`

| File | What it is |
| ---- | ---------- |
| `ui/harness/composer/ask-line.js` | The line over the composer for a draft that starts with a saved agent's tag (HarnessV4_Tasks E15): `askLineWords` gives who gets it, on which model, what they see and its size, why it does not go yet; `createAskLine` draws it, offers one launch per model family where the pool holds several makers, and holds a draft whose `@word` names no agent. `useLineWords` says whom a draft to the main agent names for it to use. |
| `ui/harness/composer/attachments.js` | The box's attachments: up to 10, each 20 MB or smaller. Images and PDFs go as base64 blocks (`attachmentBlock`), text files fenced; a picture past `PICTURE_MAX_BYTES` is drawn smaller first (`fitPicture`); one that takes the message past what Filament takes in one request is refused in words. A box made without PDFs (the Agents tab's) refuses one (`pdfRefused`). `createAttachments` draws each as a card and the drop overlay. |
| `ui/harness/composer/bar-fit.js` | The typing row as its room runs out, `foldToFit(bar)`: while a part's box ends past the row's (`holds`; Stop's ring is no part) one pill more folds to its glyph, in `FOLDS`' order (permission, usage, team, Context, model, effort), each a `fold-<name>` class aqua.css reads; `is-squeezed` past the last. Fitted on the row's or a part's resize, and on a folded row's changed words (`AGAIN_MS`). |
| `ui/harness/composer/composer.js` | The composer shell, `createComposer`: the mode switch, model picker, tuning chip, attachments, queue and slash panels, and the session strip under the box. Enter or Ctrl+Enter sends per General's Send with; mid-run it steers or queues; only Stop stops. It offers the widget slots (`bar`, `strip`, `meters`) and its live figures (`live()`), and writes settings through `cb.onSettingChange` / `cb.onSettingsWrite`. A view-only page (`setViewOnly`) reads and sends nothing. app.js builds it. |
| `ui/harness/composer/effort.js` | The tuning control, `createEffortControl`: the chip beside the model whose face is the reasoning meter (a bolt for fast mode, the window when not the standard one) and its popover of what the model offers — Reasoning with Auto first, Extended thinking, Speed, Context window — each written at once; `keeps: false` for a level chosen apart from a chat. `LEVELS`, `splitEffortLane` (a name ending in a level), `lastTuning` (the last choice, seeding a new chat), `rememberEffort` (the welcome tour's). |
| `ui/harness/composer/kept-queue.js` | A chat's waiting messages across a reload (HarnessV4_Tasks U4): `keptQueues(store)` gives `keep(chainId, items)`, writing the queue and held steers to the tab's sessionStorage as the page goes away and each second they change (app.js `keepQueues`: a crash runs no pagehide), and `take(chainId)`, which hands them back once; queue.js's `queueRestored` takes them. `keptLostWords` says which files could not be kept. Tested in `test/queue-per-chat.test.js`. |
| `ui/harness/composer/mode.js` | The permission mode switch, `createModeSwitch`: a view of the session's `loop.permissions`, its four `MODES` on toned tiles (Full access red); for a new chat it holds a pick for the create call. Under the modes, the rules in force (a chat's always-allow first), a line each (`ruleWords`), each with Forget. `switchAnswer` / `switchWords`: the words sent when the switch moves while a permission waits. Under a team in charge that changes no file (`setReading`) the chip reads Read-only and says why. |
| `ui/harness/composer/model.js` | The model picker, `createModelSelect`: a popover over the server's families, a tab per source and a search across them, a row per model (`familyFacts`, `modelTile`); a coding agent's tab has its plan's gauge (`sourcePlan`); another machine's a dot, amber offline, grey unasked, its tab before a listing says why (`sourceMachine`, `machinesOf`, `setMachines`). `firstModel`, `shownName`, `emptyList`, `pickerFoot`; `align: "start"` opens at the chip's left. |
| `ui/harness/composer/overrule-line.js` | The line over the composer while the next message overrules what saved agents answered the main agent (HarnessV4_Tasks E15 step 3): `createOverruleLine` shows whose answer and a × to take it back. Pure helpers: `withOverruled` (at most `MAX_OVERRULED`), `overrulesSent`, `overruleWords` and `overruleMark` (a sent message's mark). |
| `ui/harness/composer/queue.js` | The queue panel, `createQueue`: messages typed while a run is live, sent one per run end; stop, error or a refused send pause it until Continue; rows reorder, steer now, edit or remove. Each chat keeps its own (`queueState`); the pure rules are `turnEnded`, `turnSettled`, `openedIdle`, `queueRestored`, `queueAdd`, `awayNext` / `awayBack` (a chat not shown sends its own next message). Tested in `test/queue-per-chat.test.js`. |
| `ui/harness/composer/rich-box.js` | The message box, `createRichBox`: a `contenteditable` element with a textarea's ways (`value`, `selectionStart`, `setSelectionRange`) whose text is its words alone; each chat tag (`[title](chat:<id>)`) is drawn as the chat's link, one piece the caret steps over and Backspace takes whole. `textOfNodes` reads the box as it shows; where the browser's writing stops matching the text, it is drawn again with the caret kept. |
| `ui/harness/composer/slash.js` | The slash and mention panels, `createSlashPanel`: `/` lists commands in groups (`commandRows`) and a coding agent's own; `@` lists saved agents and teams first where a tag addresses them, then files and sessions, and after `@#` the project's names (`/lsp/symbols`), a pick tagging its file and lines; `#` lists sessions; `$` lists skills (`skillRows`, `SKILL_SECTIONS`). Picks insert what the model sees, e.g. a chat tag; `typedOf` gives a command's own words. Drawn like Spotlight. |

| ---- | ---------- |

| `ui/harness/conversation/artifact.js` | `artifactCard(at, hears)`: a page an agent published, as its card in the answer (HarnessV4_Artifacts_Plan E18) — the word Artifact, its title, its version and how many there are, type and description. | `ui/harness/conversation/beside-marks.js` | `besideMarkRow(m)`: a team on the side of the chat, as two cards in its transcript (team_v2_plan §5.4, §10 O3) the agent never sees — where it was sent (who, what, its state, its switches) and where its result came (findings, Send to your agent…, Verify, Ask its lead, Open beside). | `ui/harness/conversation/browser-line.js` | The browser's line over the box: while the chat's agents drive its browser, who and what its newest call does, with Watch live, which opens the Browser pane (`WATCH_DOES`) and goes while that pane is in sight (`inSight`). `browserLineOf(use, working, now, rested)` decides whether it stands — a call under way, or recent use while the chat works, within DRIVE_MS; `createBrowserLine` paints it; `usingWords`: its words on the header's Browser button. app.js feeds it from lib/browser-use.js. |
| `ui/harness/conversation/cards.js` | Drawing the cards Filament attaches to its own answers (HarnessV3-Facade D4): `cardEl` for the kinds in `DRAWN_KINDS` (settings-change, settings-list, goal, autofit), a kind the page does not know falling back to the answer's text; `memoryNoteEl`, the memory note above a reply with one Load per related session. Every button sends chat text as the person's next message. |
| `ui/harness/conversation/catch-up.js` | Catch me up's quiet line over the box (HarnessV4_Tasks E15 step 7): `createCatchUp` shows `MOVED_WORDS` when the session moved while nobody looked; its button opens Catch me up in the Agents tab with the question in the box (`CATCH_UP_DOES`) — nothing runs until it is sent. app.js hides it once someone types or sends. |
| `ui/harness/conversation/compacting.js` | The Compacting row: a compaction under way at the transcript's end — who writes, what has been written (an estimate, said as one), a slice pass's calls and percent, its time (`ranFor`) and a silence past `QUIET_MS` — with Stop. `compactingParts` gives the words from the server's `compaction-progress`; `compactingRow` draws it, optionally with a bar. Nothing is worked out on the page. |
| `ui/harness/conversation/crafter-line.js` | The crafter's quiet line over the box, `createCrafterLine`: in a crafter chat, the skill it crafts and a button back to the chat `/craft` was typed in; in that chat, a button per crafter at work or waiting. Its words come from lib/craft.js `craftLineOf` over the sessions list; its buttons only open chats. |
| `ui/harness/conversation/decisions.js` | The dock's decisions (HarnessV3-Views VW-D6), `createDecisions`: what waits for the developer above the composer in any view — the session's pause (interaction.js's blocks), a coding agent's questions (agent-ask.js) and each worker's waiting call on one line (`workerLine`). `answerControls` draws a worker's Deny / Always allow / Allow once for the dock and the Team view's cards; `dockKeys` keys each block so typed words survive repaints. |
| `ui/harness/conversation/empty.js` | The empty / draft state, `createEmptyState`: the time-of-day greeting, the "Start a new chat in" project chooser (`projectRows`, `knownFolders`) with the folder's path and branch, and once a folder is chosen the Start board (start-board.js) with Works in (works-in.js), asked of `POST /sessions/draft-start` as the held choices, model or draft move. Every change is held on the chat until the first send. A view-only device's page (hook `viewOnly`) says it starts none and asks nothing. |
| `ui/harness/conversation/envelope-line.js` | The envelopes' quiet line over the box (HarnessV4_Envelopes_Plan): while other agents' results wait sealed for the chat's agent, how many and whose the oldest is, each sender and subject on hover; it goes as the agent opens them. `envelopeLineOf` reads lib/subagents.js `envelopes`; `createEnvelopeLine` paints it. |
| `ui/harness/conversation/explain.js` | "Explain this request" (HarnessV2 §10.5): `renderExplain(report)` draws one request's composition report (`GET /api/requests/:id/composition`) as sections — the request, the context with a `shapeStrip` of per-turn shapes, memory's blocks, compaction, the loop and every note Filament made. Pure rendering; app.js fetches and opens it. |
| `ui/harness/conversation/history.js` | A session's earlier turns as read-only turns (HarnessV2 §10.1): `transcriptTurns` reads `GET /api/sessions/:id/transcript?work=held`, each turn with its message, final answer, marks, facts and card; work is read as its row nears the screen (`takeWork`, `withReadWork`). `mergedTurns` / `keptPageTurns` merge the page's turns with the server's; `placeBoundaries` places settings and compaction boundaries. Nothing is resent: the server composes every request. |
| `ui/harness/conversation/in-charge.js` | `createChargeBand(io)`: the gold band at the top of a chat while a team's lead runs it (team_v2_plan §10 O4; HarnessV4_Tasks U13 W3) — the team's crowned portrait, who runs the chat, a link to its crew on the Agents tab, and Back to your agent, greyed with why while a switch must wait. A team's own chat has no Back; nothing shows while your agent leads. |
| `ui/harness/conversation/interaction.js` | The dock's interaction blocks: `permissionBlock` (a command whole or a file change with its diff, Allow / Always allow (project, or chat) / Deny, a review rule's second look via `reviewWords`), `inputBlock` (a question's choices with Other…), `errorBanner`, `limitCard` (a coding agent's plan stopped its turn) and the switch card (`askOf`, `switchChoices`, `switchCard`) for an account or model switch. Ask helpers (size, cold, lost, changed): `askFacts`, `askSentence`, `askTitle`, `askCard`. |
| `ui/harness/conversation/live-line.js` | The live line under the running turn (proposal_ux §4.3): `liveLineOf(turn)` gives its state in the loop's words (a wait, what it waits for: labels.js `waitingWords`), its round, its time and when it reached its coding agent; `createLiveLine` paints it in place on turn.js's shared timer, orange while it waits for your answer, and `clear()` drops the clocks' words. |
| `ui/harness/conversation/navigator.js` | `createNavigator`: the query-map rail — one tick per user message, shown when the pointer nears the frame's left edge and the chat has two turns or more, a hover preview of question and answer, and a click that scrolls the turn to the top with a highlight. It stands beside the transcript alone (`place`), never beside the composer. |
| `ui/harness/conversation/quote-button.js` | `quoteButton`: Add to chat over a selection in the transcript, handing the selected words to the composer as a quote. It follows the selection as the transcript scrolls and goes when the selection does — a click elsewhere, a key, another chat drawn. |
| `ui/harness/conversation/reasoning.js` | `thinkEl`: the thinking block — Thinking in the gradient while it streams with the last line rolling in, Thought · a duration once done, a plain-text body, collapsed once finished. Appearance's Show reasoning is set on the page's root (`data-hide-reasoning`), where aqua.css hides the blocks. |
| `ui/harness/conversation/rewound.js` | The rewound line (HarnessV3 Step 3, D11): turns a rewind took out folded into one line where they stood — "You rewound turns 5–7 and their files · Show them · Undo · Open as a fork". `rewoundRow` and `filesRewoundRow` draw it (DOM-free, `h` injectable); `turnsWords`, `lineWords`, `filesLineWords`, `fileWords` and `rewindButton` hold the words of the rewind and its confirm. |
| `ui/harness/conversation/routine-card.js` | A routine or a watcher an agent proposed, proposed in its chat: `routineCard(p, callId)`, the card under its space call — routine-sheet.js's view with Switch on, Not now and Ask for a change while proposed; one line once on, paused, removed, changed by a later call, from another chat or on a view-only device. | `ui/harness/conversation/second-look.js` | A second look, drawn (HarnessV4_Space_Plan S3b): `secondLookView(look, o)` on a review rule's permission card and a dashboard button's sheet asks `/sessions/:chain/second-looks/:agent` for the Reviewer's run and follows it — what it reads, its five lines as they come, its time — or says why there is none. Under its head, the model it runs on, what it was asked and `openReviewerCard`. |
| `ui/harness/conversation/held-launch.js` | `heldLaunchRow(m, chainId)`: the card for sub-agents that change files while Parallelize tasks is off — each launch's model and place, a clock counted from `left`; Accept, Always accept in this chat, or One at a time; answered, one line where its agent asked (`heldRound`, `heldAnswered`). | `ui/harness/conversation/side-offer.js` | `sideOfferRow(m, chainId)`: the side-by-side card after a turn whose end found ready tasks that can run at once — each task with the files it writes and where it works, the chat's model (Accept off without one). | `ui/harness/conversation/start-board.js` | The Start (proposal_ux §4.13): `createStartBoard` draws how a new chat starts before its first send — who runs it, where it works, what it starts from with Undo all — then the first request with its window figure and parts, and every card (Tools, Memory, Skills, Compaction, Sub-agents, Instructions), greyed where the engine does not read it. | `ui/harness/conversation/status-panel.js` | The chat's status in one of two places (`STATUS_PLACES`, Appearance › Chat status): `createStatusCapsule`, the capsule first in the composer's strip (`capsuleWords`: Working, Needs you, Making room, Stopped, Comes back, Still open) whose popover has the goal, progress, agents at work, background commands, what is still open, changes and terminals; or `createStatusPanel`, the floating card. `stillOpenRows`, `openCounts`, `gitRows`. |
| `ui/harness/conversation/subagent-marks.js` | `subagentMarkRow`: the developer's own sub-agent in the transcript (HarnessV3 §15 item 86) — sent off and back with its report, named by its card, the arrival's changes as "N files wait in its copy · Review ›"; a report kept aside offers Send to the main agent. A saved agent's mark is agent-card.js's card instead. `followStore` keeps a row following the store while drawn; `arrivalWhere` says where the report was read. |
| `ui/harness/conversation/team-turns.js` | The conversation under a team (HarnessV3-Views VW-D8): `engineDivider` where the turns' engine changes ("Builders' lead took over this chat"), `orderRowsEl` for the lead's launches under its reply (a click brings the worker's card), `engineSig` (the lead's signature at the head of its replies) and `engineTag` (a turn footer's tag). Words come from lib/team.js; each takes the element maker. |
| `ui/harness/conversation/timeline.js` | The conversation timeline, `createTimeline`: the conductor that owns the scroll region — turns through turn.js, history turns, boundaries, the empty state, the navigator, cards, envelopes, visuals and artifacts, and the tail (live line, Compacting row, waiting-on line). Exports `cardsEl`, `envelopeCard`, `noticesEl`, `steerEl`, `keptBox`, `keepOutputs`. |
| `ui/harness/conversation/turn.js` | One turn's DOM: the user row (`userRow`: bubble, pictures and PDFs sent, chips, the clamp, what rode ahead of it via `deliveredWords`), the fold header (`workFold`, `ticking`), the footer (`footerEl`: Copy, Fork, Retry, Details, the facts, `reviewedChip`), plus the rows between turns — `resumedRow`, `wokeRow`, `syncRow`, `teamResultRow`, `flowSaidRow`, `watchedRow`, `guidedRow` (`guideCard`) — and `treeCard`, `commandAnswer`, `shimNote`. | `ui/harness/conversation/visual.js` | `visualCard(at, hears)`: a visual the agent drew, as its card in the answer (HarnessV4_Visuals_Plan E16) — a header naming it a visual with Save (also keeping it as an artifact), Code and Copy; the picture in its sandboxed frame, "Drawing title…" while it streams, and a line for what failed with Tell the agent. | `ui/harness/conversation/waiting-on.js` | The line after a chat's last turn while its work goes on without a turn: `waitingOn(...)` says what it waits on — background commands, its agents at work, its come-back — once the newest turn ended; `waitingOnWords` gives "Not done yet · waiting on npm test · 2m…", or after a Stop that the next message tells the agent; `waitingOnRow` draws it with its clock. | `ui/harness/conversation/works-in.js` | Works in, the Start's second question (HarnessV4_Git_Plan step 5): `createWorksIn` offers This folder, Another worktree (from `GET /git/places`) and A new worktree with its branch name made from the message (`nameFromMessage`) and checked on `GET /git/places/new`; under it what the worktree gets a copy of and what the send will do (`makeWords`).
