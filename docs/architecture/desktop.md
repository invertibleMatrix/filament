# Module map: desktop

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

The desktop app is Electron: Filament's server as the app's child (`utilityProcess`), the harness and the dashboard in
windows of its own, a tray with its card (Filament's page `ui/tray-card.html` in a small window by the tray),
notifications, start at logon, and the machines one harness window drives (a chip in its top bar, the app's popover). Only `main.js` and the preloads touch
Electron; what the app decides lives in `lib/`, plain Node, tested in `test/desktop.test.js`, `test/desktop-tray.test.js`,
`test/desktop-machines.test.js`, `test/desktop-rail.test.js` and `test/desktop-add.test.js`, the card's page in `test/tray-card.test.js`, the machine chip in `test/machine-chip.test.js`;
`scripts/desktop-drive.mjs` (`npm run test:desktop`) drives the whole app on throwaway folders and ports. Nothing under
`src/` imports it; it imports from `src/` the config's folder and port readers (`config.js`), the secrets
(`services/config/secrets.js`), `ELECTRON_VAR`, `ART_DOMAIN`, the browser's page size (`core/browser.js`) and the
harness's Now fold (`ui/harness/lib/now.js`, `agents-since.js`). The server it runs is `bin/filament.js`.

The build: `electron-builder.yml` (`npm run dist:win`, `dist:mac`, `dist:linux`: `scripts/dist.mjs`, each refused on
another system) packs the checkout as it is — no `asar` archive, as Filament starts files of its own folder (the memory
engine's Python) and reads its docs there — into `dist/<windows|mac|linux>/<version>/`: a per-user NSIS installer
(unsigned), a Mac `.dmg` and the `.zip` updates fetch (Developer ID-signed and notarized where the Mac holds the
certificate and key), a Linux AppImage and `.deb`; publishing nothing. Each carries its system's memory engine bundle,
checked whole before and after by `scripts/check-memory-bundle.mjs`; on a Mac `scripts/build-memory-bundle.mjs` signs
the bundle's programs before it writes their hashes. `scripts/pty-helper.mjs` makes node-pty's Mac `spawn-helper`
runnable — its package carries it without the execute bits, and every Mac terminal starts through it — after each
install (`postinstall`) and before each build. `.github/workflows/build.yml` builds all three and drafts a tag's
release in the public releases repository the apps update from; `docs/releasing.md` is the guide. `build/installer.nsh` is the installer's and
the uninstaller's check for a running app: `Filament.exe --quit` first, then up to a minute's wait, then
electron-builder's own box. `npm run test:desktop -- --built [exe]` drives that build.

## `desktop/`

| File | What it is |
| ---- | ---------- |
| `desktop/card-preload.cjs` | The tray card's preload, given to the card's window alone: exposes `filamentDesktop` with `act(id, route)` (`filament:card-act`: open the harness, the dashboard or a chat, Restart, hide the card), `onState(fn)` (the app's state on `filament:card-state`) and `look({ light })` (the theme of the page the app draws while Filament gives none). The app hears an act only from Filament's own page (`lib/card.js` `cardHears`). CommonJS, as a sandboxed preload is no module. |
| `desktop/dashboard-preload.cjs` | The console's preload, the dashboard window's and the console's the harness opens: `filamentApp.pressKey` alone, answered for Filament's console page alone (`consolePage`), so the console's writes carry the press key. CommonJS. |
| `desktop/harness-preload.cjs` | The harness window's preload (and a popped pane's): `filamentBrowser` (`place`, `park`, `onHand`, `handOff`: the chat's page over the pane), `filamentApp` (`notify`, `titleBar`, `addMachine`, `agentMachines`, `agentsOn`, `agentsModels`, `agentsForget`, `browserOn`, `frameArea`, `update`, `updateAct`, `onUpdate`, `checkUpdates`), `filamentMachines` (`open`, `onState`: the machine chip), `filamentPanes` (`popOut`, `bringBack`, `popped`, `onPopped`). Heard from Filament's own page alone. CommonJS. |
| `desktop/lib/add-machine.js` | Adding a machine to the window (Part 3 of 11-06): `addressOf` (no scheme: https for another machine, http for this one), `checkMachine` (who answers before anything is sent: plain http to another machine refused, a link's fingerprint pinned, an authority's certificate taken, the network listener's said to compare; `ssh://` through its tunnel (`ssh`), no code; then `/.well-known/filament`), `deviceNameHere`, `claimScript` (the claim from the machine's own page, `CLAIM_FROM`), `claimOutcome`. |
| `desktop/lib/browser-host.js` | The agent's browser, the app's half: `createPages` holds each chat's tab (a WebContentsView in `PARTITION`), parked at `PARK_SIZE`, placed over the Browser pane (`handle`, `place`, `closeAll`; `scaleIn`, `drawnIn`); only `CDP_METHODS` reach a page; `cast` sends a tab's frames (`CAST_MS`, else pictures `CAST_SHOT_MS`). `createLink` links to `LINK_PATH` (`inboundKeyOf`); `mayGo` refuses non-web pages; the veil (`VEIL_PAGE`, `HAND_MS`) hands a page over; `paneHears`, `consolePage`. No Electron. |
| `desktop/lib/build-info.js` | What a build of the desktop app is: `buildFacts({ root })` (version, git commit and subject, whether uncommitted changes went in, `builtAt`), `withBuildFile(root, build, run)` (writes `BUILD_FILE`, `desktop/build-info.json`, for electron-builder to pack and removes it after; `scripts/dist-win.mjs`), `readBuild()` (the app's own; none in a checkout), `asBuild`, `buildWords`, and `appVersion(root)` (Filament's version from package.json, not Electron's). Plain Node. |
| `desktop/lib/card.js` | The tray's card (HarnessV3-Native NA3b): `CARD_SIZE`, `cardPlace(tray, workArea)` (over, under or beside the tray icon inside the work area), `CARD_ACTS` and `cardHears(act, frameUrl, origin, route)` (acts heard only from Filament's page; `open` only with a harness chat route, `harnessRoute`), and the page the app draws while Filament gives none: `downWords`, `downPage` (a `data:` page, words escaped, no script), `esc`, `markTile`. The card is `/ui/tray-card.html`; main.js opens it. |
| `desktop/lib/frame.js` | The window's frame: `frameOf({ platform, dark, pane })` gives, on Windows, `titleBarStyle: "hidden"` with Windows' controls drawn over the page's top row (`BAR_H` 48, a popped pane's `PANE_BAR_H` 38) in the chrome's colours, and the system frame elsewhere; `overlayColors(c)` reads the colours a page sends (`filamentApp.titleBar`) as two `#rrggbb` or null. |
| `desktop/lib/log.js` | The desktop app's server log: `createLog(file)` returns `{ write, line }` over `<dataDir>\desktop\server.log`, Filament's output with the app's own `[desktop]` lines, the older half moved to `server.log.1` past `LOG_MAX_BYTES`; a failed write never stops the app. `serverTail(file)` gives Filament's last lines for a dialog. Plain Node. |
| `desktop/lib/metrics.js` | The app's memory log (the owner's of 11-17): `createMemorySampler({ metrics, windows, write })` reads `app.getAppMetrics()` each minute and writes a JSON line every `LINE_EVERY` readings to `memory.log` — each process's MB and its most since the last line, windows named, the server's last census with its age (stale past `CENSUS_STALE_MS`). `serverStarted(pid)`, `heard(census)`, `serverEnded(code)` (a line at once), `lastOf(pid)`. Plain Node. |
| `desktop/lib/logon.js` | Start at logon (HarnessV3-Native NA-D10): `logonItem({ exe, packaged, main, dataDir, port })` builds the login item that starts the app `--hidden`, the installed app or Electron over a checkout's main script, with its data folder and port; `appIdOf` (`com.filamentdev.desktop`, `.dev` for a checkout), and `oldAppIdOf` with `oldLogonEntry`: the old id's login item, moved to the new one once. main.js reads and writes. Plain Node. |
| `desktop/lib/machine-agents.js` | This Filament's agents on the window's other machines (Settings' Remote access): `createMachineAgents(…)` → `list`, `set(id, on)`, `models(id, on)`, `full(id, on)`, `forget(id)`, each an `AgentsRow` (`away`: off here, or quiet); `names`, `projects`: the new-chat menu's, none on a share. As the window's sign-in, pinned: `/remote/me`, `/remote/devices`, the mint (token sealed by `keep`), the grants; the kept row follows the window's way (`follow`). Its changes in turn; no token reaches the page. |
| `desktop/lib/machine-browser.js` | A machine's chats' browser here: `createMachineBrowsers({ machines, cookieOf, keep, pagesFor, changed })` → `sync`, `set(id, on)`, `rowOf` (`browserLink`: off, connecting, connected, refused), `pagesOf`, `all`, `destroy` — a link per machine switched on, to its `/api/browser/host`, pinned; again after `MACHINE_RETRY_MS`; 401 or 403 stops it; each move said to `changed`. Up, it holds a proxy. `partitionFor`, `machineGuards`, `placeOnMachine`. |
| `desktop/lib/pinned-socket.js` | A WebSocket's client end in main, to another machine's Filament: `dialSocket({ url, headers, pin, onOpen, onMessage, onBinary, onClose })` over wss alone — the certificate pinned where the route pins one, else checked as any site's; nothing sent to another —, masked frames (`clientFrame`), pings answered, a refusal's status and words heard, gone after `QUIET_MS` of silence or `DIAL_MS` to open. Plain Node. |
| `desktop/lib/tunnel.js` | Another machine's localhost in this app (b-tunnel): `createProxy({ name, send })` → `start` (127.0.0.1, a port of its own), `take`, `stop`, `auth` — CONNECT and plain http requests, each a stream over the machine's link to its loopback; a host no loopback's refused; a caller without the proxy's own secret (Basic, `PROXY_USER`) answered 407. `proxyConfig`: `fixed_servers`, `PROXY_BYPASS` (`*;<-loopback>`) — Chromium asks a PAC script nothing for loopback. Plain Node. |
| `desktop/lib/machines.js` | The window's machines, in `<dataDir>\desktop\machines.json`: `readMachines(file, origin)`, This computer first, never kept, then `{ id, name, routes, partition }` (`partitionOf`: `persist:machine-<id>`, `.<n>` for a new certificate); `addMachine`, `renameMachine`, `removeMachine`, `setMachineOff` (disconnected), `setMachineBrowser`; routes `url`, `lan` (`pinsFor`), `ssh` (a tunnel), others kept; `pickRoute` holds an SSH tunnel, asks /.well-known/filament the id; `machineWatch`; `slotOfInput`. |
| `desktop/lib/tailnet-peers.js` | The Add sheet's tailnet (Part 2 of 11-06): `tailnetFilaments` — `tailscale status --json`, then each online machine's `https://<name>/.well-known/filament`, yours first, all at once, `PEER_MS` each, read to `PEER_BYTES` (`cappedJson`), the first `PEERS_MAX`; those answering with an id listed by Tailscale's host name and owner, never their own word, else why none; no Tailscale, nothing said. `askPeer`, its seam. |
| `desktop/lib/ssh-route.js` | A machine reached by SSH (Part 2 of 11-06): `sshAsked` (`ssh://<alias>[:port]`), `aliasOf` ([user@]host, never an option), `sshArgs` (`ssh -N -T`, batch mode, no ControlMaster, `-L 127.0.0.1:<local>:127.0.0.1:<port> -- <alias>`), `sshWords`; `createTunnels` → `hold` (started, again once dropped; one start for two asks; failures back off, `fresh` past it; none left behind a close; an earlier run's ssh at its port ended: `staleOf`), `routeFor` (`LOCAL_PORTS`, never a kept port), `only`, `close`. |
| `desktop/lib/rail.js` | The machines of one window, a top-bar switcher: `switchLayout` (where each view stands), `lentFrame` (the controls' room lent to a machine's page), `railRows`, `railState` (the popover's rows), `pageState` (a chip's state), `remotePrefs`, `certVerdict`, `unreachablePage`, `harnessAt`, `createRail`: views, undrag, Ctrl+1..9, looks (a name as it answers), `openPop`/`pick`/`closePop`, `hearsPage`, `frameArea`, `tintFrom`, `add`, `tailnet`, `openOn` (`#/new/<folder>`), Disconnect, Remove. |
| `desktop/lib/renderer-watch.js` | A tracked window's page process, watched (the owner's of 11-17): `watchRenderer` logs `render-process-gone` (window, reason, exit code, pid, what it showed, memory last seen), not when quitting, clean or destroyed; `unresponsive` said, never acted on. `crashPlan` → main's `recoverPage`: the harness again (`?crashed=`), without its chat (`away=`) after a memory death or its 2nd crash in 30 min; at the 3rd in 10 min no more (`stoppedWords`). `pid()` for the sampler. |
| `desktop/lib/notes.js` | What the app says in system notifications: `alertNote(list, seen, since, quiet, now)` (each alert once by id, only those raised since the app started, several as one, memory's never, a failover once in `FAILOVER_QUIET_MS`), `needsNote(rows)` (chats that need you by title and project, never a question's words), `endedNote`, `restartingNote`, `backNote`, `spaceNote(news)` (Your Space's new rows counted by project), `balloonOf(note, logo)` and `noteLine`. main.js shows them. |
| `desktop/lib/policy.js` | What windows may show and how the server starts: `routeOf(url, origin)` keeps Filament's origin, sends other http(s) to the browser, `EDITOR_LINKS` to the editor, refuses the rest; `askedByPerson` and `isPress` (an outside open only within `ACTIVATION_MS` of a press); `mayGrant` (`OWN_GRANTS`; `ARTIFACT_GRANTS`, here or on another machine's network address); `serverEnv` (the app's environment less `ELECTRON_*`, `FILAMENT_SUPERVISOR` set) and `serverArgs` (`--port` only when given). Plain Node. |
| `desktop/lib/pop-out.js` | Pop out (HarnessV4_BrowserSize_Plan BS4), a harness pane in a window of its own: `POP_SIZE`, `POP_TAB_MAX`, `popTab(v)` (a tab id as the page sends it, or null), `popPlaceName(tab)` (a tool pane's own saved place, `pop:browser`; every file, artifact and thread under one, `pop:item`), `popRoute(route)` (a chat route alone) and `popUrl(origin, tab, route)` (the harness page with `?pane=`). Plain Node. |
| `desktop/lib/settings.js` | The desktop app's own choices in `<dataDir>\desktop\settings.json`: `SETTINGS` (the defaults: `notify`, `updates`), `readSettings(file)` and `keepSettings(file, patch)`. Filament's config is not the app's to write. Plain Node. |
| `desktop/lib/start.js` | What the app finds where Filament should listen (HarnessV3-Native NA-D7): `portOf(dataDir, given)` (`--port`, else the folder config's `server.port`, else the default), `followPort` and `hostOf` (re-read before each restart; a wildcard host is `127.0.0.1`); `foundAt(port, { host, dataDir })` says `start`, `attach` (a Filament of this data folder, `sameFolder`) or `refuse` with why; `refusedWords`; `TAKE_OVER_MS` and `attachWatch` (an attached Filament silent 45 s is taken over). Plain Node. |
| `desktop/lib/supervisor.js` | The app's Filament server as a child process: `createSupervisor({ fork, answers, shutdown, onState, log })` returns `{ start, restart, stop, now }` over its states (starting, late at `LATE_MS`, up, restarting, stopping, stopped, taken, failed). One that ends after answering restarts no sooner than `RESTART_GAP_MS` after its last start, once the port is free; one that never answered is failed. Restart and Quit ask `POST /api/shutdown { ifIdle: true }`, ending the process at `END_WAIT_MS`. |
| `desktop/lib/tray.js` | The tray as data: `trayRows` (the menu, owned or attached: Show the card, the two windows, Restart where up, late, taken or failed, the update's row (`updateRows`: Update, its download's share, Restart to update, a store's or a release's page), Start at logon, Notifications and Check for updates as checks, Quit) and `trayTip` (the tooltip: an attached Filament that does not answer, how many chats need you). main.js makes Electron's menu of it. Plain Node. |
| `desktop/lib/updates.js` | Updates from the releases repository (`releasesRepoOf` reads `app-update.yml`, else `repoOf`): `kindOf` (nsis, mac, appimage, deb, store, page), `ASSETS` (each kind's file and `latest*.yml`), `STORE_PAGES`, `lookForUpdate`, `isNewer`, `shaIn`, `fetchInstaller` (services/updates.js's), `installArgs`, `createUpdater` (a look `FIRST_LOOK_MS` in, every `LOOK_EVERY_MS`, `look(true)` at Check now → what it found; `fetch` on a press; none → available → downloading → ready or failed). Plain Node. |
| `desktop/lib/install-update.js` | How a fetched update installs, by kind: `readySquirrel` (a Mac's zip handed to Squirrel.Mac from a 127.0.0.1 server of its own behind a random token, `SQUIRREL_MS`), `replaceAppImage` (copied beside, made runnable, renamed into place), `installDeb` (pkexec runs `DEB_INSTALL`: a copy of root's own, its SHA-512 checked again, installed by apt), `relaunchOf`. Windows' runs from main.js. Plain Node. |
| `desktop/lib/shell-path.js` | The login shell's PATH for an app the Finder or a launcher started, which gets launchd's minimal one: `readShellPath` asks `$SHELL -ilc` between marks (`SHELL_PATH_MS`, never on Windows), `mergedPath` puts its folders first; main.js reads it while Electron gets ready and sets it before the server starts, so npm, git and the agents are found. Plain Node. |
| `desktop/lib/icons.js` | `iconsOf(root, platform)`: the tray's and the windows' icons per system — Windows' `.ico`, a Mac's template image for the menu bar (drawn in the bar's colour), Linux's PNGs (`tray/filament-*.png`). |
| `desktop/lib/waiting.js` | The window the app shows while its Filament gives no page yet: `underWay(state)` (starting, late, restarting, stopping), `waitWords(state, port)` and `waitPage(words, { dark, busy, bar, version })` (a `data:` page in the window's colours with Filament's mark, the words, a spinner while on its way, a draggable top row as tall as the title bar and the version; words escaped, no script). Filament's page replaces it at its first answer. Plain Node; main.js loads it. |
| `desktop/lib/watch.js` | The harness watched from the tray (NA3b): `createWatch({ call, now, outageMs })` → `{ look }`, reading runs, events, chats and threads into the left bar's rows — `needs`, `works`, `needsNew`, `ended`, Your Space's new rows; null while Filament does not answer; what came while unseen past `OUTAGE_MS` learned, not told. `createFleet`: each machine kept but one disconnected, where it answers as itself, its partition's sign-in; a tick waits `FLEET_WAIT_MS` at most. `markUnread` alone sends. |
| `desktop/lib/window-state.js` | Where each window stood, kept in `<dataDir>\desktop\windows.json`: `placeOf(saved, screens, size)` (the saved place only while enough of it stays on a screen, else the usual size on the main screen), `readPlaces` and `keepPlace` (written whole through a temporary file). Plain Node. |
| `desktop/main.js` | The Filament desktop app, the only file that speaks to Electron (`npm run desktop -- [--data-dir] [--port] [--hidden]`): Electron's profile under `<dataDir>\desktop`, one app per data folder, the port (`lib/start.js`), its server started and watched (`lib/supervisor.js`) or attached, the sandboxed windows, tray, card, notifications, logon start, browser host, the window's machines (`lib/rail.js`), their SSH tunnels (`lib/ssh-route.js`) and this Filament's agents there (`lib/machine-agents.js`). |
| `desktop/rail-page.js` | The app's page's script, a classic one (a file:// page's module is refused): `drawRail(doc, state)` draws the popover under the chip (`popPlace`, kept inside the window), the keys on the machine showing; `hearRail(doc, bridge)` hears a pick, a ⋯ or right-click menu, Add a machine, Escape or a press outside, the arrows; `addFlow`, `paintSheet`, `hearSheet` run the Add sheet's steps; `drawPeers`, `peerLook`, `peerPick` its tailnet's Filaments. Exported for its test. |
| `desktop/rail-preload.cjs` | The app's page's preload, given to that page's own view alone: `filamentRail` with `select(id)` (a machine picked: `filament:rail-select`, the popover closed), `close()`, `onState(fn)` (`filament:rail-state`, asked by `filament:rail-ready`), `menu(id)`, `openAdd`, `closeAdd`, `add(input)` (`filament:rail-add`, a check or a pairing) and `tailnet()` (`filament:rail-tailnet`). The app hears it only from `rail.html` in that view (`createRail`'s `hears`); no machine's page has it. CommonJS. |
| `desktop/machine-preload.cjs` | Another machine's view's one bridge (11-08): `filamentMachines` with `open(rect)` (`filament:machines-open`, the popover under its chip), `onState(fn)` (`filament:machines`, asked by `filament:machines-ready`: its chip's state and the room lent it) and `titleBar(c)` (`filament:machines-title-bar`, the controls' colours while it shows); `filamentBrowser`, as the harness window's. | `desktop/rail.html` | The app's own page over the harness window (file://, a CSP of its own: no script but `rail-page.js`), see-through but for what shows on it: the machines popover under the chip pressed — each machine's dot, why where it is not connected, its count, a tick on the one showing, its key, another's ⋯ — and Add a machine; and the Add sheet over the whole window (the tailnet's Filaments, the link, address or `ssh://`, the code, the fingerprint, who answers). |
| `desktop/veil-preload.cjs` | The veil's preload (HarnessV4_BrowserSize_Plan BS3): the see-through page the app lays over an agent's browser page while it drives (`lib/browser-host.js` `VEIL_PAGE`) exposes `filamentVeil.take()`, which sends `filament:veil-take` when Take over is pressed; the app hears it only from a veil of its own (`veilPressed`). CommonJS. |
