# Module map: ui/harness

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `ui/harness/`

| File | What it is |
| ---- | ---------- |
| `ui/harness/app.js` | The harness application: the shell's frames filled with the three regions, the hash router (`#/` a new task, `#/task/<chainId>` a session, `/plan`, `/team` or `/side` its view; Settings, the control room and the Artifacts screens over the chat), and the turn's conductor — send (a message, a resume, or a steer into a live run's mailbox), the stream into the transcript, the run's events onto the same turn, the footer from the record, stop, fork, open. A chat views the server's native session. |
| `ui/harness/aqua.css` | The Aqua pass (HarnessV3 §15 item 92): the harness in the Instruments' macOS language — `--aq-*` tokens in both themes, app-icon tiles (`--tone`), the glass composer, capsule controls, the circular send and stop with the running ring, the model picker (`mp-*`), the tuning popover (`tp-*`), glass menus with tiles and keycaps, the Spotlight slash panel, attachment cards and the queue. `harness.html` loads it last. |
| `ui/harness/artifact-acts.js` | What the developer does to an artifact (HarnessV4_Artifacts_Plan E18 step 4), from the Artifacts page's ⋮ and its full view in the same words: `setPinned`, `renameArtifact` (a dialog), `deleteArtifact` (asked first), `makeNewest`, `downloadArtifact` (the version's file under the server's name), `copyLink`, `showInfo` (where it lives, its times, each version with its maker and size, what a Dashboard reads) and `artifactItems` (the ⋮ menu). A refusal is said in the server's words. |
| `ui/harness/artifact-edit.js` | A Doc's or a deck's text edited in its full view (E18 step 6): `artifactEditor(name, { draft, onLeave, onChange })` — its Markdown (`GET /api/artifacts/:name/text`) beside its page, which shows each change as typed (a deck at the caret's slide); Save or Ctrl+S keeps it as the next version (`POST /api/artifacts/:name/versions`), Cancel asks first where something changed, and a version that came meanwhile is said at once with Save anyway and Discard mine. Typing outlives the view (`hasDraft`). |
| `ui/harness/artifact-frame.js` | An artifact's page in a frame (E18 step 2), for the side pane's tab and the full view: `artifactFrame(name, { title, onTell })` on its own address, never the harness's origin, in the harness's theme and Motion; a line under it for what failed in it, with Tell the agent, or for a frame that left its page, with Back. A new version shows as published, an old one when asked; its page's ask is heard only right after a click in it. `artifactPreview` is a still preview that asks nothing. |
| `ui/harness/artifact-view.js` | An artifact's full view (E18 step 2), `renderArtifactView(host, name, o)` at `#/artifacts/:name` over the conversation's frame: a head with its mark, title, newest version, when it came, the chat and the model that made it, what its page keeps and what a Dashboard reads; Versions (Make this the newest), Pin, Open in browser, Download, ⋮, Ask for a change (into the box of the chat that made it), and Edit for a Doc or a deck (`artifact-edit.js`). Back returns to where it opened from. |
| `ui/harness/artifacts-live.js` | The artifacts as this page knows them (E18 step 2): `artifactRecord(name)` (`GET /api/artifacts/:name`, read once and again after a new version; a failed read is not kept), `followRecord(el, name, ok, failed)` (an element painted again after each change while it is on the page) and `onPublished(fn)` (each version, rename, pin, delete and data change the events stream says). Cards, frames, the full view and the Artifacts page follow it. |
| `ui/harness/artifacts-page.js` | The Artifacts page at `#/artifacts` (E18 step 4), a full-frame screen like Settings: `renderArtifactsPage(host, o)` — All or Pinned, a search over titles and descriptions, a grid of still previews loaded as they near the screen or a list, the filter (type, project, model), by month, the last opened or changed first, each one's ⋮ from `artifact-acts.js`; `TILES` start a task that makes one of a type. It draws in place (`morphChildren`), so a card under a resting pointer stays the same element. |
| `ui/harness/bar-flight.js` | The left bar's moves: `notePlaces(root)` notes where each marked part stands (`data-flip`) before a draw, and `playMoves` after it slides every part that moved (FLIP) and carries a chat that changed place between Now and its project over the bar — a lifted copy set down where it lands, a place scrolled out of view met at its list's edge. `motion` reads the Motion setting (Reduced: a short fade; Off: nothing); `barHold` holds the moves while the pointer is on the bar or a menu it opened. |
| `ui/harness/command-center.js` | The command center (Ctrl+K, the sidebar's Search): `createCommandCenter` — quick actions with their shortcuts (`comboKeys`, `actionsFor`), recent chats (full-text search), each other machine's (the desk's `search`), the task's recent changes and project files, under the scopes All · Actions · Settings · Chats · Files (`nextScope`); a setting typed ("ask", "1m", "mem off") is a row that changes it for this chat (`lib/setting-intents.js`, `settingsPart`). `searchHistory` keeps eight queries. |
| `ui/harness/context-callbacks.js` | `createInspectorCallbacks`: the settings document's write path shared by every harness surface that edits it (the setup sheets, the Next request pane) — one PATCH at a time, a toast for every answer and a reload after. |
| `ui/harness/control-room.js` | The maximised control room, `renderControlRoom` at `#/control-room/:runId`: the sidebar and side pane hide and the run fills the screen — a line saying where it stands (the live round and its newest thought), its spine (the rounds, the metrics, the replay scrubber once it ended) and the chat input as the mailbox that steers it; a run whose log the server has dropped says so (`RUN_GONE`). Esc returns to the conversation. |
| `ui/harness/desk-inbox.js` | The desk's inbox (the remote desk of 11-22): `createDeskInbox({ bridge, onChange })` reads the asks of each other machine's chat in Now's Needs you through the app (`filamentMachines.call` op `asks`), each read as that machine's words (`readAsks`), `READS_MOST` at once, again on its `ask`, `turn` and `hello` frames; `cardsOf` draws a row's cards — question, command, a button per answer, words, Open; a plan, form, secret, edit or long command Open alone (`apart`) —, answered there (`answer`). |
| `ui/harness/desk-work.js` | Bring back (the remote desk's s2d): `createDeskWork({ api, toast, dialog, onChange })` keeps GET /api/remote-work's records (`readWorks`); `sync(desk)` looks at a Run on chat whose turn ended there since (`dueLooks`: not at work nor waiting for you; POST …/check with `seen`; one refused a moment asked again, `mends`); `cardsOf` (under its row in Now) and `pill` (under its project) say what waits (`waitWords`); `bringBack` asks what comes, a choice per overlap, and POSTs …/back (`cameWords`). |
| `ui/harness/find.js` | Find in task (AgentPlanUX §5.11; Ctrl+F): `createFind` — a small bar under the header's right end (the status capsule steps down while it is open); matches marked with `N of M`, Previous and Next, a match in a closed fold opened and scrolled to, Esc closes and clears; the scope toggle searches the messages or the file changes (the Edit/Write cards and the Changes group). |
| `ui/harness/header.js` | The frame's header (proposal_ux §3.3, §4.2), `createHeader`: on the left the crumb — the folder chip (its leaf, a worktree's mark, a hover card; typing there sets a new chat's folder) › the chat's title, whose press opens the chat menu (pin, rename, archive, copy, reload, move to a worktree, fork); the view tabs in the middle; on the right a running flow's line, the pane and Layout buttons, Open in and Help. It makes the place chip and `+N −N`, which the app mounts under the box. |
| `ui/harness/how-sheet.js` | How earlier turns are kept (proposal_ux §4.12): `openHowSheet`, the one sheet for how a chat makes room (`HOW_TITLE`), opened from the context ring's popover and the Context pane. Its level control (`howLevels`) picks whose settings it shows: This chat (`panes/context-how.js`'s section) or All new chats (your defaults); each level writes through its own writer. `repaintContextHow` draws the chat's section again when the session moves. |
| `ui/harness/install-sheet.js` | The install sheet (HarnessV3-ACP AC3-8): `openInstall(id, { agents, accounts, signIn, onToast }, io)` — a coding agent installed from Settings → Coding agents, in the sign-in sheet's shape (`lib/task-sheet.js`): the command shown whole, run on Install in a terminal on the sheet (`lib/xterm.js`), Cancel install stopping it, closing the sheet leaving it running; with no terminal, the line to run oneself, then Connect. A good install shows its models and who it runs as, and offers Sign in. |
| `ui/harness/live-topic.js` | `settingsFollower({ held, read })`: the settings document of the chat a page shows, read again when the events feed says it moved (`settings`, with the new hash) — never for a hash the page holds already, one read at a time, a burst folding into one more read (BUG-10 P9). DOM-free; `app.js` wires it. |
| `ui/harness/move-sheet.js` | Move a chat to a worktree (HarnessV4_Git_Plan §12): `moveSheet({ chat, title, onMoving, onMoved, onToast, hear })` reads `GET /api/sessions/:id/move` as it opens and as the name or place changes — where to (a new worktree or another of the repository's places), each file that goes with its counts, each that stays with why, everyone else's files, what git ignores, what still runs in the old folder — then Move, which the server checks again. `moveWords`; the copy line is `worktree-copy.js`'s. |
| `ui/harness/notify.js` | The tab title and the run-end notification: `setTabTitle`/`setTitleLead` (the task's name, `● ` while a run is live) and `notifyRunEnded` (a browser notification when a run ends in a hidden tab, gated by General's switch for how it ended, `NOTIFY_PREF`, `notifies`); `ensureNotificationPermission` asks only while a switch is on. In the desktop app's window (`inDesktopApp`) it tells nothing, since the app tells of every chat itself. |
| `ui/harness/now-list.js` | Now in the left bar (proposal_ux §4.1): `createNow` — Needs you, Working and Done across every project, its rows `lib/now.js`'s, read beside the runs list the sidebar polls: each followed turn's newest events and the threads of chats whose agents run, while the page is in view, where a run moved; the other machines' rows among them (`more`) with chips, in the bar their asks (`askCards`). A row opens the chat, thread or card that asks; it places each chat here or in its project. `chipTone`. |
| `ui/harness/prefs.js` | Browser preferences (AgentPlanUX §5.10), what belongs to the browser rather than the server — theme, font sizes, code presentation, notification switches, shortcut overrides: `prefs.get`/`set`/`onChange` (returning the unsubscribe) over `PREF_DEFAULTS`, in the shared store under `filament.harness.*`; a stored value is coerced to its default's type, and anything missing or unreadable falls back to the default. |
| `ui/harness/session-start.js` | The session-start choice (HarnessV3 Step 2 D15), what a new chat holds until its first send — the Start board's held changes over your defaults and the permission picker's standing: `sessionStartBody` builds the exact `POST /api/sessions` body `ensureSession` sends (the held patch, `loop.permissions` only for a mode picked, the held tuning); `chipStanding` (what an unborn chat's mode switch shows), `worksInPart`. Pure. |
| `ui/harness/setup-sheet.js` | The setup sheets (proposal_ux §4.6): `openSetupSheet` over `SETUP_SHEETS` — what Overview's How it is set up widgets change, each on a sheet of its own, drawn with the shared editor (`sectionCard`) over the session's own document, read as it opens and after every write. Who runs this chat opens on the teams to hand the chat to (`widgets/hand.js`); What it may do draws the chat's MCP servers (`lib/mcp-list.js`). `OLD_TABS` opens the sheet standing for each `#/context/<tab>` address. |
| `ui/harness/shell.js` | The window (proposal_ux §3.1), `createShell`: the sidebar, then one frame — the header over the chat and the panes. Its width is dragged (264 min, half the window max, kept); Ctrl+B or Hide folds it to a 48px rail; shown, its top bar holds the chat's crumb (`header.crumbIn`); folded below 360 px; past `WIDE_SIDE` or in a `WIDE_WINDOW` window it is `.wide`. Panes: `panes/pane-host.js`'s; `contentCol`, `setGuest`. `chatOnly`: no sidebar nor rail, nothing kept; `onFullPage`: Open full page. |
| `ui/harness/shortcuts.js` | The shortcut registry and matcher (AgentPlanUX §5.12): `SHORTCUTS` plus per-command overrides in the `shortcuts` pref; `matchShortcut`/`comboFromEvent` (exact modifiers, no key repeat, never mid-IME, a digit read by its key so a Mac's Option+2 is Alt+2), `list`, `comboOf`, `rebind`, `reset`, `conflicts`, `isReserved` (browser-reserved combos refused) and `comboLabel` (Ctrl+K, ⌘K on a Mac). Alt+1 to Alt+4 bring the session's views; the Composer rows are display-only (`composerKeys`). |
| `ui/harness/sidebar.js` | The left bar (proposal_ux §3.2, §4.1), `createSidebar`: the top bar, New chat and Search, Your Space, then one scroll region — Now (`now-list.js`), Pinned, and Projects (by project, by time, or by machine) — and the Library at the foot. A chat stands in one place: in Now while it has a row there, else under Pinned or its project (`bar-flight.js`). In the app, every machine's chats (lib/desk.js), opened in place (`cb.openThere`, `showingThere`). `appRowsOf`. |
| `ui/harness/sign-in.js` | The sign-in sheet (AC3-7): `openSignIn(upstream, { keeper, onToast, then }, io)` — a coding agent's account signs in its agent's way, from Settings → Coding agents, Account or a turn its login refused: its ways named where it has several; a terminal sign-in in a terminal on the sheet (`lib/xterm.js`), a page sign-in's wait with the page, the code and Cancel (from another computer a device code first, `fromAnotherComputer`); no terminal, the line to run. How it ended is the account's row. |
| `ui/harness/state.js` | The harness's client-side state: `state` (the open chats, the current one, the sessions list, the models), `chatOf`/`putChat`, `atWork`, `newChatId`; the chat's session view (`applySessionView`, the one updater, and `onSessionView`); drafts and their files in sessionStorage (`draftFor`, `saveDraft`, `draftFilesFor`, `startKept`); and the few localStorage preferences: recent folders, a new chat's model (`startModel`), the sidebar's and pane's widths. Nothing sensitive reaches localStorage. |
| `ui/harness/subagent-viewer.js` | An agent's conversation: `subagentConversation` — its head (words, card, model, the context handed to it, state, time, Stop, Open on its machine), each exchange (the opening context, the task or follow-up whole, its run — another machine's: its run here — live: thinking, words and calls as they stream, how it ended), a follow-up box once idle, and a worktree agent's changes with Apply. Mounted by `panes/thread.js` and `views/side.js`; `guestConversation` draws a coding agent's own agent. |
| `ui/harness/theme.js` | The browser-only look, through `prefs.js`: `themePref`/`setThemePref` (Zai Dark, Zai Light, System, the default; `THEMES`), `uiFontSize`, `codeFontSize`, `motionPref` (Full, Reduced, Off; `MOTIONS`), `applyTheme` (the theme's class and font sizes on `<html>`), `hintTheme`/`themeHinted` (a look worn, not kept) and `watchTheme` (the system's scheme; Ctrl+Shift+L cycles the theme, Ctrl+= / Ctrl+- / Ctrl+0 the UI font size); `FONTS`, `MIN_FONT`, `MAX_FONT`, `clampFontSize`. |
| `ui/harness/view-settings.js` | The settings document's fields the session view keeps (Step 6 §2.2): `viewSettingsOf(doc)` — the settings, the window doc, the spend ledger (`usage`), the price card (`price`), the derivations (`derived`) and the rules in force (`rulesInForce`) — and `settingsRead` (whether the view holds the document itself, not only a turn's mark of its hash). Pure and pinned by a test, since this seam is where figures go missing. |
| `ui/harness/waiting.js` | The harness queue (HarnessV3 Step 3 D14), DOM-free: a send that finds the chat held (moving to another folder, or a coding agent's turn of its own) stays with the chat and sends itself when that ends. `createWaitingQueue` (with Cancel and the stop route's hook), `queueText` (the waiting line, the holder named), `waitingToast`, `holderFromView`, `MOVE_WINDOW`, `waitingStore` (a waiting send kept over a reload) and `waitingOwes`. The app wires the row. |
| `ui/harness/worktree-copy.js` | A project's worktree template on the page (HarnessV4_Four_Plan E19): `createCopyLine({ folder, off, setOff, changed })` — the line under New worktree, at the start and on the Move sheet, saying what the new worktree gets a copy of (the project's `worktree.copy` from `/api/git/places/template`), each entry switchable for this worktree alone — and `copyPicker`, the sheet listing what git leaves out, measured, to choose the list from; `copyLineWords`, `candidateWords`, `isInside`, `listPath`. |
| `ui/harness/zc.css` | The harness's utility sheet (AgentPlanUX §3.7): a hand-typed Tailwind subset, only the classes the markup uses, its px values and tokens from the design reference. |
