# Module map: adapters

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `adapters/agents/`

| File | What it is |
| ---- | ---------- |
| `adapters/agents/agent-process.js` | A coding agent's process, whatever protocol it speaks: `RpcProcess` is the JSON-RPC peer over its stdin/stdout (requests with timeouts, handlers for the agent's requests, notifications, `withdraw`, `ending(what)`, a tree kill emitting `ended`), `jsonrpc` on for ACP, off for Codex. `resolveAgentCommand` (`npmShim`, `scriptNode`, `pathNode`) and `commandExists` find the command, elsewhere than Windows in `~/.local/bin` too (`unixDirs`); `agentEnv` (`AGENT_ENV_SCRUB`) builds its environment. |
| `adapters/agents/agy-feed.js` | Antigravity's agy CLI from Google's release feed, which ACP's registry follows late. `createAgyFeed` → `{ refresh, view, stale }` reads `AGY_FEED_URL` for this computer (`feedTarget`), checks it (`checkRelease`) and keeps it in `<dataDir>/agents/agy-feed.json`, stale after `AGY_FEED_STALE_MS`. `withAgyFeed(registry, feed)` lays it over the registry's `AGY_ID` entry: the feed's version and program (`agyProgram`, `AGY_ARGS`, `AGY_ENV`), none before a read. |
| `adapters/agents/agy-quota.js` | Antigravity's plan quota, which agy says nothing of over ACP, from Google's Code Assist service with the Google sign-in agy keeps. `agySignIn` reads it, never writes or renews it: an added account's file in its folder (`agyTokenFile`), the Default account's file or system keyring (`readKeyring`), whichever expires later. `readAgyQuota` asks both hosts under Filament's name with agy's version, its windows by `agyQuotaWindows`. `signInExpired`. |
| `adapters/agents/asks.js` | An agent's question in one shape (HarnessV3-ACP AC2-4), pure: each agent's own form read into one (questions, typed answers, a plan, a link, a permission, an always-only one) by `fromElicitation`, `fromCursorQuestion`, `fromCursorPlan`, `fromCodexQuestion`, `fromAgentPlan` and `fromJudged`, written back by `toElicitation`, `toCursorQuestion`, `toCursorPlan`, `toCodexQuestion` and `toPermission`. Also `checkAnswer`, `nobodyAnswer`, `answerWords`, `clientQuestions`, `answerFromText`. |
| `adapters/agents/chat-servers.js` | The MCP servers a coding agent's session opens with besides Filament's own (OV-D15): the upstream's `mcpServers` and the chat's `plugins.mcp` as one list, `serversFor(acp, chat, { title, http, cwd, fenced })` → `{ servers, words, key }` (a server's name and transport, never a value; none for another machine's agents' chat), then `acpServers`, `codexServers`, `cursorServers`. `chatKeyOf(chat)` hashes the list: a change opens the session again. |
| `adapters/agents/client-bridge.js` | The client-tool bridge, letting a chat client's own hands do the agent's work: `ClientToolset` recognises the tools a client such as Claude Code declares (Read, Write, Edit, Bash, AskUserQuestion, TodoWrite), builds the tool calls Filament emits for the agent (`ACTION_PREFIX`, `newActionId`, `isActionId`; `buildQuestions`, `askShown`, `parseAskAnswer` for questions) and reads the results back (`extractToolResults`, `newestUserText`). Pausing and resuming the turn is `turn-bridge.js`'s. |
| `adapters/agents/compactions.js` | An agent's session and the chat's compactions, one rule for the three bridges (HarnessV3-ACP AC5-1): a session stands on the chat's newest compaction when it started; a newer one starts a fresh session seeded from the harness's composition (`COMPACTED_WORDS`, `EARLIER_WORDS`), and an undo brings back the session kept `before`. `compactionOf`, `moveFor`, the house headers (`COMPACTION_HEADER`, `STANDS_ON_HEADER`, `LINE_HEADER`, `EARLIER_TRY_HEADER`, `SEEN_HEADER`) and their readers. |
| `adapters/agents/context.js` | What Filament gives a coding agent's session besides the person's words (HarnessV3-ACP AC4-1): the standing blocks (memory's briefing, goal, skills, task graph) through the agent's system channel, else ahead of the first prompt (`standingFor`, `standingText`, `openedWith`); later changes once ahead of the next prompt (`contextUpdate`, `said`), again after a compaction (`compacted`, `agentCompacted`); recall after the words (`withPromptBlocks`). `givenTools`, `isAgentCommand`, `givenRecord`. |
| `adapters/agents/cursor-sdk.js` | Cursor through its SDK (`@cursor/sdk`), behind Settings › Experimental: `findSdkDir`, `loadCursorSdk` (its entry, `sdkEntry`), `sdkStatus`, `installCursorSdk`; `CursorSdkBridge` runs one SDK agent per conversation, kept across turns and restarts. Its shell and file tools give way to Filament's under the full or native bridge and in a chat with a permission switch; stricter than Auto it keeps `CURSOR_KEPT` alone: no `task`, no MCP servers. `expandModelNames`, `selectSdkModel`, `describeSdkTool`. |
| `adapters/agents/destinations.js` | The agent bridges as destinations (`core/ports.js` `Destination`): `acpDestination(bridge, upstream)`, `codexDestination(bridge, upstream)` and `cursorDestination(bridge, upstream)`, each running the upstream's turns through its bridge, with its models and connection test coming from the agent itself. `server.js`'s `destinationFor` picks one per upstream. |
| `adapters/agents/idle.js` | The idle sweep's rule, shared by the three bridges (HarnessV4_Tasks C25): `idleStep(conv, now, inUse)` → `keep` (in use, or idle less than the upstream's `acp.sessionIdleMinutes`), `rest` (a harness chat: the agent lets go of the session and the record stays, so the next message opens it again as after a restart) or `drop` (an outside client's chat, or a harness chat unused for `CHAT_KEPT_MS`, 30 days). `idleDropOp(conv, now)` gives the ops line a dropped chat leaves. |
| `adapters/agents/installs.js` | The agents Filament installs (AC3-8), in `<dataDir>/agents/installed/<id>/<version>`: `createInstalls({ dir, platform, arch, fetch, maxBytes, log, now })` → `{ plan, download, settle, found, receipt, all, remove, dropOthers, sweep }`. `plan`: npm's, uv's, or a program's download, which `download` fetches over https, checks (SHA-512, SHA-256) and unpacks into `program` (`throughLink`, `PROGRAM_MAX_BYTES`); `settle` keeps the receipt; `sweep` deletes folders none names. `npmCommandName`. |
| `adapters/agents/left-running.js` | What a coding agent leaves running after its turn's Stop (HarnessV4_Tasks B13), as Cursor's CLI does: `startedSince({ agentPid, since })` reads the process table (`listProcesses`: PowerShell's `Win32_Process` or `ps`, within `LIST_WAIT_MS`) before the agent hears its cancel, `startedUnder` and `stillRunning` find what is left, and `leftRunning({ was, alone })` ends it (`endTree`) only where the stopped command ran alone. `leftRunningWords` says it for the turn. |
| `adapters/agents/registry.js` | ACP's registry of coding agents (HarnessV3-ACP AC3-8): `createRegistry({ dir, fetch, log, now })` → `{ refresh, view, stale, iconOf }`, read by the server from `REGISTRY_URL` on Refresh or when Settings › Coding agents opens on a copy older than `REGISTRY_STALE_MS`, at most `REGISTRY_MAX_BYTES`, https only. `checkRegistry` checks each entry and leaves out one that fails; icons are kept only from the registry's host and only as an SVG `safeSvg` passes. `platformTarget`, `isAgentId`, `fetchText`. |
| `adapters/agents/turn-bridge.js` | Shared machinery for the agent bridges (ACP, Cursor's SDK, Codex): `LiveTurn`, a turn outliving the reply that started it, its events buffered while none listens; `TurnBridge` with the wait, resume and interrupt cycle, `askPerson` (to the page, the client's question tool, or nobody) and `judged`/`permitCalls` (the session's switch over the loop's calls, an always-only offer asked). Also `choosePermission`, `alwaysOf`, `describeToolCall`, the policy readers, `mcpAddress`, `addressGiven`. |

## `adapters/agents/acp/`

| File | What it is |
| ---- | ---------- |
| `adapters/agents/acp/bridge.js` | The ACP bridge: drives an ACP agent (Claude Code, Cursor, Antigravity, Qoder CLI) as a chat model, Filament its editor. `AcpBridge` keeps one process per upstream and model, its own sub-agents off where it can (`./own-agents.js`), and one session per conversation; runs a turn (`run`: `session/prompt`, the update stream, permissions, the client's hands, MCP), reopens a lost session, summarizes and compacts, lists models and sessions, tests, signs in and out. Also `determineCwd`, `findSession`. |
| `adapters/agents/acp/configure.js` | `applySessionSettings` applies the requested mode, model and effort to an agent session in that order, with a note per request honoured, refused or not offered; models as complete ids or as Cursor's base model plus parameters. `MODE_ALIASES` maps common mode words onto the agent's own, `askingMode` swaps a mode that asks nobody for one that asks in a harness session, `offeredAuto` takes the agent's own `auto`; plan mode is kept until its plan is accepted. Each switch is said before it is asked. |
| `adapters/agents/acp/detect.js` | Which known agents this machine has and whether they are signed in, and as whom where they say: `detectAgents` (no registry agent), `detectAgentsWithStatus`, `loginStatus`, `readLogin`, `upstreamLogin`; `loginLaunch` and `startAgentLogin` open a console on an agent's sign-in. `catalogueInstalled`, `catalogueInstalledNow`, `programHere` and `catalogueVersion` say whether a catalogue agent or an upstream's program is on this computer; `detectedAgentSeed` is the config store's first-run seed. |
| `adapters/agents/acp/failures.js` | What kind of failure an agent's error is (HarnessV3-ACP AC0-3), so a refusal is not held against health: `classifyFailure(error)` → `{ kind, retryable, cools }` (`auth`, `limit`, `refusal`, `overflow`, `timeout`, `transport`) from its words, the adapter's `errorKind` and the JSON-RPC code. `agentCause(error, account)` reads busy, rate, out or account against the account's windows; `overflowSaid` gives the tokens an overflow names; `saysSignedOut`. |
| `adapters/agents/acp/key-models.js` | The models an Anthropic API key can use, for a Claude Code account on one: `keyAccess(upstream, identity)` finds the key where Claude Code reads it, by the source its adapter names (ANTHROPIC_API_KEY, or a Console sign-in's in the account's folder; a helper's or a token is not read), and the address it calls; `keyModels` asks the Models API there, every page, within `KEY_MODELS_MS`. The key goes in that request alone; a failure is said by status and type, and by the host asked (`keyListWords`). |
| `adapters/agents/acp/mcp-relay.js` | Filament's MCP server over stdio, for an agent that takes no MCP server over HTTP: run by it as `node mcp-relay.js` (the app's program as Node), Filament's address in its variable (`RELAY_ADDRESS_VAR`), never on its command line, it posts each JSON-RPC line there side by side, with no clock, writing back what comes (`relay`, `answersOf`); a call the agent cancels, or leaves open as it closes its end, has its connection closed, which stops it at Filament. Node's own modules alone. |
| `adapters/agents/acp/negotiate.js` | The pure part of model and mode negotiation: `readSessionOffer` (what a session offers: models, effort levels, other settings, modes), `resolveMode` (a requested mode through aliases), `planVariant`, `modelSelection` (a flat model name taken apart into Cursor's base model and parameter values), `matchOffered` (the offered id a person most plausibly meant), `typedName` (the typed name an id is, effort aside), and `modelLabels`, `listedModels` (an agent's own words for the models it lists). |
| `adapters/agents/acp/next-step.js` | Words at a coding agent's next step (HarnessV3-ACP AC3-1), for an agent that keeps the work of a turn it cancels (`cancelKeepsWork`, Cursor's CLI): `createNextStep({ cancel, running })` → `{ send, watch, take, end }`. Each send waits, in order, until no call runs; the turn is cancelled once and `take` hands them all to `nextStepPrompt`, which says whose each is (the person's, Filament's). A turn that ends first hands them back. |
| `adapters/agents/acp/open-end.js` | `createOpenEnd({ notes, who })` → `{ heard, answer }` (HarnessV4_Tasks B15): a prompt Claude's adapter failed with `incomplete_tool_call` over calls left unanswered (work left running behind its turn) is answered as ended where the turn's own thread last said a reply after its newest call, the adapter's complaint becoming the turn's note; a turn that ended on a call stays a failure. The bridge uses it for a turn's prompts and for words queued into the agent's own cycle. |
| `adapters/agents/acp/own-agents.js` | An agent's own sub-agent tool kept off where a turn hands it Filament's agent tool, for the agents whose switch is their process's (`ownOffAtStart`: Qoder's), in a process of its own: `ownAgentsOff(upstream)` → `{ held, args, env, words }`, Qoder's `--disallowed-tools` for each of `QODER_OWN_AGENTS` (`Agent`, `Workflow`). Cursor's CLI and Antigravity take no such switch. |
| `adapters/agents/acp/process.js` | `AcpProcess`: the JSON-RPC peer of `../agent-process.js` with ACP's handshake (`initialize` once, telling `CLIENT_INFO`) and the terminals an agent runs through Filament; a request the agent withdraws (`$/cancel_request`) is withdrawn from its handler; `authStatus` and `heardWho(ms)` say whom the agent runs as. `clientCapabilitiesFor` declares what Filament takes: sub-agent sessions, elicitation (form and URL), `auth.terminal`, `session.compaction` and `session.notices`. |
| `adapters/agents/acp/profile.js` | What a coding agent says it can do, read from its `initialize` answer (AC0-1): `readProfile(init, confirmed)` (name, version, prompt content, MCP transports, session methods, sub-agents, raw messages, steering, queueing, account, sign-ins, and `ways`: each declared method by kind — its own, a terminal's, a key from a variable — with the catalogue's `confirmedOf` facts), `authenticateMethod`, `takesHttpMcp`, `COMPACT_WINDOW_FROM`, `ProfileStore` (`acp-profiles.json`, `retain` on each save). |
| `adapters/agents/acp/prompt.js` | The prompt text one turn sends, for ACP agents and Cursor's SDK alike: `composePrompt` puts the newest user message with memory's recall after it, preceded where needed by the turns the session missed, the seed conversation (the harness's composition, or the archive or the client's history), the client's system prompt, what changed in Filament's context, and the steering instruction once (`steerPrompt`, `DEFAULT_STEERING_PROMPT`). Also `missedTurns`, `transcript`, `countTaken`. |
| `adapters/agents/acp/queued.js` | The person's words queued at the agent while its turn runs (HarnessV3-FailurePoints §7.2), for an agent that queues prompts and sends raw messages (Claude's adapter): `createQueued(prompt)` → `{ send, heard, carries, waiting, drained, letGo }`. Each is a plain `session/prompt` Claude folds into its running turn or runs next; `heard` reads the echo that says it took them, `carries` matches results to taken words, `drained` waits for every answer, `letGo` cancels what waits on failure. |
| `adapters/agents/acp/schema-pin.js` | `ACP_SCHEMA`: ACP's own schema, pinned (HarnessV3-ACP AC0-2): the SDK version, the update kinds with their required fields, and the unstable ones. Generated from the installed `@agentclientprotocol/sdk` by `npm run acp-schema` (`scripts/acp-schema.mjs`); never edited by hand. |
| `adapters/agents/acp/schema.js` | An agent's updates read against the pinned `ACP_SCHEMA` (HarnessV3-ACP AC0-2): `missingFields` (the required fields an update lacks), `undrawnNote` (a kind outside the schema, or in it and not drawn) and `missingNote`, each naming the schema's version; the update reader says each once per kind a turn. |
| `adapters/agents/acp/sessions.js` | One ACP bridge's conversation-to-session map and its persistence: `SessionMap` (by `conversationKey`) with `load`/`save` (a debounced state file, renamed into place, with each session's commands and the compaction it stands on), `absorbUpdate` (commands, mode, title, config options), `adoptTitles`, `sweep` (`../idle.js`'s `idleStep`). `resumedConversation`, `newConversation`; `givenAgain` (a session reopened from its record: Filament's own server, over HTTP or the relay, a new token). |
| `adapters/agents/acp/toolset.js` | What Filament offers an agent session, decided before it opens and noted after: `configuredMcpServers`, `planToolset` (the client-bridge mode in force, native or steering, the chat's servers, Filament's MCP server with its token — over HTTP, else through the relay, `relayServer`, `relayHere` — added folders, Claude's `_meta`, raw messages, thinking display) and `noteToolset` (what the session really got, on the record). Also `claudeCompactWindow`, `RELAY_SCRIPT`, `filamentsDoor`. |
| `adapters/agents/acp/updates.js` | The agent's side of a turn, read: `createUpdateReader` maps one turn's `session/update` stream to the events the application renders and the turn's totals (text, thoughts, tool calls with `diffLineCounts`, plans, usage, titles, sub-agents, Cursor's to-dos); `createTextReader`, `createCompactionReader`, `modelWindow`. Usage readers: `readUsage`, `turnUsage`, `readResultUsage`, `resultSpend`, `ledgerSpend` and `growth` (Claude's raw results against the session's running totals). |

Generated from the installed Codex's stable API by `npm run codex-schema` (`scripts/codex-schema.mjs`); never edited by hand. |

## `adapters/git/`

| File | What it is |
| ---- | ---------- |
| `adapters/git/carry.js` | Carrying a chat's own uncommitted files between places of a repository (HarnessV4_Git_Plan §12): read-only `blobsAt`, `blobsAtEach` (by `cat-file --batch-check`), `blobsNow` (by `hash-object`) and `dirtyOf`, and the two writes a move is made of, `writeAs(place, rev, paths)` and `toLastCommit(place, paths)`, both git's own restore, nothing staged. `bringUncommitted(from, to, base)` gives a flow's new worktree its folder's uncommitted files. Paths reach git literally; answers in words. |
| `adapters/git/changes.js` | What the agents' hands changed, read back from a turn's recorded rounds (harness plan B2, HarnessV4_Git_Plan step 1): `ownChangesOf(rounds, { patch, path, place, alone })` → `{ files, totals, during, outside, places, errors }`, each agent's own files per place, net from before the first round naming them to after the last, `also` where another changed them between; `during`, what changed while its commands ran. Read-only git: `diffFiles`, `diffPatch`, `changesSince`, `taskFolders`. |
| `adapters/git/footprint.js` | Filament's footprint in a repository (the footprint plan, Phase 7): it reads `gitCommonOf`, `filamentRefs` (each `refs/filament/` ref with its commit, tree and time), `folderBytes(dir, budget)` (links counted, never followed; `partial` past the budget) and `routineBranches` (routine runs' branches with their worktree, uncommitted files and own commits), and makes Clean up's writes on the person's press: `dropRefs`, `dropRefGroups` (one `update-ref --stdin` step) and `dropBranch`, without hooks. |
| `adapters/git/inspect.js` | Read-only git for a project folder through `snapshot.js`'s `git()`: `statusOf` (`parsePorcelainV2`), `diffOf`, `diffsOf`, `logOf`, `branchesOf`, `lastCommits`, `ignoredOf`, `placeInfo(folder, { whole })` (place, worktree, branch; `whole`: base, ahead, behind, uncommitted); a clone's facts: `remoteOf` (`remoteRead`), `cloneOf`, `clonesOf`, `folderFacts`, by `remoteKey`; `remoteKeys`: folders' keys kept, read in lanes; `folderThere`: a stat waited 2 s at most (an offline share). Nothing writes. |
| `adapters/git/places.js` | The places of a repository (HarnessV4_Git_Plan steps 4, 5): `worktreesOf` (git's worktree list read by `parseWorktrees`, Filament's helper copies left out), `readWorktree`, `heldBack` (why a worktree has no Remove), `goesWith` (what git ignores there), and the writes on the developer's click: `removeWorktree` (moved aside, git's record dropped, deleted here, a link as a link), `putBack`, and `makeWorktree` and `ownWorktree` for a chat's first send, `takeBack` when it fails. Also `leftBehind`. |
| `adapters/git/snapshot.js` | Working-tree snapshots on hidden refs (plan WP-J.2): `snapshotTree(folder, { name, previous })` captures the whole repository as a commit under `refs/filament/snapshots/<name>` through a temporary index, leaving branches, index and `git status` alone; `addWorktree` checks one out detached with hooks off (`gitWithoutHooks`). Also `git()`, the runner every git adapter uses, off the server's thread (`gitProgram`, `OWN_CONFIG`), and `placeOf`, `folderOf`, `repoOf`, `listSnapshots`, `snapshotExists`. |
| `adapters/git/send.js` | Copies across machines: `bundleSnapshot` (`ask` first) → less what stays (`leaveOut`, `leftOutWhy`: an untracked secret or key, a link out, a junction's files, a submodule, too large; no home or credentials repo); `importBundle`; `mirrorHaves`, `mirrorHas`; `checkoutCopy` (a fresh `.git` on the mirror, LFS pointers; folded paths refused); `captureCopy` (via the mirror; nested repositories stay), kept by `keepCapture`, `bundleKept`; `importBack`; `linkAstray`; `sweepLeft`. Hooks, filters off. |
| `adapters/git/patch.js` | A builder's patch workspace (big repos, phase 1): an overlay at its copy's path, files copied up from the commit through git's filters as they are opened; `openPatch`, `capturePatch` (a temporary index and commit-tree), `parkPatch`, `revivePatch`, `markPatchUnsaved`; `promotePatch` moves it to a worktree at the same folder with its changed files; the launch history rule 10 reads (`movesOf`, `noteMove`). |
| `adapters/git/sparse.js` | Sparse copies for big repositories (the plan of 11-09, phase 2): `bigRepo`, a cone from the session folder, changed files and paths (`coneOf`, `coneTooWide`), `checkoutSparse` and `widenCone` with `SPARSE_CONFIG` on the command line — never porcelain, the shared config unchanged —, the cone file in git's record (`readCone`, `writeCone`), and `skippedPaths`/`presentOf`, by which a capture keeps a sparse checkout's outside; a helper's words (`sparseWords`, `widenedWords`). |
| `adapters/git/spawn-pool.js` | Processes started off the server's thread, as on Windows a start holds its thread 15 to 25 ms and far longer with many at once: `createSpawnPool({ url, threads, marginMs })` → `{ execFile }` runs execFile on one of `SPAWN_THREADS` worker threads (`spawn-thread.js`), started as calls need them, answering `Ran` `{ failure, stdout, stderr }`; a call its thread has not answered `SPAWN_MARGIN_MS` past its time or stop is answered here. `execFileOffThread` is the shared pool's call. |
| `adapters/git/spawn-thread.js` | A worker thread of `spawn-pool.js` that git's processes start on: each call spawned as asked, its stdout and stderr written to two temp files (`filament-spawn-<pid>-<thread>-<id>`), never pipes, since on Windows every new process inherits open handles and a long-lived one would hold a git's pipe open; the call is answered from the files at exit and they are removed. It keeps execFile's rules: `timeout`, `maxBuffer` (measured every 100 ms), a stop by id, `input` on a stdin pipe. Exports nothing. |
| `adapters/git/standing.js` | Where a folder's repository stands, for a session's briefing: `repoStandingOf(folder, { commits, own, worktrees, refusedOf, siblingMs })` → `RepoStanding` (`core/repo-standing.js`), or null outside a repository or past the folder fence: the branch against its base (`placeInfo`, `baseOf`), the other worktrees and whether each is merged (`worktreesOf`, `readWorktree`), the branch's own commits and the base's newest. Read-only, no index lock; `server.js` hands it to memory as `repoState`. |
| `adapters/git/template.js` | A worktree template's files (HarnessV4_Four_Plan E19): `measure(top, path)` (bytes and files, links never followed), `copyCandidates(place)` (what git leaves out of a worktree, ignored and untracked, biggest first, at most `CANDIDATES_MAX`) and `copyInto({ from, to, paths, onProgress, signal })` → `CopyResult`: files copied eight at a time with the disk's fast clone, never over a checked-out file, links as links, failures named, a full disk or the signal ending it, keeping what it copied. |
| `adapters/git/cow.js` | Copy-on-write clones for builder copies (big repos, phase 3): `cowSupport` asks once per repository whether its drive clones files, kept in `<home>/.cow.json`; `cloneTree` copies the session's folder without `.git`, nested repositories, links or locks; `restatIndex` gives the clone's index its own stats so git hashes nothing again; `makeClone` makes the copy at its commit; `buildCaches` names the build caches git ignores there (`BUILD_CACHES`), which a clone keeps warm. |
| `adapters/git/worktree.js` | A writing sub-agent's own git worktree (HarnessV3 §15 item 88): `openTaskWorktree` snapshots the folder's repository as it stands, uncommitted files included, onto `refs/filament/subagents/<id>/base` and checks it out detached under `TASK_HOME`, `DEPENDENCY_DIRS` linked in; `captureTaskWork` commits each exchange onto `…/work`; idle copies are parked and reused, at most `KEPT_COPIES`. `previewApply`, `applyTaskWork` (file by file, three-way where both changed), `rebaseTaskWork`, `markApplied`. |
| `adapters/git/watch.js` | A branch watched for new commits (the plan of 11-11, w3): `branchHead` (its tip by its exact name, null where it has none), `branchCameAt` (when it came to a tip, by its reflog), `commitsBetween` (a move's commits added, what it dropped, or its start gone), `commitsMade`, `commonDirOf`, `watchBranch` (its tip within moments: its refs' files looked at every second, none held open, whichever worktree committed; read every 30 s on the network or where no repository is found). Reads only. |

## `adapters/lsp/`
