# Module map: src root and small folders

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `src/`

| File | What it is |
| ---- | ---------- |
| `acp-render.js` | An old path kept for its importers: re-exports all of `app/acp-render.js` (an agent's activity rendered as text for a chat client: `formatToolLine`, `ActivityRenderer`, the diff and plan renderers). Imported by `test/render.test.js`; it goes when that test moves (Refactoring Plan, Phase 3). |
| `acp.js` | An old path kept for its importers: re-exports all of `adapters/agents/acp/bridge.js`, `acp/process.js`, `acp/detect.js`, `acp/negotiate.js`, `adapters/agents/agent-process.js`, `core/catalogues.js`, `core/conversation.js` and `core/wire/flatten.js`, plus `formatToolLine` from `app/acp-render.js` and `LiveTurn`, `describeToolCall`, `choosePermission` from `adapters/agents/turn-bridge.js`. Imported by seven tests (`acp`, `acp-env`, `acp-kill`, `agents`, `core-notes`, `ops`, `security`). |
| `archive.js` | An old path kept for its importers: re-exports all of `services/memory/archive.js` (the archive, Filament's SQLite record of projects, chains and turns). Imported by 19 tests and `scripts/memory-bench.mjs`. |
| `assistant.js` | An old path kept for its importers: re-exports all of `app/assistant.js` (the dashboard assistant that configures Filament through tools against a draft config: `Assistant`, `TOOLS`, `PAGES`, `buildSystemPrompt`). Imported by `test/assistant.test.js`. |
| `autofit.js` | An old path: re-exports all of `core/autofit.js` (the context-fit vocabulary: `fitVerdict`, `detectOverflow`, `AUTOFIT_RESERVE_CAP`). Nothing in the tree imports this path; only `test/fixtures/ratchets.json` names it, among the untyped files. |
| `client-bridge.js` | An old path kept for its importers: re-exports all of `adapters/agents/client-bridge.js` (the client-tool bridge: `ClientToolset`, the action ids, `extractToolResults`). Imported by `test/client-bridge.test.js`. |
| `commands.js` | An old path kept for its importers: re-exports all of `app/commands/registry.js` (the catalogue of what can be typed into a chat: `commandCatalog`, `commandsMarkdown`). Imported by `scripts/gen-docs.js`. |
| `config.js` | An old path kept for its importers: re-exports all of `services/config/store.js` and wraps `defaultConfig({ withAgents })` and `loadConfig(dataDir)` with the first-run agent seed (`detectedAgentSeed` from `adapters/agents/acp/detect.js`), as the composition root hands it to the store. | `doctor.js` | An old path kept for `bin/filament.js`: re-exports all of `cli/doctor.js` (`runDoctor`, `formatDoctor`); it goes when `bin/filament.js` imports `cli/doctor.js` itself. |
| `hands.js` | An old path kept for its importers: re-exports all of `adapters/tools/hands.js` (the server-side file and shell tools of the agent loop and its sub-agents). Imported by `test/hands.test.js`, `test/incident-invariants.test.js` and `test/remediation.test.js`. |

| `mcp-server.js` | An old path kept for its importers: re-exports all of `http/mcp.js` (`McpToolServer`, Filament's MCP toolset over Streamable HTTP, and its paging helpers). Imported by `test/firehose-ops.test.js` and `test/mcp-paging.test.js`. |
| `memory-backup.js` | An old path kept for its importers: re-exports all of `services/memory/backup.js` (`BackupManager` and `consistentCopy`, backups of the memory folder). Imported by `test/memory-backup.test.js`. |

## `cli/`

| File | What it is |
| ---- | ---------- |
| `cli/ask.js` | The command line's questions at a terminal: `processTerm()`, `askLine`, `askYes`, `askChoice` (by number, Enter to skip where it may), `askSecret` (a key typed with a star a character, Ctrl+C or the terminal gone exit 130) and `readAll` (stdin, for `--key-stdin`). With no person at a terminal a question is a `CliError` that exits 4. |
| `cli/client.js` | The way to a running Filament: `whereFilament(dataDir)` (its `listening.json`, else the config's port, else the folder's default — read, never written) and `connect` (its calls carry the folder's owner key; exit 3 where none answers, or one of another data folder does, or refuses its key). Says still what moved to services/machines/client.js, as the commands import it: `EXIT`, `CliError`, `clientAt`, `refusalWords`, `busyOf`, `readEvents`, the `Client` type. |
| `cli/pinned.js` | Says still what moved to services/machines/pinned.js, as the command line and the desktop app import it: `pinnedFetch(pin)`, fetch pinned to a certificate's SHA-256 fingerprint, and `certificateAt(url)`. |
| `cli/remotes.js` | The Filaments on other machines the command line drives (the owner's of 11-06): `machineOf` reads the machine a command names (`--machine`, `--url`, FILAMENT_MACHINE). Says still what moved to services/machines/remotes.js, as the commands and the desktop app import it: `REMOTES_FILE`, `readRemotes`, `shownRemote`, `pairingOf`, `connectTo`, `remoteNamed`, `connectRemote`, `disconnect`, `machineAt`, `certRefused`, `plainWords`, `onThisMachine`, the `Remote` type. |
| `cli/commands.js` | `COMMANDS` of `{ name, usage, summary, more, run }`: setup, status, open, keys (list, add, test, remove), agents (list, detect, install, connect, off, sign-in, check, sign-out), models, memory, chats, chat (reply streamed, ended by `QUIET_MS` of silence; an ask answered at a terminal, else exit 4), settings (get, set), stop, restart, service, update, pair, connect, machines, disconnect, devices (list, revoke, rename); `--machine` names a connected one; `statusOf`, `statusWords`, `valueOf`. |
| `cli/doctor.js` | `filament doctor`: `runDoctor({ dataDir, turn, agentFilter, log })` checks the config, the data folder, the running server, every enabled coding agent (command, handshake, session, capabilities, login and how to sign in; Codex's app-server, sign-in and models) and housekeeping detection, and with `--turn` sends one real one-word turn per agent through Filament's front door; `formatDoctor(report)` prints the findings. `bin/filament.js` calls it through `src/doctor.js`, `--agent` the filter. |
| `cli/flows.js` | The steps that take more than one call: `addKey` (a provider, its plan, its fields, the key typed or piped in, never from argv, then tried unless `--no-test`), `tryKey`, a coding agent's accounts (`accountsOf`, `accountsNamed`, `accountOf`, `signedInOf`, `accountLabel`, `accountWord`), `signedInWords`, `signIn` (a browser's page or a terminal's line, `far` ways first over SSH or to another machine), `openPage` (where `screenHere`: not over SSH, nor a Linux with no display), `named`, `flagValue`. |
| `cli/listening.js` | Where a running Filament listens, for the command line: `LISTENING_FILE`, `listeningUrl`, `writeListening` (the server's, as it listens), `removeListening` (its own process's alone) and `readListening` (none where its process is gone). |
| `cli/main.js` | `runCli(argv, { dataDir, term, out, err, write })` — the commands past bin's own (start, print-key, where, doctor): parses with `parseArgs`, runs one, and gives its exit code, or null where it is none. `commandsHelp()` for `--help`, `filament help <command>` for one. |
| `cli/setup.js` | `filament setup`, at a terminal: Filament started where none runs (this program's `start`, detached, waited for up to a minute), the coding agents here connected and signed in, a provider's key added, memory and its side model, then where it stands and the harness opened. With no terminal it says the commands that do each step (exit 4). |
| `cli/service.js` | `filament service` (`runService`): Filament under systemd's user manager on Linux — install writes `unitText` (the launcher `launcherOf` picks, `--data-dir`, `--port`, Restart=always) to `unitFile`, daemon-reload, enable --now, says lingering; uninstall, status, logs (journalctl). `underSystemd`: `stop`/`restart` through systemctl, once idle unless --force, a stop hung past `tools.stopMs` restarted. Refuses on macOS, Windows and with no user manager. `tools.spawn` runs systemd's tools. |
| `cli/update.js` | `filament update` (`runUpdate`): a server build as install.sh put it (`<base>/<version>`, `current`) to the newest release (`--version`, `--check`): SHA-512 checked, glibc weighed, unpacked beside, `current` moved in a rename; restarted under systemd once idle (`--wait`: `cameBack`), one not up left for the one before (`goBack`); one installed, another running, restarted on; `--back`; pruned to two. `createSelfUpdate` (`/api/update`): only current's while it waits, `$` doubled (`unexpanded`). |
