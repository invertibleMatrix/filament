# Module map: services

The [architecture](../ARCHITECTURE.md) explains the layers; each row below says what one file is and does.

## `services/`

| File | What it is |
| ---- | ---------- |
| `services/agent-accounts.js` | `createAgentAccounts({ file, log, now })` → `report`, `signedIn`, `unknown`, `view`, `retain`, `onChange` — each coding agent's account as the agent itself said it (HarnessV3-ACP AC3-6): who it runs as, its plan's windows with their newest readings, extra usage or credits, and when and from where each came, per upstream in `agent-accounts.json`, so a restart or a later page still says who ran. The bridges feed it through their `onAccount`; the shapes are core/agent-limits.js. |
| `services/agent-cards.js` | Saved agents (HarnessV4_Tasks E15): a card is what a saved agent is kept as — its `@` tag, its name, where it is listed, the line on what it is good for, how it thinks, what it may do (`CARD_MAY`), its model rows, what it sees of the session it is called in (`CARD_VIEWS`), and the commands it runs without asking. `createAgentCardStore` keeps them beside `SHIPPED_CARDS` (`shippedCard`); `cardTag`, `tagShaped`, `cardsNamedIn`, `modelNamed`, `mayLower`. |
| `services/app-hooks.js` | `createAppHooks({ dataDir, now, log })` — each kept app's hooks' tokens, the random part of `/hook/<app>/<token>`, by app and hook in `app-hooks.json` (`APP_HOOKS_FILE`): `ensure(app, names)` makes one when a Keep first grants a hook and keeps it across later Keeps, `renew` makes a new address and stops the old one, `find(app, token)` compares in constant time, `list`, and `drop(app)` when the app is deleted. The shapes are core/app-hooks.js. |
| `services/app-import.js` | Import app… and the apps a project's folder brings (the Space Apps plan): `appFromZip(buf, { maxBytes })` reads an app folder from a .zip (services/zip.js), app.json and its page at its top or in one top folder, its download's own parts taken out; `importApp` unpacks it into the project's `.filament/apps/` beside one there, never over it; `folderApps` lists the apps already there; `folderNameOf`, `keptWebIn`, `notYetAdded`. |
| `services/app-runs.js` | `createAppRuns({ dir, kept, log, now })` → `load()` and `save(name, run, keep)` — the runs of a Space's buttons kept on disk, one file each under `app-runs/<name>/` in the data folder, written as it starts, every few seconds while it says something and as it ends, the newest `kept` of each kept. A run still going when Filament stopped loads back stopped, in `CUT_WORDS`. |
| `services/app-secrets.js` | `createAppSecrets({ dataDir, encrypt, now, log })` → `list(app)` (when each was set, never a value), `set(app, name, value)` (checked by core/app-secrets.js), `clear`, `drop(app)` and `values(app)` — an app's secret values in `app-secrets.json` (`APP_SECRETS_FILE`), sealed with the installation's secret.key unless `server.encryptSecrets` is off. Values are read for an app's commands' environment (services/dashboard-runner.js) and a script watcher's program's (app/watchers/script.js). |
| `services/app-sql-child.js` | The process an app's SQL runs in, apart from Filament's: services/app-sql.js forks it and sends one statement at a time. Each app's database is opened once and kept open, capped as it opens, then held by the authorizer with `sqlMay` (core/app-sql.js); a second statement in the same text is refused. Ending this process is what stops SQLite mid-query. |
| `services/app-sql.js` | `createAppSql({ dataDir, timeoutMs, maxMb, idleMs, log })` → `run(name, sql, params)`, `drop`, `fileOf`, `stop` — one SQLite database per app, each in a process of its own (services/app-sql-child.js) started at its first statement and ended at a statement's time limit (`SQL_TIMEOUT_MS`; the next one gets a new process) or when the app goes idle. The child's environment carries none of Filament's keys (`sqlEnvOf`), and a slow app makes no other wait. |
| `services/app-starters.js` | The starters of ＋ New app (the Space Apps plan): real app folders Filament ships under `starters/apps/` (`STARTERS_DIR`), each saying itself in its `starter.json` — `appStarters()` lists them, `startersFor(own)` those a Space offers, `copyStarter` copies one into the project's `.filament/apps/` (`APPS_FOLDER`) for an agent to adapt, and `newAppWords` writes the words the agent's box starts with. |
| `services/artifact-data.js` | `createArtifactData({ store, onChange })` → `collections`, `list`, `get`, `change` — what an artifact's page keeps: collections of small JSON records with an `id`, under the artifact's `data/` folder beside its versions, so every view reads the same and no version changes them; deleting the artifact takes them. A `change` sets, updates and deletes together, all or nothing, within `COLLECTION_MAX_BYTES` and `DATA_MAX_BYTES`; `collectionName`, `COLLECTION_RULE`. |
| `services/artifact-feeds.js` | `createFeeds({ usage, archive, now })` → `read(name, { days })` — Filament's own numbers for a Dashboard's tiles, read-only, answered on the Dashboard's own address (http/artifacts.js): model calls by day and by model from the durable daily usage, the last hour by minute and the calls in flight from the records, sessions by day from the archive; a bad name or day range answers in words with its status. |
| `services/artifacts.js` | `createArtifactStore({ dataDir })` — the artifacts' store: a folder per artifact under `artifacts/` (`ARTIFACTS_DIR`) holding its record (`artifact.json`: title, description, icon, type, each version with who made it and its files, and the version each session last read or published) and a folder per version, written whole beside it; `get`, `list`, `publish` (one over a version the session has not read is refused). `readFolder` reads a project folder published as a page; `leftWords`. |
| `services/cache-churn.js` | The cache-churn watch: a prompt cache pays only when a request's prefix matches what the provider cached, and a client that resends a changing history re-writes nearly the whole conversation each request. `churnLegOf` classifies one finished record (`CHURN_RULES`), `churnVerdict` says when a window of legs is a bill and not noise, `churnNote` words it, and `createCacheChurnWatch` keeps the last legs per session; the record store runs it in `finish`, before the record persists. |
| `services/call-waits.js` | `callWaits` — in-process news for a call through the front door that waits for a slot at its provider (services/health.js's gate): `listen(id, { queued, slot, memory })` until the returned function is called, `queued(id, news)` (the words, provider, model, ceiling and what holds its slots), `slot(id)`, and `memory(id, call)` for each memory call the request ran. Filament's own calls name themselves with `x-filament-call` (app/internal-call.js). |
| `services/changes-kept.js` | `createChangesKept({ dir, most, maxAgeDays, slowMs })` → `worth`, `get`, `put`, `purge`, `sweep`, `settled` — a turn's or a run's changes cut to the rows its card draws, kept on disk across a restart: a file an answer, named by its owner and question, read back only where its key, basis and question match; `worthKeeping` takes a walk of a second or more that git told whole. Bounded by count, oldest read first, and by age where said; a chat's purged when it is deleted; every failure a miss. |
| `services/daily-usage.js` | `DailyUsage` — durable per-day usage in daily-usage.json: tokens, cost, speed and cache numbers per upstream and model, each finished request counted as it finishes. It outlives the request log's rotation, so last month's use has an answer. A day also keeps who asked, by client and project, as parts a build that keeps none reads past (`who`, capped by `WHO_KEEPS`, the rest `WHO_OTHER`); `reach`: what is on record. `localDay`, `derive`, `computeTps`, `writingMs`, `isMemoryRecord`, `KEEP_DAYS`. |
| `services/dashboard-runner.js` | `createDashboardRunner` — a Space's dashboards and apps run with no AI (HarnessV4_Space_Plan S2): the kept ones and the drafts that read by themselves; each source's command run as the Keep granted it, in the project's folder with no shell, 60 s and 1 MB at most; a source failing three times in a row stops; watches write in What happened; buttons run as jobs. In an archived project nothing reads by itself. A Keep pins its scripts' bytes and the code beside each (services/script-pins.js). |
| `services/devices.js` | `createDevices({ dataDir, now, log })`: paired devices. `startPairing`: a code (5 min, one claim); `pending`, `cancelPairing`, `spoil`; wrong codes counted; `claim`: a token once; `verify`; `lapsed`: unused `UNUSED_DAYS`, from `unusedFrom` at the earliest (`expiresAt`); `list`, `rename`, `revoke` (`onRevoke`), `forget`. `mintAgents`; `grant` sets `GRANTS` (`onGrant`): `fullControl`, `heldGrant`, `grantEnds`. `lendModels`, `modelsLentTo`, `UNREAD_DEVICE`. `devices.json` keeps hashes |
| `services/copies.js` | The copies another machine's agents work in: `copiesRootOf`, `createCopies` → a folder per machine, by its device here, `take`/`release`, `bind` (its launch's chat), `lease`/`grace`/`keep`/`setWorking`/`holdWhile` (its chat's turns, work, a command), `measure`, `usage`, `clear`/`sweep` (`onCleared` waited for), `fenceOf`; `storeOf` (in `.mirrors`, by repository, out of agents' reach), `roomFor`; `keepState`/`keptOf` (a copy's state kept, `KEPT_MAX`). Room: 12 copies, 20 GB. `copies.json`. |
| `services/transfers.js` | Copies a machine sends here (cp-send): `createTransfers({ copies, take, haves, has, checkout, capture, keep })` → `haves`, `open` (one per send; resumes from disk; `OPEN_MAX`, room), `part`, `commit` (sha-256, `take` into the store's `mirror.git`, one at a time), `place` (a copy checked out at a commit sent; taken again once its state is kept), `back`, `backPart` (its chat's change captured, never mid-turn, kept `BACK_TTL_MS`, in parts). Cleared copies end their sends. `MIRROR`. |
| `services/events.js` | `createEventBus()` → `publish(topic, payload)`, `subscribe(topic, fn)` — everything in the running app a surface may watch (a record finishing, an operation, an agent turn's progress), published once by topic and delivered synchronously in publication order to each subscriber (or one of every topic), each entry numbered by one `seq`; nothing kept. Records and ops go on `record` and `op`, a run's events on its run topic, which the run log keeps (services/runs.js). |
| `services/flow-store.js` | `createFlowStore({ dir, log })` → `list(chainId)`, `get`, `put`, `remove`, `drop`, `chats` — the flows a chat keeps, one file a chat under `flows/` in the data folder: each flow's steps, boxes and states, each box's chat and its whole result, apart from the chat's record, whose meta every read parses. A chat keeps its open flows and its newest closed ones up to `FLOW_LIMITS`; each write is whole or not at all. |
| `services/health.js` | The upstream health board and the gate — `HealthBoard`: cooldowns after failures, the provider's rate-limit headers, quotas, the candidates' order by strategy (latency, cost, quota) and the concurrency ceiling a 429 teaches (`LEARNED_CEILING_MS`, `LEARNED_HOLD_MOST_MS`, `LEARNED_KEPT_MS`), the state the dashboard shows as healthy, cooling down or rate limited; `ConcurrencyGate`, the slots a call waits for; `isRetryableStatus`, `isAbortError`, `requestWasAborted`. |
| `services/house.js` | The house key: one random secret per process, held in memory only, that Filament's own calls through its front door (the loop's ticks, sub-agents, memory's model calls, the assistant, housekeeping, pings, replays) authenticate with instead of an inbound key — `houseKey`, `houseAuth`, `isHouseCall`, `credentialOf`, `isMachineryRequest` (a loop's tick or a sub-agent), and the headers only a house call may carry (`HOUSE_ONLY_HEADERS`, `READER_HEADERS`, `admitHeaders`); `MODE_HEADER`, a client's. |
| `services/lan-tls.js` | Reach this machine on my network: `createLanListener`, https on `server.lan.port` (`lanPortOf`, `LAN_PORT`, `LAN_PORT_MAX`) beside the loopback listener: `apply`, `state`, `settled`, `newKey`, `close`; `lanIdentity` makes its certificate, kept in `lan-tls/`, renewed with its key a month before its end; `lanIps`, `lanAddresses`, `lanNames`; WSL 2's NAT said (`wslNat`, `behindWslNat`); Windows Firewall: `readFirewall`, `firewallVerdict`, `allowThroughFirewall` (`FIREWALL_RULE`). |
| `services/tailscale.js` | Share on my tailnet: `createTailnetShare` — loopback doors at `server.tailscale.port` and the next, answering the tailnet name's Host or loopback alone, served by `tailscale serve` at https 443 and 8443 where nothing else is (`servedAt`), its own from before known (`fileMemo`), retried while Tailscale is down (`RETRY_MS`): `apply` (trust taken back drops the doors' connections), `retry`, `look`, `state`, `close`; `tailnetDoor`; `findCli`, `runCli`, `statusOf`, `stateWords`, `askedAt`. |
| `services/live-words.js` | A running turn's words, held while it runs (HarnessV3-Launch LD-D16): `createLiveWords()` → `start`, `piece(id, type, text)`, `endBlock`, `blocks`, `follow`, `end`, `held` — its text and thinking blocks so far, so a page that joins later (a reload, a second tab) reads them beside the run's events, over the run's event stream or the page's run socket; the run log keeps a round's words only when the round ends. `wordsFrames`. |
| `services/memory-log.js` | The server's memory census (the owner's of 11-17): `censusOf({ runs, subagents })` — rss, heap used/committed/limit, external, array buffers in MB; the run store's `memory()` and the registry's in millions of characters. `convoChars` counts a conversation from block lengths, never serialised; `registryCensus(entries, cache)` caches a kept conversation by its array; `postCensus(port, census)` posts each minute over Electron's `parentPort`, none without one. |
| `services/loop-health.js` | `watchLoopHealth({ log, windowMs, p99Ms, quietMs })` → `{ look, stop }` — the event loop's health in the server's log, short of a stall: each window's delay read with `monitorEventLoopDelay`, and a window whose 99th percentile passed `SLOW_P99_MS` written as one content-free line, at most once a minute. Started with the server and stopped at its shutdown; services/loop-stall.js covers the long holds. |
| `services/loop-stall.js` | `watchLoopStalls({ ops, thresholdMs, everyMs })` — the event-loop stall detector: a tick that times itself, and a tick late by `STALL_MS` or more is an operation, a warning on the System tab with the length of the hold (content-free: a duration and the threshold). Started with the server and stopped at its shutdown. |
| `services/loopback.js` | `loopbackPost(url, { headers, body, signal })` → a fetch `Response` whose body streams — Filament's calls to its own front door (an agent loop's model call through app/internal-call.js, memory's, the assistant's, a replay, a ping) over node:http, with no deadline but the caller's signal: Node's fetch fails a call whose provider waits past 300 s. An abort rejects the call or errors its body with the signal's reason. |
| `services/machine.js` | `createMachine({ dataDir, host, log, now })` → `get`, `rename` — this machine as another Filament knows it: an id made once and a name (`computerName` until one is given), a kept address read anew, in `machine.json`; one unreadable is set aside, never overwritten. `GET /.well-known/filament` says it with `MACHINE_PROTOCOL` and `MACHINE_PROTOCOL_LOWEST`, read by `protocolGap` (which side updates, `gapWords`); `/api/state` says it with `viewer`. Not memory.json's deviceId. |
| `services/machine-caps.js` | What this machine has to work with now, for another machine's agents to choose where a task runs (p-caps): `createMachineCaps(…)` → `read` — its CPUs (count, model, `load1`, or on Windows `busyPercent` from `SAMPLE_MS` of `busyBetween`), memory free and total, its GPUs (`nvidiaGpus` of nvidia-smi's `NVIDIA_ARGS`, kept `GPU_KEPT_MS`; Apple Silicon's unified one). Nothing of whose machine it is. `GET /api/machine/caps` serves it. |
| `services/mcp-servers.js` | Pure: your MCP servers across the settings layers — the knob `plugins.mcp` on your defaults, a project's and a chat's own layer, adding up by name: `mergeServers` (a narrower layer's server joins, replaces one of its name, or switches one on or off), `serversOn`, the account a remote one signs in with (`withAccount`), its note and load (`withNote`, `withLoad`), `startsServer` (a press); its credentials masked and restored (`maskEntry`, `maskList`, `maskAnswer`, `restoreList`, `cryptLayer`). |
| `services/mcp-sign-ins.js` | `createSignInStore({ dataDir, encrypt, log })` — the sign-ins to remote MCP servers by address, with Filament's registrations at each authorization server and the servers whose registration turned Filament down, in `mcp-sign-ins.json` (`SIGN_INS_FILE`); tokens and client secrets are sealed with `secret.key` unless `server.encryptSecrets` is off, and the file is written to a temporary one and renamed. The protocol's pure half is core/oauth.js. |
| `services/oplog.js` | `OpLog` — the operation log: everything Filament does that is not a model call (health cooldowns, config changes, background jobs, engine lifecycle, learner runs, alerts) as durable, filterable events the System tab shows. Content-free by contract: ids, counts, durations and decisions, never conversation text (`sanitizeDetail` cuts values and caps keys). `wireMemoryOps` and `wireHealthOps` connect the memory service and the health board; the kinds come from core/op-kinds.js, re-exported. |
| `services/project-folder.js` | `projectFolderOf(folder, { asks })` — the folder a folder's project is made of: itself, or, inside a linked worktree, the same place in the repository's main folder, so a chat in a worktree stands in its project with its memory. Read from git's own files, never by running git (the worktree's `.git` file, its `gitdir:` line, `commondir`, the common folder's parent); `repositoryFolderOf`. |
| `services/records.js` | Per-request records: `UsageStore` keeps an in-memory ring for the UI, the JSONL log on disk (rotated at `MAX_LOG_BYTES` into `LOG_GENERATIONS`: `rotateLog`, `readLogReach`, `readLastJsonlRecords`), cost estimation and live events; a record's source (`recordSource`, `TRAFFIC_SOURCE_KEYS`, `recordInScope`, `headersAreInternal`, `HARNESS_CLIENT`, `OWN_CLIENT`, `clientOf`) and writing speed (`addWriting`, `writingRate`, `rateNow`). Re-exports core/pricing.js's lookups and core/redact.js's redaction. |
| `services/response-store.js` | `ResponseStore({ ttlMs, max, now })` — the responses a client may continue with `previous_response_id` (each its items, model and time), bounded and time-limited, kept in memory only, so a restart forgets them and a client that asks for one is told. The clock is injected; http/responses.js holds it. |
| `services/run-images.js` | `createRunImages({ dir, knobs, log, now })` → `keep`, `fileOf`, `sweep`, `typeOf` — the pictures a call handed its model (a read image, an MCP server's screenshot, what a coding agent looked at), kept beside the run files once per content, so the call's card shows them live, after the turn and after a reload. Only PNG, JPEG, GIF or WebP known by their first bytes (core/media.js), never an SVG; `IMAGE_KEEP_MAX_BYTES`, `IMAGES_PER_CALL`. |
| `services/runs.js` | `createRunLog` — the run log: every event a loop publishes on the bus under its run's topic (state changes, rounds, tools, sub-agents), numbered per run, kept in a ring and the run's JSONL file, replayable after a restart. It hears the whole bus and filters, so producers stay unaware. A coding agent's question that waits goes on `turns` as an `ask` (its chat, its id), opened or settled. `RUN_EVENT_TYPES`, `RUN_EVENT_FIELDS`, `eventJson`, `followRunEvents`, `readImages`, `typedByDeveloper`. |
| `services/saved-flows.js` | `createSavedFlows({ dataDir, log, now })` → `list`, `find`, `save` — saved flows (HarnessV4_Flow_Plan F6): a drawn flow's steps and boxes kept to start again from Agents › New flow, with each step's why and each box's needs, without the words it was drawn from. `SHIPPED_FLOWS` ships one, Plan, check, build, hunt. Kept in `flows-saved.json` in the data folder, in memory without one. |
| `services/script-pins.js` | Approval by content: the bytes of the project's scripts a command runs, pinned by hash when the person approves it — a dashboard's Keep (services/dashboard-runner.js), a script watcher's Switch on (app/watchers/script.js) — and read again before it runs. `pinsOf(parts, folder, hash)` pins each part that is a file of the project with the code beside it (`codeBeside`, `BESIDE_MAX`); `scriptsChanged` names those changed, gone or new since; `inProject`, `hashOf`. |
| `services/session-settings.js` | The switchboard: three layers — the global config, the project's and the session's `settings_json` — each knob resolved session, project, global, default, its source named (`resolveSettings`), but MCP servers and folders, which add up (`mergeFolders`). `KNOBS` (each knob's type, default, scope, reach), `applyPatch`, `flatten` (`PROTO_KEYS` passed by), `teamMembersOf`, `agentTeamsOf`, `parseKnobText`, `formatKnobText`, `asksLess`, `configAsksLess`, `namesMode` (a press). |
| `services/session-turns.js` | `SessionTurns` — one turn at a time in a chat of the harness's own, in memory, keyed by the chat's chain key: the holder is the harness's turn, a turn a coding agent began by itself, or the chat's move to another folder. A harness turn holds it around the whole turn; commands, housekeeping, count_tokens, Filament's own ticks and an outside client's requests never do. The turn belongs to the server, not the connection: closing the tab releases nothing. `renewOnWrite`. |
| `services/session-writers.js` | `SessionWriters` — which harness tab writes each session, in memory: the first to open it, or one taking it over, writes; the others follow. A write made as the person acts in a tab (`takeOf`) takes it over first, others are refused in words naming where it is open (`readOnlyWords`, each tab's `placeOf` from its stream). A tab counts while its stream is open; a session let go waits free, and a `peek` takes nothing; `tabOf`. |
| `services/shelf.js` | The shelf (the Space Apps plan): browser libraries every artifact's address serves at `SHELF_AT` from `SHELF_DIR` (vendored under ui/harness/vendor/shelf/ as scripts/vendor-shelf.mjs built it), so an app's page loads them with no network. `shelf()` reads its `shelf.json` once (each library's version, ES module, classic script and global), `shelfPath(path)` gives a listed file's place on disk, and `shelfLines` gives the guide's words for it. |
| `services/source-folder.js` | `listFolder(f, root, signal)` — an app's folder source (the Space Apps plan): a folder of the project listed read-only as rows (its path from the project's folder, name, kind, size, when it last changed), `depth` deep and by a name's pattern, at most `FOLDER_SEEN_MAX` entries looked at. Never above the project's folder: its real path is checked, and a link inside is listed, never followed. |
| `services/space-files.js` | `createSpaceFiles({ dir, now, log })` → `keep`, `pathOf`, `forget`, `sweep(held)` — the files a person attaches to a Space's tasks, their bytes in one folder a project, each written whole (a temporary file, then a rename). Which task holds which is in the Space's file (core/space.js), so a Space brought back has them again; `sweep` removes what no Space holds once `SWEEP_AFTER_MS` old. `fileKindOf` tells a picture by its bytes. |
| `services/space-machines.js` | `createSpaceMachines({ spaces, machines, folderOf, remoteOf, log, everyMs })` → `start`, `stop`, `pull`: a project's Space fed by every machine (sp-cross). Every `SPACE_MACHINES_MS` each Space with a git remote asks each machine kept for its `GET /api/spaces/machine-feed` since `fedFrom`, each call timed, and the store writes it (`machineFed`; a cut answer, `past`, closes no row). A machine that fails, or answers 503, rests 5 pulls. |
| `services/spaces.js` | `createSpaceStore({ dir, events, log, now, apart })` — a project's Space on disk, one JSON file per project under `spaces/`, read once and kept in memory; each change written whole, then said on the events bus's `space` topic. Settings › Space in `_space-settings.json` (`defaults`, `setDefaults`), a Space's own (`settingsOf`, `setSettings`) and what it runs on (`runsOn`, 11-04). Shapes and checks: core/space.js, core/space-settings.js. `SPACE_PRUNE_EVERY_MS`, `NO_SPACE`, `SPACE_DELETED`. |
| `services/spend.js` | `usageOf(chain)` — what a session has spent, read from its chain's spend ledger (`meta.spend`: dollars, the four token columns, cache savings, unpriced requests), which the records feed with every model call the session makes, its loop's ticks and its sub-agents' calls included; for the Spend and Cache widgets and the settings answer. Spend is tracked, never capped. |
| `services/store-files.js` | A store's file of another build's version (r-itself, 11-12): `STORE_FILES`, the stores that read a versioned file and the version each reads (teams, agents, a Space, the usage files, telemetry); `readStoreFile` sets one of another version aside whole as `<file>.v<version>.<when>` before anything is saved over it, takes this build's own back, keeps both where two differ (`.kept`), says each once; `setAsideIn`, `setAside`, `asidesOf`; `unreadBy`, `STORE_FILES_BEFORE` for cli/update.js. |
| `services/subagent-starts.js` | Pure: `SUBAGENT_STARTS` — the ways the developer begins a side agent, each a row of the launch's own fields: the worker card it runs as, a lower "may do" where it needs one, and what it sees. One table for the harness page, the launch route and the `/subagent` command; whatever the launch names itself wins, and no session default changes. `startFields`; `CATCH_UP_TASK`, the question of Catch me up, the one start that brings its own and is a live copy while the cache is warm (`fork: "warm"`). |
| `services/task-notes.js` | `createTaskNotes({ dir, now })` — what the agent keeps behind its task graph (HarnessV4_TaskNotes_Plan): notes, each a long text under a title of its own, and files copied in, behind each task or the graph itself, on disk with the chat and never in its record or the conversation, so a compaction or a restart loses none. `list`, `counts`, `keepNote`, `copy` (a plan carried into a new chat, 11-06); `NOTES_LIMITS`, `fileName`, `titleOf`. |
| `services/teams.js` | Teams (HarnessV4_Tasks E15 step 6): a saved group of cards — its lead in charge and the crew it hands work to, each with the team's own line for that member; any card may lead or sit in a crew. `SHIPPED_TEAMS` (Builders and BugHunters, each led by its own Lead), `createTeamStore` keeps your own in `TEAMS_FILE` (`TEAM_LIMITS`), `teamKey`, `memberId`, `checkWords`, `checksUnasked`, `writesMore`, `SHIPPED_TEAM_SETS`. Its crew is core/roster.js's, a team it does not ship core/folded-teams.js's. |
