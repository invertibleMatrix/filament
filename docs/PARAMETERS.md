# Filament parameters

Generated from `src/core/schema.js` by `npm run docs`. The same text appears next to every field in the settings UI.

## Layering

Rules apply in three layers: **global defaults** (Rules page) → **upstream overrides** → **route overrides**. A field left unset on a layer inherits from the layer below. Every rule field below can be overridden on any layer.

| top-level | what |
|---|---|
| `server` | listener, keys, timeouts |
| `observability` | what is recorded per request |
| `rules` | global request-shaping rules |
| `upstreams[]` | places requests are forwarded to |
| `routes[]` | model name → upstream mapping, top to bottom |
| `sessions` | your session defaults, one turn at a time, a turn a restart cut off |
| `agentLoop` | the `agent/<model>` loop: a model given hands and permission modes |
| `memory` | the long-term memory system |
| `alerts` | what the console and tray warn about |
| `ui` | the harness page's own choices for this data folder: the welcome tour seen |
| `telemetry` | anonymous usage statistics: on or off, the notice shown |
| `experimental` | features still being tried, each off until turned on: chats named by the side model |

## Rules

Request shaping rules. Layered: global defaults, then per-upstream, then per-route overrides.


### rules.thinking

How the Anthropic `thinking` parameter is sent upstream.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.thinking.mode` | enum (`client`, `adaptive`, `disabled`, `strip`) | `client` | Which thinking configuration goes upstream. | `client` keeps what the agent sent (after the fixes below). `adaptive` forces adaptive thinking. `disabled` forces thinking off (stripped on models that cannot disable it). `strip` removes the parameter so the model uses its own default. |
| `rules.thinking.legacyToAdaptive` | boolean | `true` | Convert the legacy `{type:"enabled", budget_tokens}` shape into `{type:"adaptive"}` for adaptive-only models. | Claude Opus 4.7+, Opus 5, Sonnet 5 and Fable reject `budget_tokens` with HTTP 400. Agents built on older SDKs still send the legacy shape; this makes them work. |
| `rules.thinking.adaptiveOnlyModels` | regex | `claude-(fable\|mythos\|opus-5\|opus-4[-.]?[78]\|sonnet-5)` | Model-name pattern for models that accept only adaptive thinking. | Used by `legacyToAdaptive`. Extend it when new models ship. |
| `rules.thinking.rejectsDisabledModels` | regex | `claude-(fable\|mythos)` | Models that reject `thinking.type:"disabled"` (thinking is always on). | For these the shim removes a `disabled` value instead of forwarding it, avoiding a 400. |
| `rules.thinking.noAdaptiveModels` | regex | `claude-(haiku\|sonnet-4[-.]?5\|opus-4[-.]?[0-5]$\|3[-.])` | Models that do not accept `thinking.type:"adaptive"` at all (older Claude, Haiku 4.5). | An adaptive request to these is converted to `enabled` with `fallbackBudgetTokens`, and `output_config.effort` is removed. |
| `rules.thinking.fallbackBudgetTokens` | number | `16000` | Thinking budget used when converting adaptive thinking for `noAdaptiveModels`. | Must be at least 1024 and less than `max_tokens`. Larger budgets cost more output tokens. |
| `rules.thinking.display` | enum (`keep`, `summarized`, `omitted`, `updates`) | `summarized` | Value of `thinking.display` sent for models that support it. | `summarized` makes the model return readable reasoning summaries (visible thinking in the agent). `omitted` (the API default on Fable, Opus 5, Sonnet 5, Opus 4.7+) returns empty thinking blocks even though thinking is still billed. `updates` returns short progress notes (beta, Fable only). `keep` sends whatever the agent sent. |
| `rules.thinking.displayModels` | regex | `claude-(fable\|mythos\|opus-5\|opus-4[-.]?[678]\|sonnet-5\|sonnet-4[-.]?6)` | Models that accept `thinking.display`. | Older models reject unknown thinking fields, so display is only added for matches. |
| `rules.thinking.respectClientDisplay` | boolean | `false` | If the agent already set `thinking.display`, keep its value. | Off means the shim's `display` setting always wins. |
| `rules.thinking.stripUnsignedHistory` | boolean | `true` | Remove thinking blocks that have no signature from earlier assistant turns before forwarding to Anthropic. | Such blocks come from ACP agents (Cursor) or other providers when you switch models mid-conversation; Anthropic rejects them with HTTP 400. Signed blocks are left alone, so the prompt cache is unaffected. |

### rules.effort

How `output_config.effort` (Anthropic) or `reasoning_effort` (OpenAI) is chosen.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.effort.sources` | array (`suffix`, `client`, `default`) | `["suffix","client","default"]` | Where the effort level comes from, in priority order; the first source that yields a value wins. | `suffix` reads a `-low/-medium/-high/-xhigh/-max` ending on the requested model name. `client` uses the value the agent sent. `default` uses the `default` setting below. |
| `rules.effort.default` | enum (`none`, `low`, `medium`, `high`, `xhigh`, `max`) | `none` | Effort used when no other source provides one. | `none` sends no effort field (the model's own default, usually `high`). Higher effort means more thinking, better results on hard problems and more output tokens billed. |
| `rules.effort.allowed` | array (`low`, `medium`, `high`, `xhigh`, `max`) | `["low","medium","high","xhigh","max"]` | Effort levels the shim is allowed to send. | Anything outside this list is handled per `onUnsupported`. Remove `max` here if you want a hard cost ceiling. |
| `rules.effort.onUnsupported` | enum (`clamp`, `drop`, `pass`) | `clamp` | What to do when the chosen effort is not allowed for the model or by `allowed`. | `clamp` picks the nearest lower allowed level. `drop` removes the field. `pass` sends it anyway (the provider may return 400). |
| `rules.effort.suffixes` | array (`low`, `medium`, `high`, `xhigh`, `max`) | `["low","medium","high","xhigh","max"]` | Model-name suffixes recognized as effort selectors, e.g. `claude-opus-5-max`. | Lets agents without an effort setting choose effort by picking a model name. |
| `rules.effort.stripSuffix` | boolean | `true` | Remove the recognized effort suffix from the model name before matching routes and forwarding. | On (default): `claude-opus-5-xhigh` matches `claude-*`, the upstream receives `claude-opus-5`, and xhigh becomes the effort. Off: the suffix still sets the effort, but the exact name is forwarded, for providers whose own model ids end in an effort word. Set it on a route or an upstream to keep the exact name only there (the route is still found with the suffix removed, so a `claude-*` route keeps matching). Coding agents such as Cursor always receive the exact name; no setting needed. |
| `rules.effort.modelCaps` | list | `[{"match":"claude-(opus\|sonnet)-4[-.]?6","allowed":["low","medium","high","max"]},{"match":"claude-(haiku\|sonnet-4[-.]?5\|opus-4[-.]?[0-5]$\|3[-.])","allowed":[]}]` | Per-model-family limits on effort levels. | Each entry is `{match: <regex>, allowed: [levels]}`. An empty list means the family accepts no effort field at all, so it is removed. Opus 4.6 and Sonnet 4.6 have no `xhigh`; Haiku 4.5 and Sonnet 4.5 have no effort. For one model at one provider, its row on the Upstreams page (`tune` → Reasoning) and then its provider's own listing (Anthropic's states each model's levels) come before these entries; `allowed` above still caps them all. |
| `rules.effort.capWhenThinkingDisabled` | enum (`none`, `low`, `medium`, `high`) | `high` | Maximum effort to send when thinking is disabled. | Opus 5 returns 400 for `xhigh`/`max` with thinking disabled. `none` disables the cap. |

### rules.resilience

What happens when an upstream misbehaves: failover to the backups and cooldowns after failures.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.resilience.failover` | boolean | `false` | Use the backup upstreams listed on a route when the first one fails or is out of quota. | On: a request that gets 429 / 5xx / unreachable from the first upstream is retried on the next backup in priority order, and upstreams that just failed or report exhausted quota are tried last. Off (the default since 2026-11-09): only the first upstream of a route is ever used; backups are ignored until it is switched on. Switchable from Settings › Providers, the console's Home page and the tray card. |
| `rules.resilience.cooldownBaseSeconds` | number | `10` | First cooldown after a retryable failure (429, 5xx, unreachable). | Doubles with each consecutive failure (10, 20, 40 s …) and resets on the next success. A cooling-down upstream is tried last, not skipped, so a route with a single upstream still works. |
| `rules.resilience.cooldownMaxSeconds` | number | `300` | Longest cooldown. | Caps the doubling. |

### rules.autofit

The context-fit stage that observes every request (the window, where it came from, the compaction line, the estimate and the verdict — on the request record, the meter and the widgets) and the /autofit command's defaults. Nothing here lets anything rewrite a request between a client and its provider: a request that does not fit goes out as it came, the provider's refusal reaches the client, and the person runs /autofit when they want the session compacted to fit (2026-09-28: the automatic ladder — proactive clearing, the reactive retry, the local 413 — was removed; its walking clear re-wrote the prompt cache every leg and cost a three-digit bill).

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.autofit.margin` | number | `0.85` | The /autofit command's margin: the share of the compaction line a fit holds. | A fit summarizes the smallest prefix of oldest turns that lands the next request under this share of the compaction line (context.compaction.thresholdPercent of the window). The margin is what keeps the fit holding: the next many requests stay under it without another compaction, so the prompt cache survives. /autofit <30-95> overrides it per call. |

### rules.trim

The slice pass: how a compaction summary too big for one call of its writer is read — in sequential slices sized from the writer's window, oldest first, each call carrying the summaries before it. A chat Filament runs falls to it where even its folded turns outgrow one call (Settings › Context names the writer).

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.trim.sliceBudgetFraction` | number | `0.7` | Share of the summarizer's window one slice call may use. | The rest is left for the summaries carried into that call and for its reply. Slices are sized **after** each call returns, from the summary it actually produced, so the count is discovered rather than guessed. Lower is safer on a provider that counts tokens differently than Filament does. |
| `rules.trim.digestCapFraction` | number | `0.3` | Share of the slice budget the carried summaries may take before they are recompressed. | Carried summaries grow monotonically, so late in a long pass there would be no room left for content: past this share they are re-summarized into one rolling digest. That one call loses prompt-cache reuse (the carried prefix changes); between recompressions the prefix is append-only and caches normally. |
| `rules.trim.sliceSummaryTokens` | number | `1500` | The length each slice summary is asked for. | The prompt asks for about 0.75x this in words. It is never a cap: the call asks for the most the summarizer can write inside its window (a reasoning model thinks inside the same room), and the summary is kept whole. |
| `rules.trim.minSummaryPercent` | number | `0.5` | Floor under one slice summary, as a percentage of the slice it condenses. | Measured: a summarizer answered an 88,925-token slice with 51 tokens — three sentences for 86 messages — with HTTP 200, so the empty-reply guard passed it and half the conversation left the summary. Under this floor (never more than a quarter of `sliceSummaryTokens`) the slice is retried at half the size, at most 3 retries per pass, and the rest of the pass stays at the size that worked; a slice that cannot be split further is kept and marked **unusually short** in its heading. A cached summary under the floor is written again instead of reused. `0` disables the check. |
| `rules.trim.maxSliceTokens` | number | `100000` | Ceiling on ONE slice, in tokens — whatever the summarizer's window would allow. | One summary condenses one slice to about `sliceSummaryTokens`, so a slice's size sets how much detail survives. Without a ceiling the slice budget is `0.7 × the model's context window`: a 1M window would make 700k-token slices, each condensed into one summary of some 1,100 words. More, smaller slices cost slightly more and keep more. `0` disables the ceiling and restores window-proportional sizing. |
| `rules.trim.tailMessageCapChars` | number | `24000` | Longest single message the summarizer reads. | About 6,000 tokens. A longer tool result is clipped with a marker, the full bytes staying in the archive; a longer message of words alone (the summary an earlier compaction wrote, a long paste) is read whole, in pieces. |

### rules.translate

Cross-format translation: an OpenAI-format request can reach an Anthropic upstream and vice versa. Filament converts the request, the reply and the stream; lossy steps are listed in the request record.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.translate.mode` | enum (`auto`, `never`) | `auto` | Whether to translate when the client's format differs from the upstream's. | `auto`: translate whenever the route's format or the upstream type requires it (an `anthropic` upstream reached from `/v1/chat/completions`, an `openai-compatible` one from `/v1/messages`). `never`: refuse such requests with a clear error. |
| `rules.translate.reasoning` | boolean | `true` | Carry the model's reasoning across formats. | Anthropic thinking text becomes OpenAI `reasoning_content` deltas; OpenAI `reasoning_content` becomes Anthropic `thinking` blocks (unsigned, so they are stripped again before any Anthropic model sees them). Off drops reasoning from translated replies. |
| `rules.translate.openaiMaxTokensField` | enum (`max_tokens`, `max_completion_tokens`) | `max_tokens` | Field used for the length limit when translating to OpenAI format. | `max_tokens` is understood by every OpenAI-compatible server; official OpenAI reasoning models prefer `max_completion_tokens`. |

### rules.speed

Fast mode: the same model served faster for a higher price. Anthropic's is `speed: "fast"` (up to 2.5x output speed for roughly double the price; research preview, Claude Opus 5.5, Opus 5 and Opus 4.8 only). Other providers ask for theirs with fields of their own — xAI's and OpenAI's priority processing is `service_tier: "priority"` — declared per model on the Upstreams page (`tune`: fast mode, its multiplier and its request fields). The harness offers it as the model.fast setting wherever it exists; Filament prices a fast request at the model's fastMultiplier. The other way is a flex tier (cheaper, slower; OpenAI's `service_tier: "flex"`), declared the same way on an OpenAI-format provider and offered as the model.flex setting — asked for with a `-flex` suffix, never together with fast mode (fast wins).

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.speed.mode` | enum (`client`, `always`, `never`) | `client` | When to request fast mode. | `client`: only when the agent asks (a `-fast` model suffix such as `claude-opus-5-fast`, or `speed: "fast"` in the request). `always`: every request to a supported model runs fast. `never`: fast requests are downgraded to standard speed. |
| `rules.speed.suffix` | boolean | `true` | Recognize a `-fast` model-name suffix as a fast-mode request. | Combines with effort suffixes in any order: `claude-opus-5-xhigh-fast` and `claude-opus-5-fast-xhigh` both work. The suffix is removed before forwarding. Cursor's own `-fast` model ids are unaffected because ACP routes use the full name. The same switch governs `-flex` (a flex-tier request), which is read only where the model declares a flex tier — elsewhere it stays part of the name. |
| `rules.speed.models` | regex | `claude-opus-(5([-.]5)?\|4[-.]?8)$` | Models that accept Anthropic's fast mode (on an Anthropic-format upstream). | Fast requests to any other model are downgraded to standard and noted in the changes list, instead of failing with HTTP 400. Not available through Bedrock, Vertex or Foundry. A model's own row on the Upstreams page wins over this pattern for that provider, either way — that is also where an OpenAI-format provider's fast mode is declared. |
| `rules.speed.beta` | string | `fast-mode-2026-02-01` | Beta flag added to the `anthropic-beta` header when fast mode is sent. | Anthropic requires it alongside the top-level `speed` field. Update if Anthropic renames the beta. |

Other request parameters.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.params.strip` | array | `[]` | Top-level request fields to always remove before forwarding. | Use for fields an upstream rejects. Applied to every request on this layer. |
| `rules.params.stripRules` | list | `[{"match":"claude-(fable\|mythos\|opus-5\|opus-4[-.]?[78]\|sonnet-5)","strip":["temperature","top_p","top_k"]}]` | Per-model-family fields to remove. | Each entry is `{match: <regex>, strip: [fields]}`. | `rules.params.forceStream` | enum (`client`, `on`, `off`) | `client` | Streaming mode sent upstream. | `client` keeps the agent's choice. `on` always streams (avoids HTTP timeouts on long thinking). `off` never streams. | `rules.params.openaiIncludeUsage` | boolean | `true` | For OpenAI-format streams, ask the upstream to include a final usage chunk (`stream_options.include_usage`). | Without it most OpenAI-compatible servers do not report token usage on streams, so the shim's usage view stays empty. |

### rules.cache

Prompt caching (Anthropic `cache_control` markers).

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.cache.ensureBreakpoints` | enum (`off`, `system`, `system-and-last-user`) | `system-and-last-user` | Add cache markers when the agent sent none. | `system` marks the last system block. `system-and-last-user` also marks the last user message, which makes long tool-loop conversations reuse the cached prefix turn after turn, and the user message before the newest reply, where the request before put its mark, so a round of many calls at once still reads that cache past the provider's lookback. `off` never adds markers. Agents that manage caching themselves (Claude Code) are left alone when `respectClient` is on. |
| `rules.cache.respectClient` | boolean | `true` | If the agent sent any `cache_control`, do not add or move markers. | Prevents the shim from fighting an agent's own cache strategy. |
| `rules.cache.ttl` | enum (`5m`, `1h`) | `5m` | Cache lifetime requested on markers the shim adds. | `1h` costs more to write but survives longer idle periods. Some accounts need the extended-cache-ttl beta for `1h`. |
| `rules.cache.minSystemChars` | number | `2000` | Only add a system marker when the system prompt is at least this many characters. | Prefixes below the model's minimum cacheable size (1024 to 4096 tokens depending on model) are never cached, so marking them is pointless. |

### rules.headers

Outbound HTTP headers.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `rules.headers.forwardResponse` | enum (`safe`, `minimal`) | `safe` | Which upstream response headers are passed back to the agent. | `safe` forwards everything except connection-level and encoding headers, so rate-limit headers, request ids and provider extras reach the agent. `minimal` forwards only request id and retry-after. |
| `rules.headers.identity` | enum (`none`, `claude-code`, `custom`) | `none` | How the shim presents itself to the upstream. | `claude-code` sends the Claude Code user agent and `x-app: cli`. | `rules.headers.userAgent` | string | `` | User agent for `identity: custom`. | Sent as the `user-agent` header. |
| `rules.headers.set` | map | `{}` | Headers to set on every upstream request (name to value). | Overrides anything the shim would otherwise send for that name. Use for provider-specific requirements. |
| `rules.headers.remove` | array | `[]` | Header names to remove from the upstream request. | Applied last, after everything else. |

| `rules.headers.forwardClient` | array | `["anthropic-beta","x-request-id","x-session-id","x-client-request-id"]` | Inbound headers copied to the upstream request (allowlist). | Authentication headers are never forwarded; the upstream's own credentials are used. |

## Server

Listener and access control.

| `server.host` | string | `127.0.0.1` | Interface to listen on. | `127.0.0.1` keeps the shim private to this machine. `0.0.0.0` exposes it to the network; then set inbound keys. |
| `server.port` | number | `20300` | Port for both the API endpoints and the settings UI. | Agents use `http://<host>:<port>/v1`. |
| `server.inboundKeys` | array | `[]` | API keys agents must present. | Checked as `Authorization: Bearer <key>` or `x-api-key`. Empty list with `requireAuth` off means open access on the listener. |
| `server.requireAuth` | boolean | `true` | Require an inbound key on the model endpoints. | The settings UI and admin API answer this computer, the devices paired in Settings › Remote access and `adminToken` alone, whatever this says. |
| `server.adminToken` | secret | `` | Token that lets a script on another machine call the admin API, sent as `x-filament-admin` or a Bearer token. | Leave empty for none: this computer and the full devices paired in Settings › Remote access administer Filament still — a view-only one reads. A browser on another machine pairs instead. |
| `server.allowedHosts` | array | `[]` | Extra host names the console, the admin API, the model endpoints and MCP may be reached under. | They answer only to `localhost`, IP addresses and the configured `host` (a defence against DNS rebinding from web pages). Add a name here when you reach Filament through a reverse proxy or a hosts-file alias. |
| `server.maxBodyBytes` | number | `67108864` | Largest accepted request body. | Long agent conversations with many tools can reach several megabytes. A call of Filament's own loop past it goes with its older pictures, PDFs and files left out until it is within. The message box refuses a message whose attachments together pass it. |
| `server.logLevel` | enum (`error`, `warn`, `info`, `debug`) | `info` | Log verbosity in Filament's terminal window. | `debug` prints every rewrite decision. |
| `server.encryptSecrets` | boolean | `true` | Store API keys, tokens and inbound keys encrypted in config.json. | AES-256-GCM with a random key in `secret.key` next to the config. Copy both files to move an installation; config.json alone reveals no secrets. Off writes them in plain text (only for debugging). |
| `server.advertiseEffortSuffixes` | array (`low`, `medium`, `high`, `xhigh`, `max`) | `[]` | Effort suffixes to add as extra entries on Filament's `/v1/models` for Claude models. | With `["xhigh","max"]`, an agent's model picker also shows `claude-opus-5-xhigh` and `claude-opus-5-max`, which pick effort without any agent setting. Empty keeps the list short. |

### server.lan

Reach this machine on my network (Settings › Remote access): an https listener of its own for the devices paired with this machine.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `server.lan.enabled` | boolean | `false` | Listen on this machine's network addresses, over https. | On: Filament listens on every address of this machine at `port`, over https with a certificate of its own — self-signed, made the first time and kept in the data folder's `lan-tls` folder — beside the loopback listener, which stays as it is. Its pages, API, stream and sockets answer the devices paired in Settings › Remote access and the pairing page anyone; the model endpoints, MCP, an app's hooks and artifacts answer on this machine alone. A browser warns of the certificate once: its fingerprint must be the one Settings › Remote access shows. Takes effect at once. |
| `server.lan.port` | number | `20343` | Port for the network listener. | Its own port, never the loopback listener's. Takes effect at once; a Windows Firewall rule Filament made names the port it was made for. |

### server.tailscale

Share on my tailnet (Settings › Remote access): `tailscale serve` gives this Filament an https address on your tailnet.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `server.tailscale.serve` | boolean | `false` | Serve this Filament on your tailnet with tailscale serve. | On: Filament asks Tailscale's command line to serve https://<this machine>.<your tailnet>.ts.net — its certificate one an authority signs — to a door of its own on loopback at `port`, and the artifacts at port 8443 of that name. ## Observability

What is recorded per request.

| `observability.keepLastRequests` | number | `500` | Requests kept in memory for the UI. | Older entries fall off, a finished agent tick or sub-agent call first, but never one of a turn still running, whose cache card and accounting read them until it ends; everything is still appended to the log file. A restart reloads this many from the end of the log — the current file first, then its rotated generations, newest first — by reading backwards in chunks, so raising the number costs RAM for the extra rows, not a 66 MB slurp of the whole file. |
| `observability.logFile` | string | `requests.jsonl` | JSONL file (inside the data directory) with one record per request. | Empty disables file logging. |
| `observability.storeBodies` | enum (`none`, `summary`, `shaped`, `full`) | `summary` | How much of each request to keep (memory and the JSONL log). | `summary` keeps what matters without the conversation: model in/out, thinking in/out, effort in/out, stream flag, message and tool counts, sizes, the headers sent, and every change applied. `none` keeps metadata and usage only. `shaped` additionally stores the full request body as sent upstream (whole chat, secrets redacted). `full` also stores the inbound body. Long agent sessions are megabytes per request, so use `shaped`/`full` only while debugging; bodies above `maxStoredBodyBytes` are truncated. |
| `observability.maxStoredBodyBytes` | number | `2097152` | Per-request cap for stored bodies. | Keeps the log file and memory bounded. |
| `observability.storeInternalBodies` | boolean | `false` | Also keep the bodies of Filament's OWN model calls: memory learning, recall rewriting, summary slices, compaction summaries, the memory engine, the console's assistant and health pings. | Off by default. | `observability.tokenCalibration` | boolean | `true` | Learn the token estimator's error per upstream+model from the usage every real reply already states, and apply it as a multiplier. | Nothing is ever sent anywhere to learn this — it reads receipts Filament keeps. ### observability.runEvents

The run log: every event an agent turn or a sub-agent publishes, kept per run so the harness can watch a run live and replay it after a restart (`/api/runs`).

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `observability.runEvents.persist` | boolean | `true` | Append each run's events to `runs/<id>.jsonl` in the data directory. | Off keeps runs in memory only: a restart forgets them and a replay of an older run is not possible. | `observability.runEvents.retentionDays` | number | `7` | Days a run's file is kept before the sweep removes it. | Checked at start and every six hours; a run that is still running is never removed. 0 keeps files forever. |
| `observability.runEvents.maxPerRun` | number | `20000` | Events kept in memory per run. | Past this the oldest fall out of the ring; a viewer asking for them is told the first number it can still get (and the file, when persistence is on, fills the rest). | `observability.runEvents.ringMB` | number | `4` | Megabytes of a running run's newest events kept in memory, as their JSON measures them. | Older events are read from the run's file, a page at a time, when something asks for them (a viewer opening the run, a page scrolled back), so what a long turn streamed stays on disk instead of in the server's memory. With `persist` off, or once a run's file could not be written, its events stay in memory, up to `maxPerRun`. |
| `observability.runEvents.keepRuns` | number | `200` | Ended runs kept in memory. | Older ended runs leave memory (their files stay until the sweep); a running run is never evicted. |
| `observability.runEvents.toolPreviewChars` | number | `2000` | Characters of a tool's result carried on the agent loop's `tool-end` event. | The harness shows a command's output, a read's first lines or a search's hits from this preview (the model saw the whole result). The run log is conversation-bearing already (`round-text`), so this changes nothing about where content lives: the run file, never the operation log. |
| `observability.runEvents.imagesMaxMB` | number | `500` | Megabytes of the pictures tools handed agents, kept so the harness shows them on the calls' cards. | A picture an agent read, or one a tool returned (an MCP server's screenshot), is kept as the model saw it beside the run files (`runs/images/`), once per content, for as long as run files are kept (`retentionDays`). The pictures are conversation, as the run files are. |
| `observability.broadcast` | boolean | `true` | Push live request events to the UI. | Uses server-sent events; negligible cost. |

| `upstreams[].models` | array | `[]` | Model names you typed for this upstream, offered in every picker beside the ones it lists itself. | Add one with the Add button under the upstream's model list (or here, comma separated). | `upstreams[].pricing` | map | `{}` | This upstream's model cards: each model's prices (USD per million tokens), what it can do here — reasoning levels, fast mode, extended thinking, context windows, output ceiling, tools. Every field is optional, and every one you leave out comes from the next source that knows: the provider's own model listing (captured by Refresh — Anthropic's states each model's reasoning levels, thinking, window and output ceiling; OpenRouter-style listings state windows), then the Rules page, then Filament's built-in knowledge. When the provider itself states what it charged (xAI does), that figure is used instead of any price here. `contextTokens` is the model's standard context window at THIS provider: every request record judges its fit by it (nothing is ever reshaped to fit), /autofit fits a session to it, and a summary's slices are sized with it. `windows` lists the other windows a session may choose (the harness's Context window control; `[]` = the standard one only) — windows the same name takes; a provider that sells each window as a name of its own (Kimi's `k3` at 1M beside `k3-256k`) needs none, since the picker folds those names into one model with a Context window choice, and `windowMultipliers` on the family's row says what each of those windows costs against the cheapest, window tokens → multiplier (`{"1000000": 2}`: the 1M window at twice; on a plan, twice the quota), shown beside the window in the picker. `maxOutputTokens` is the model's maximum output: sessions and agent turns without their own max_tokens use it; left out, what the provider's listing states or a refusal of a larger request named (Filament remembers that one for the model here, and its own call goes again within it), else 128,000. `efforts` lists the reasoning levels the model takes (`low`, `medium`, `high`, `xhigh`, `max`; `[]` = it takes no effort field, which is then removed) and `effortDefault` the level the provider uses when none is sent. `fast` says whether the model has a fast mode here, `fastMultiplier` what it costs against the standard price (or how much faster it spends a subscription's quota; Anthropic's is 2), and `fastParams` the request fields that ask for it on an OpenAI-format provider — xAI and OpenAI take `{"service_tier": "priority"}`, and the reply's own tier decides whether the request is billed fast. ## Route fields

A route maps a model name the agent asks for to an upstream and a model there.

| `routes[].match` | string | `` | Model-name pattern the agent sends. | Exact name, or a glob with `*` (for example `claude-*`). An effort suffix is stripped before matching when `effort.stripSuffix` is on. First matching route wins, top to bottom. |
| `routes[].upstream` | string | `` | Upstream id. | Must reference an existing upstream. |
| `routes[].upstreamModel` | string | `{model}` | Model name to send upstream. | `{model}` is replaced with the matched name without suffix, e.g. `anthropic/{model}` for OmniRoute's prefixed ids. `{1}`, `{2}`… are the parts matched by each `*` in `match`, so `direct/claude-*` can be sent as `claude-{1}`. This lets several routes address the same upstream model under different names. |
| `routes[].format` | enum (`auto`, `anthropic`, `openai`) | `auto` | Wire format sent to the upstream for this route. | `auto`: the agent's own format when the upstream speaks it, otherwise the one it does speak (translated). `anthropic` or `openai` forces that format; requests in the other format are translated (see `rules.translate`). |
| `routes[].fallbacks` | list | `[]` | The failover order: other upstreams that serve this route when the one before fails. | Each entry is `{upstream, upstreamModel}`, tried in order (strategy in_order) when the previous one fails before answering: rate limit (429), server errors (5xx, 529), unreachable, an unknown model on that provider (404, or a 400 naming the model) or a refused key (401, 403). A plain-name route with entries here is a virtual model (`free-model`). Other strategies spread requests across the same list. |
| `routes[].strategy` | enum (`in_order`, `round_robin`, `random`, `least_latency`, `least_cost`, `quota_aware`) | `in_order` | How to choose among the primary upstream and its fallbacks for each request. | `in_order`: primary first, fallbacks only on failure. `round_robin`: rotate. `random`. `least_latency`: the upstream with the lowest recent first-byte time. `least_cost`: cheapest by the model's price card at each upstream. `quota_aware`: avoid upstreams whose rate-limit headers or quota say they are nearly exhausted. Upstreams that are cooling down after failures are always tried last. |
| `routes[].discoverPrefixes` | array | `[]` | For router upstreams (9router, OmniRoute) that list models as `provider/model`: provider prefixes whose models this route advertises by bare name. | Routers usually accept the bare model name and pick their default provider for it. | `routes[].enabled` | boolean | `true` | Whether this route is active. | Disabled routes are skipped. |

## Agent loop

The agent loop: one model with Filament's file and shell tools, run server-side. The harness drives every LLM route through it (a plain route picked there runs the loop), and Filament's own calls name it `agent/<model>`; an outside client's request goes to the model it names.

| `agentLoop.permissions` | string (`read-only`, `edit`, `ask`, `auto`) | `edit` | What the agent may do without asking. | A command that only reads runs in every mode — on the bash hand in a real bash (Git Bash, bash or sh), `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `rg`, `find`, `pwd` or `echo` with options that only read, on paths inside the working folder, after a `cd` into one of its folders too; a command Filament cannot tell only reads is asked about or refused with the reason (a write, a path outside, a program it does not know). `read-only`: reads, searches and those commands run; a write or any other command is refused in words. `edit`: writes and edits inside the working folder run free too; any other shell command asks first. `ask`: every write, edit and other command asks. `auto`: nothing asks (bash still runs with a filtered environment, no API keys). Asking pauses the turn on a question: the harness's card answers it — Allow runs the call, and Deny or any other message you type refuses it, delivered to the model in your words; /allow alone, typed or from a client that draws no card, allows it. Nothing reads your words for a yes. The mode is enforced at the tool gate and never changes the loop's system prompt or tool list, so switching it mid-task — restrictive before a risky step, loose after — costs no cache. `edit` is the mode people actually work in; ask-on-every-write is the mode nobody keeps on. |
| `agentLoop.systemPrompt` | string | `` | Your own system prompt for agent/<model> turns. Empty = the built-in one. | When set, your text replaces the loop's built-in role and report sentences; the folder, tools and steering lines are still appended after it, so the loop keeps working. The assembled prompt — built-in or with your overlay — is on the console's Settings → Prompts page. |
| `agentLoop.roots` | array | `[]` | Folders the agent may work in; the working folder must lie under one of them. | Absolute folder paths (`C:\work`, `/home/me/code`; a filesystem root is allowed, a bare drive letter is not a folder). The working folder comes from the client's `x-filament-cwd` header (the harness sends it), else from the project memory names for the chat; it is judged as the filesystem resolves it, so a link under a listed root that points elsewhere is judged by where it points. A folder outside this list, or one that does not exist, is refused in words; a folder on a network share (`\\host\share\…`) whose share no listed root names is outside, judged without asking the share. Empty means any folder the process can reach, a network share's too — allowed only while the listener is loopback-only (`server.host` localhost, a 127.x.x.x address, ::1 or ::ffff:127.x.x.x); on an exposed listener an empty list refuses every turn until you name the folders, a share's before it is asked. |
| `agentLoop.envPass` | array | `[]` | Environment variables the commands Filament runs are also given, by name. | A command Filament runs for an agent — the loop's `bash` and `powershell`, a background command, a terminal a coding agent asks Filament for, Filament's own Bash over MCP — and a program it starts for you (a hook, an MCP server on this computer, a language server, a dashboard's command, a script watcher) gets a filtered copy of the environment Filament was started with: what a build, a test or git needs and that is no secret. That is the PATH, your home and the system's folders, locale, proxies, certificate bundles, the ssh agent's socket, git's author and committer and its other `GIT_*`, `npm_config_*`, the toolchain and SDK homes and build settings Filament knows, and which cloud profile, kubeconfig or Docker a tool uses. Never a `GIT_*` or `npm_config_*` name that reads like a secret (`key`, `token`, `secret`, `password`, `credential`, `auth`, `session`, `cookie`, `private`), a value that is an address with a password in it (`http://user:password@proxy`), git's config by environment (`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n`), or anything the list does not know. A name listed here goes through whatever it reads like or holds: `HTTPS_PROXY` whose address carries a password, a licence file's path, an SDK's home Filament does not know. Names only, never a value; on Windows in any case; one of Filament's own (`FILAMENT_*`) is refused. It holds from the next command started: a program already running keeps the environment it started with. A coding agent's own shell is not Filament's: it has the environment its agent was started with (`upstreams[].acp.envRemove` withholds from that). |
| `agentLoop.resultCapChars` | number | `0` | A tool result longer than this many characters reaches the model as its head plus a pointer. | The whole result is archived and `filament_recall` brings it back, so nothing is lost — the cap keeps one huge read or command dump from riding every remaining round of the turn at full size. It bites the moment the result lands, never retroactively, so the prefix stays byte-stable and the provider's cache survives. 0 disables it; a session's `loop.resultCapChars` overrides this for that session. |

### agentLoop.subagents

Sub-agents: a fresh agent loop on one task, launched by the agent (the `agent` tool), from the harness's spawn widget, or by `/subagent` in a chat Filament runs; a team's workers are sub-agents its lead launches. A session's `subagents.*` settings override `ask`, `teams`, `worktree` and `workspace`; `slots` holds across every chat.

| parameter | type | default | what it does | effect |
|---|---|---|---|---|
| `agentLoop.subagents.slots` | list | `[]` | How many agents run on each model at once, across every chat and every team. | Each entry is `{upstream, model, n}`: a source's id (a provider's upstream, or a coding agent's account), the model's name as that source receives it, and how many agents run on it at once, 1 to 64; each model once at each source. A model with no entry has no limit. Every chat's sub-agents and every lead's workers share these: a launch takes a free slot, the next row of its list takes it where one is full, a team's worker waits for one where every slot is busy (its card says for what), and others are refused in words. A number counts agents only: Filament's gate on requests holds to what the provider showed, never to this (a price card's `maxConcurrency` caps nothing either). A provider's 429 lowers a model's number for a while; its rate-limit headers count requests a minute, and lower none. Each model's row on Settings › Providers, or on its coding agent's page, writes it. |
| `agentLoop.subagents.ask` | array | `[]` | The saved agents a session's main agent may ask, by tag. | Empty: nobody. Each tag names a card in the harness's Library, where a card's tick “Your agent may use it” writes this list. ## Long-term memory

Long-term memory for every model and every client. Filament installs and runs Mnemosyne (open source, SQLite, on your machine) as its own child process, keeps a byte-exact archive of your conversations, and on autopilot gives each request what past sessions established: identity, your rules, the project's dossier, decisions, related sessions. Models can also call memory tools themselves. Content never enters records or logs.

| `memory.enabled` | boolean | `true` | Turn memory on. | On (the default): Filament runs the Mnemosyne engine it installed as its own child process, the autopilot adds relevant memory to requests, it learns from your sessions, and models get the filament_memory_* tools unless a client sends `x-filament-memory: off`. Off: the archive still records every conversation, for your sessions and their transcripts, but nothing is recalled, learned or offered as a tool. A config that saved off stays off. |
| `memory.folder` | string | `` | Folder that holds the memory (archive.db, mnemosyne/, memory.json). | Empty = `<data folder>/memory`. Any drive works. Pointing a fresh install at an existing folder adopts it. |
